# 资源管理门面拆分与应用纹理清单化改造规划

> 状态：已实施（阶段 0 提交 6cb7b35e，门面拆分提交 faf6fd7d）
> 关联代码：`src/resource/`、`src/app/GameResourceBootstrapper.cpp`、`src/app/states/AppStateDependencies.h`

## 1. 背景与目标

`ResourceMgr`（src/resource/ResourceMgr.h）当前是一个"上帝门面"：约 40 个消费者通过它访问纹理资源，它还兼任 GPU 设备服务定位器。
本改造有两个目标：

1. **数据导向（DOP）**：让"新增一个方块纹理 / shader 贴图"只需改 JSON，不碰 C++、不重编译。
2. **单一职责（SRP）**：解散 `ResourceMgr` 门面，让内部已经模块化的 5 个子库成为一等依赖，按消费者聚类注入；消除设备转发、静态指针注入等职责错位。

已确认决策：

- 删除死资源 `shader_ldr_lut`（全项目无消费点，GameResourceBootstrapper.cpp:214）。
- 采用**选项 C：彻底拆分门面**。
- 明确不做：通用资产管线、创造模式标签页数量 `kTabCount` 的数据化（属 UI 布局逻辑）。

## 2. 现状调查结论

### 2.1 所有权与传播链

唯一实例 `GameManager::m_resourceMgr`（GameManager.h:69），全程按引用传播：

```
GameManager → AppStateDependencies.resourceMgr (AppStateDependencies.h:30)
  → 各 AppState → GameSessionDependencies (GameSessionConfig.h:58) → Game (Game.cpp:67)
  → GameSession / GameplayRenderRuntime → RenderScene / RenderResourceHub / 各渲染器与 UI 控件
```

注意：`AppStateDependencies` 已独立携带 `RhiDevice&` 与 `RhiCommandListPool&`（AppStateDependencies.h:36-37），
因此经由 `ResourceMgr` 取设备是一条**冗余依赖**。

### 2.2 ResourceMgr 的真实结构

`ResourceMgr` 是**纯转发门面**：全部 30+ 个方法逐行委托给 5 个子库，自身无业务逻辑、无额外状态
（ResourceMgr.cpp:18-26）。子库职责边界天然清晰：

| 子库 | 职责 |
|---|---|
| `Texture2DLibrary` | 命名 2D 纹理 + GUI 纹理存储 |
| `BlockTextureLibrary` | 方块纹理管线：catalog、图集、纹理数组、动画、tint、平均色、各向异性、OMM 像素源 |
| `UiTextureAtlasLibrary` | 方块图标 / 物品纹理 / HUD 图标三套图集 |
| `EnvironmentTextureLibrary` | lightmap（昼夜）+ colormap（草/树叶） |
| `CubemapLibrary` | 立方体贴图（当前仅菜单天空盒） |

### 2.3 消费者聚类（拆分依据）

几乎没有消费者横跨两个职责族：

| 消费者族 | 文件数 | 实际使用的方法族 |
|---|---|---|
| Shader 渲染通道（SsgiPass、SsaoPass、DeferredLightingPass 等 12 个） | 12 | 仅 `getTexture2DHandle`（shader 贴图） |
| 地形/延迟管线（TerrainRhiPipelineSet、DeferredPipeline） | 2 | 方块数组 + lightmap + colormap + atlas |
| UI 物品栏家族（Hotbar、Inventory、Creative、ItemGrid、DataDrivenContainer） | 7 | 物品图集 + 图标 + GUI 纹理 |
| 实体渲染器（Humanoid、Drop、FallingBlock、FirstPersonHeldItem、BlockEntity） | 5 | GUI 纹理 + 物品像素 + 数组 + colormap |
| 设备消费者（含 UISlider 等纯 UI 控件） | 24 | 仅 `rhiDevice()`，与纹理无关 |
| 天空盒（SkyboxRenderer） | 1 | 仅 `getCubemap` |

### 2.4 已识别的 SRP 问题

1. **GPU 设备转发错位**：24 个文件经 `ResourceMgr` 拿 `RhiDevice`，纯纹理管理器充当服务定位器。
2. **`BlockModelRegistry::s_resourceMgr` 静态指针**（BlockModelRegistry.h:27）：隐藏全局状态，绕过 DI 链，
   经 `BlockRegistry::init(&resourceMgr)` 注入（GameResourceBootstrapper.cpp:263）。
3. **结构性 `init()` 混入内容加载**：`menu_skybox` 藏在 `ResourceMgr::init()` 内（ResourceMgr.cpp:44）。
4. **空接口 `IBlockTextureColorProvider`**：`blockTextureAverageColor` 全库无调用者。
5. **启动期硬编码加载**：`bootstrapGameResources` 中约 60 行逐个罗列的纹理加载调用与 `Paths.h` 的
   20+ 个单文件路径宏耦合。

## 3. 目标架构

### 3.1 资源聚合体取代门面

新增 `GameResources` 聚合结构（`src/resource/GameResources.h`），以值持有 5 个子库，
仅负责生命周期（init / shutdown），不含任何转发方法：

```cpp
struct GameResources {
    Texture2DLibrary texture2D;
    BlockTextureLibrary blockTextures;
    UiTextureAtlasLibrary uiTextures;
    EnvironmentTextureLibrary environmentTextures;
    CubemapLibrary cubemaps;

    void init(RhiDevice& rhiDevice, RhiCommandListPool& commandListPool);
    void shutdown();
};
```

- `GameManager` 持有 `GameResources` 替代 `ResourceMgr`。
- 依赖链上的结构体（`AppStateDependencies`、`GameSessionDependencies`、`UIRenderContext`、
  `ecs::GameplayServices` 等）改携带 `GameResources&`；`AppStateDependencies` 已有的
  `rhiDevice` / `commandListPool` 字段保持不变，成为设备的唯一传播途径。
- 消费者通过聚合体访问所需子库：`resources.blockTextures.textureArray()`。
  消费者声明依赖时注释说明其依赖的子库（不新增中间抽象，避免过度设计）。

### 3.2 应用级纹理清单

新增 `assets/config/app_textures.json`，收录所有应用级纹理：

```json
{
  "textures": [
    { "name": "shader_noise2d", "path": "textures/shaderpacks/noise2D.png",
      "srgb": false, "flip": false, "queueSharing": "graphicsComputeConcurrent" },
    { "name": "widgets", "path": "textures/gui/widgets.png", "kind": "gui", "flip": true }
  ],
  "cubemaps": [
    { "name": "menu_skybox", "faces": {
      "right": "textures/skybox/right.png", "left": "textures/skybox/left.png",
      "top": "textures/skybox/top.png", "bottom": "textures/skybox/bottom.png",
      "front": "textures/skybox/front.png", "back": "textures/skybox/back.png" } }
  ]
}
```

- `kind` 缺省为普通 2D 纹理；`gui` 走 `Texture2DLibrary::loadGui`。
- `queueSharing` 缺省 `exclusive`，可选 `graphicsComputeConcurrent`。
- `path` 相对 `ASSETS_DIR`；解析失败或任一条目加载失败即中止启动（无回退）。
- 新增解析器 `src/resource/AppTextureManifest.{h,cpp}`：
  `static bool load(GameResources&, const std::string& manifestPath)`。
  参照 `EntityTexturePreloader` 的"读 JSON → 拼路径 → 调库"范式。

### 3.3 方法迁移映射表（消费者改写依据）

| 原 ResourceMgr 方法 | 新访问路径 |
|---|---|
| `getTexture2DHandle` / `loadTexture2D` | `texture2D.getHandle` / `texture2D.load` |
| `getGuiTextureHandle` / `loadGuiTexture` | `texture2D.getGuiHandle` / `texture2D.loadGui` |
| `getTextureArray` / `getBlockNormalTextureArray` / `getBlockSpecularTextureArray` | `blockTextures.textureArray` 等 |
| `getAtlas` / `getTextureArrayLayer` / `getTextureAnimation` / `getTextureTint` / `arrayLayerToAtlasTile` / `getBlockTextureTileSize` / `blockTextureAverageColor` | `blockTextures.*` |
| `hasBlockNormalMaps` / `hasBlockSpecularMaps` / `getTerrainOpacityMicromapSource` / `setAtlasAnisotropy` / `getAtlasAnisotropy` | `blockTextures.*` |
| `getLightmapDay` / `getLightmapNight` / `getGrassColormap` / `getFoliageColormap` | `environmentTextures.*` |
| `getItemTextureAtlas` / `getItemTextureIndex` / `getItemTexturePixels` / `getItemIconAtlas` / `getHudIconAtlas` / `getHudIconIndex` | `uiTextures.*` |
| `getCubemap` | `cubemaps.get` |
| `rhiDevice()` / `commandListPool()` | **直接注入 `RhiDevice&` / `RhiCommandListPool&`**（不经过资源系统） |
| `IBlockTextureColorProvider` | **删除**（接口与覆写一并移除） |

### 3.4 静态指针修复

`BlockModelRegistry::s_resourceMgr` 改为显式注入 `const BlockTextureLibrary&`（它只消费方块纹理查询）。
`BlockRegistry::init` 签名同步调整，`bootstrapGameResources` 改传 `resources.blockTextures`。

## 4. 分阶段实施步骤

每阶段独立编译通过、可独立提交。

### 阶段 0：应用纹理清单与死资源清理

**改动文件：**
- 新增 `assets/config/app_textures.json`（清单条目见 §4.1）
- 新增 `src/resource/AppTextureManifest.{h,cpp}`
- 修改 `src/app/GameResourceBootstrapper.cpp`：删除被清单取代的硬编码调用
  （含 `for (i <= 7)` 标签页循环与 `shader_ldr_lut`）
- 修改 `src/Paths.h`：删除被清单取代的 ~20 个单文件路径宏，新增 `APP_TEXTURES_MANIFEST_PATH`
- 修改 `src/resource/ResourceMgr.cpp`：`menu_skybox` 移出 `init()`，由清单加载

**验收：** 编译通过；主菜单天空盒、快捷栏、创造模式标签页、雨雪粒子正常。

#### 4.1 清单初始条目

- 普通 2D：`shader_noise2d`（graphicsComputeConcurrent）、`shader_bayer256`、`shader_ripple_normal`、`rain`、`snow`
  （**不含** `shader_ldr_lut`，删除）
- GUI：`widgets`、`inventory`、`creative_tab_inventory`、`creative_tab_items`、
  `creative_tab_top_selected_1..7`、`creative_tab_top_unselected_1..7`、
  `creative_tab_bottom_selected_1..7`、`creative_tab_bottom_unselected_1..7`、
  `creative_scroller`、`creative_scroller_disabled`、`steve`、`chest`
- Cubemap：`menu_skybox`（6 面）

注：容器背景纹理遍历 `ContainerUiRegistry` 动态生成，保留在引导代码中，不入清单。

### 阶段 1：引入 GameResources，门面暂时保留

**改动文件：**
- 新增 `src/resource/GameResources.{h,cpp}`（聚合 5 个子库 + 生命周期）
- 修改 `GameManager`：`m_resourceMgr` → `m_resources`，`bootstrapGameResources` 签名改为接收 `GameResources&`
- 修改 `AppStateDependencies`、`GameSessionDependencies`、`Game`、`GameSession`、`GameplayRenderRuntime`、
  `UIRenderContext`、`ecs::GameplayServices`：`ResourceMgr&` → `GameResources&`
- 修改 `GameResourceBootstrapper.cpp`、`EntityTexturePreloader.{h,cpp}`、`UIImage`：改经子库写入
- 修改 `BlockModelRegistry` / `BlockRegistry::init`：静态指针 → 显式注入 `const BlockTextureLibrary&`

本阶段结束时 `ResourceMgr` 仅剩尚未迁移的消费者引用。编译必须通过。

### 阶段 2：按聚类迁移查询侧消费者

按 §2.3 的聚类逐批迁移，每批一个提交：

1. **Shader 通道批**（12 个文件）：`getTexture2DHandle` → `resources.texture2D.getHandle`
2. **地形/延迟管线批**（2 个文件）：方块数组 / lightmap / colormap / atlas / anisotropy
3. **UI 物品栏批**（7 个文件 + HudControl）：物品图集、图标、GUI 纹理
4. **实体渲染器批**（5 个文件）：GUI 纹理、物品像素、数组、colormap
5. **天空盒 + 其余零散**（SkyboxRenderer、RainRenderer、ParticleSystem、Dashboard 等）

### 阶段 3：拆除设备转发与门面残骸

1. **设备转发迁移**：24 个 `rhiDevice()` / 5 个 `commandListPool()` 消费者改为直接注入：
   - 渲染器/管线：构造或 `init` 参数已普遍携带 `RhiDevice&`，补齐缺失者
   - UI 侧：`UIRenderContext` 增加 `RhiDevice&` 字段，由 `UIRenderer` 填充；
     各控件经上下文取设备，不再经资源系统
2. 确认全库无 `ResourceMgr` 剩余引用后，删除 `ResourceMgr.{h,cpp}` 与
   `BlockTextureColorProvider.h`
3. `Paths.h` 二次裁剪：删除阶段 2 中确认无引用的残余宏

### 阶段 4：收尾

- 全量构建 + 冒烟验证（§5）
- 按项目规范提交（每阶段一次提交）

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 改动面大（40+ 类），回归风险 | 分 5 个阶段提交，每阶段编译 + 对应冒烟项；消费者迁移是纯机械的方法名映射（§3.3） |
| `rhiDevice()` 消费者的注入路径不一 | 渲染器多数已有设备参数；UI 侧统一走 `UIRenderContext` 新增字段，逐控件机械改写 |
| 清单字符串名拼写错误延迟到运行时 | 启动即校验、失败即退出（项目既有风格）；加载失败打印条目名与路径 |
| `BlockModelRegistry` 注入时机 | 其初始化在 `buildBlockIconAtlas` 之前的引导序列中，注入 `blockTextures` 时数据已就绪，顺序不变 |
| `UIImage` 运行时写入 | `Texture2DLibrary::loadGui` 本身支持运行时追加，行为不变 |
