# 异形方块系统设计报告

> 版本：v1.0
> 日期：2026-06-22
> 范围：为 Mecraft 引入楼梯、台阶、围墙、铁砧、锅等异形方块，基于自研 JSON 模型格式（兼容 Minecraft 原版 `from`/`to`/`faces` 字段）

---

## 一、研究背景与目标

### 1.1 研究目的

当前 Mecraft 仅支持三种渲染形状：`Cube`（立方体，走贪婪合并）、`Cross`（交叉面片，花草）、`Custom`（火把/水等少量自定义）。对于楼梯、台阶、竖板砖、锅、铁砧等异形方块尚无系统化支持，每加一种就要手写一个 `MeshBuilderFn`，难以扩展。

### 1.2 研究对象

- Mecraft 现有方块定义、方块模型、纹理映射、区块网格生成（贪婪合并）相关代码
- Minecraft 原版 JSON 模型格式（`D:\project\minecraft-vanilla-assets\models`）

### 1.3 目标

1. 设计一套 Mecraft 自研的 JSON 模型格式，至少支持 `from`、`to`、`faces` 字段，足以表达任意由长方体组合而成的异形方块
2. 提供从 Minecraft 原版模型 JSON 转换为 Mecraft 模型 JSON 的 Python 脚本（含 `parent` 继承解析、纹理变量解析），无需手工重写 `from`/`to`/`faces`
3. 将异形模型集成进现有区块网格生成管线（复用 `MeshBuilderRegistry` 扩展点）
4. 充分考虑异形方块的贪婪合并与优化策略

方块 ID 为 `RuntimeId = uint16_t`（最多 65535 种），内置方块在 `BuiltinIds.h` 中宏定义。`blocks.json` 描述每个方块的属性，加载时纹理名被解析为 `AnimatedTextureRef{firstLayer, frameCount}`，指向纹理数组层。

### 2.2 纹理系统

Mecraft 使用 **纹理数组（Texture Array）** 而非纹理图集。每个纹理占一层（动画纹理占多层）。`AnimatedTextureRef.firstLayer` 即纹理数组层索引，写入顶点的 `layer` 字段。

`BlockStateRegistry::getStateTextures(blockId)` 返回 per-state 纹理，可在基础 `BlockDef` 六面纹理之上按状态覆盖。纹理名（如 `"oak_planks"`）→ 层索引的映射在 `BlockRegistry::init()` 加载 `blocks.json` 时建立。

**网格生成中的 UV 范围是 `0.0 ~ 1.0`**（非 0~16），由 `buildFaceUv()` 生成。

### 2.5 贪婪合并算法

经典三层循环：**6 个面方向 × 每个方向的层切片 × 层内 2D 平面贪心扩张**。

- 每个面通过模板参数传入法线方向（`NormalX/Y/Z`），编译期消除分支
- `FaceCell` 数组 + `consumed` 数组标记已合并格子
- 合并条件：相邻方块同纹理层、同不透明度、同 renderShape
- 仅适用于完整 `Cube` 方块

### 2.6 MeshBuilderRegistry 扩展点

```cpp:48:59:src/renderer/mesh/MeshBuilderRegistry.cpp
void MeshBuilderRegistry::initBuiltinBuilders() {
    registerBuilder("cube",   CUBE_TAG,  MeshShapeClass::Cube,   nullptr);
    registerBuilder("cross",  CROSS_TAG, MeshShapeClass::Cross,  &ChunkMeshBuilders::buildCross);
    registerBuilder("torch",  TORCH_TAG, MeshShapeClass::Custom, &ChunkMeshBuilders::buildTorch);
    registerBuilder("water",  WATER_TAG, MeshShapeClass::Custom, &ChunkMeshBuilders::buildWater);
}
```

**这是异形方块系统的天然集成点**：注册一个新的 `"model"` builder，所有异形方块共享同一个 builder，通过 `BlockDef` 关联的模型数据驱动几何生成。

### 2.7 现有异形方块支持

**当前不支持任何 from/to 类异形方块**（无楼梯、台阶、围墙、铁砧、锅）。仅 `Cross`（花草）和少量 `Custom`（火把、水）存在，且都是手写几何，没有数据驱动。

## 三、Minecraft 原版 JSON 模型格式分析

### 3.1 顶层结构

```json
{
  "parent": "block/cube_all",      // 可选，继承父模型
  "ambientocclusion": true,        // 可选，默认 true
  "textures": {                    // 纹理变量定义
    "particle": "#all",
    "all": "block/oak_planks"
  },
  "elements": [                    // 几何元素列表
    {
      "from": [0, 0, 0],
      "to": [16, 16, 16],
      "faces": { ... }
    }
  ],
  "display": { ... },              // 不同视角变换（GUI/地面/手持），Mecraft 不需要
  "gui_light": "side"
}
```

### 3.2 `from` / `to` 字段

定义一个长方体的两个对角顶点，**坐标范围 0~16**（一个完整方块占据 `[0,0,0]~[16,16,16]`）。

示例（栅栏柱，`fence_post.json`）：

```json
"from": [6, 0, 6],
"to": [10, 16, 10]
```

表示一个 4×16×4 的柱子。坐标系：X=东西，Y=上下，Z=南北，原点在方块西北下角。

### 3.3 `faces` 字段

每个元素有 6 个面，键为方位名：`down`(-Y)、`up`(+Y)、`north`(-Z)、`south`(+Z)、`west`(-X)、`east`(+X)。

每个面的子字段：

| 子字段 | 类型 | 说明 |
|--------|------|------|
| `texture` | string | 纹理变量引用，如 `"#side"`（**必须**） |
| `uv` | [x1,y1,x2,y2] | UV 坐标，**范围 0~16** |
| `cullface` | string | 面剔除方向，如 `"north"`；缺省则该面永不剔除 |
| `rotation` | int | 纹理旋转 0/90/180/270 |
| `tintindex` | int | 染色索引，用于动态着色（树叶、草地、水） |

示例（`slab.json` 下半砖）：

```json
"north": { "uv": [0, 8, 16, 16], "texture": "#side", "cullface": "north" }
```

### 3.4 `textures` 字段（纹理变量）

键为变量名，值有两种形式：

- **直接路径**：`"block/oak_planks"` 或 `"minecraft:block/oak_planks"`
- **引用**：`"#all"`，引用同模型中定义的其他变量

`particle` 变量特殊，用于粒子效果。

### 3.5 `parent` 继承

子模型继承父模型的所有字段（`textures`、`elements`、`ambientocclusion`），自身字段覆盖父字段。继承可多层递归。Minecraft 用此机制复用模板（如所有楼梯继承 `block/stairs`，其再继承 `block/cube`）。

### 3.6 典型异形方块模型示例

**楼梯**（`stairs.json`，由 3 个长方体组成）：

```json
{
  "parent": "block/block",
  "textures": {
    "bottom": "#bottom",
    "top": "#top",
    "side": "#side"
  },
  "elements": [
    { "from": [0, 0, 0], "to": [16, 8, 16],
      "faces": {
        "down":  {"uv": [0,0,16,16], "texture": "#bottom", "cullface": "down"},
        "up":    {"uv": [0,0,16,16], "texture": "#top"},
        "north": {"uv": [0,8,16,16], "texture": "#side", "cullface": "north"},
        "south": {"uv": [0,8,16,16], "texture": "#side", "cullface": "south"},
        "west":  {"uv": [0,8,16,16], "texture": "#side", "cullface": "west"},
        "east":  {"uv": [0,8,16,16], "texture": "#side", "cullface": "east"}
      }
    },
    { "from": [0, 8, 0], "to": [16, 16, 8],
      "faces": {
        "up":    {"uv": [0,0,16,8], "texture": "#top"},
        "north": {"uv": [0,0,16,8], "texture": "#side", "cullface": "north"},
        "west":  {"uv": [0,0,8,8],  "texture": "#side", "cullface": "west"},
        "east":  {"uv": [8,0,16,8], "texture": "#side", "cullface": "east"}
      }
    },
    { "from": [0, 8, 8], "to": [8, 16, 16],
```

### 4.2 Mecraft 模型 JSON 格式（`mecraft_model_v1`）

设计原则：**与 Minecraft 的 `from`/`to`/`faces`/`uv`/`cullface`/`rotation`/`tintindex` 语义完全一致**，便于用 Python 脚本直接转换；去除 Mecraft 不需要的字段（`display`、`gui_light`）；纹理变量值改为 Mecraft 纹理名（去除 `block/` 前缀和命名空间）。

#### 4.2.1 完整格式定义

```json
{
  "format": "mecraft_model_v1",
  "ambientocclusion": true,
  "textures": {
    "particle": "oak_planks",
    "top": "oak_planks_top",
    "side": "oak_planks_side",
    "bottom": "oak_planks_bottom"
  },
  "elements": [
    {
      "from": [0, 0, 0],
      "to": [16, 16, 16],
      "faces": {
        "down":  {"texture": "#bottom", "uv": [0, 0, 16, 16], "cullface": "down"},
        "up":    {"texture": "#top",    "uv": [0, 0, 16, 16], "cullface": "up"},
        "north": {"texture": "#side",   "uv": [0, 0, 16, 16], "cullface": "north"},
        "south": {"texture": "#side",   "uv": [0, 0, 16, 16], "cullface": "south"},
        "west":  {"texture": "#side",   "uv": [0, 0, 16, 16], "cullface": "west"},
        "east":  {"texture": "#side",   "uv": [0, 0, 16, 16], "cullface": "east"}
      }
    }
  ]
}
```

#### 4.2.2 字段语义（与 Minecraft 对齐）

| 字段 | 位置 | 类型 | 范围/取值 | 说明 |
|------|------|------|-----------|------|
| `format` | 顶层 | string | `"mecraft_model_v1"` | 格式标识，用于校验 |
| `ambientocclusion` | 顶层 | bool | true/false | 是否启用 AO（Mecraft 顶点已有 ao 字段） |
| `textures` | 顶层 | object | 变量名→纹理名 | 变量名不带 `#`；值为 Mecraft 纹理名（如 `"oak_planks"`），不含 `block/` 前缀 |
| `elements` | 顶层 | array | — | 长方体元素列表 |
| `from` | element | [x,y,z] | 0~16 | 长方体一个对角顶点 |
| `to` | element | [x,y,z] | 0~16 | 长方体对角顶点 |
| `faces` | element | object | down/up/north/south/west/east | 6 面，每面可选（缺省则该面不渲染） |
| `texture` | face | string | `"#变量名"` | **必须**，引用 `textures` 中的变量 |
| `uv` | face | [x1,y1,x2,y2] | 0~16 | UV 坐标，缺省为该面在元素上的自然投影 |
| `cullface` | face | string | down/up/north/south/west/east | 该方向邻居为不透明完整立方体时剔除本面；缺省则永不剔除 |
| `rotation` | face | int | 0/90/180/270 | 纹理旋转 |
| `tintindex` | face | int | -1/0/1/… | 染色索引，-1 或缺省表示无染色 |

#### 4.2.3 与 Minecraft 的差异

| 项目 | Minecraft | Mecraft | 原因 |
|------|-----------|---------|------|
| `parent` | 支持 | **不支持**（转换时扁平化） | 简化运行时加载，继承在转换脚本中一次性解析 |
| `textures` 值 | `"block/xxx"` 或 `"#var"` | Mecraft 纹理名 `"xxx"` 或 `"#var"` | 对齐 Mecraft 纹理命名 |
| `display`/`gui_light` | 支持 | **不支持** | Mecraft 物品渲染另行处理 |
| 元素 `rotation` | 支持（任意轴 0~360） | **暂不支持**（用方块状态变换替代） | 简化；朝向通过方块状态 rotY/flipY 实现 |
| `__comment` | 非官方 | 转换时丢弃 | — |

### 4.3 内存数据结构

新增 `src/world/block/BlockModel.h`：

```cpp
// A single face of a model element. Faces are optional per direction.
struct ModelFace {
    std::string textureVar;   // e.g. "#side" (keeps leading '#')
    float uv[4];              // x1, y1, x2, y2 in 0..16 range
    uint8_t cullfaceBits;     // bitmask of Direction (0 = never cull)
    uint8_t uvRotation;       // 0/90/180/270
    int8_t  tintIndex;        // -1 = none
};

// An axis-aligned box element of a model, in 0..16 local space.
struct ModelElement {
    float from[3];            // 0..16
    float to[3];              // 0..16
    // Per-direction face; nullptr means face absent.
    // Index order matches Direction enum (Down,Up,North,South,West,East).
    std::array<std::unique_ptr<ModelFace>, 6> faces;
};

// A parsed Mecraft block model.
struct BlockModel {
    std::string name;         // e.g. "block/oak_stairs"
    bool ambientOcclusion = true;
    // Texture variable -> Mecraft texture name (no '#', no "block/" prefix).
    std::unordered_map<std::string, std::string> textures;
    std::vector<ModelElement> elements;
};

// Transform applied to a model based on block state (facing/half/axis).
// All rotations are in 90-degree increments around block center (8,8,8).
struct ModelTransform {
    uint8_t rotY = 0;         // 0/90/180/270 around Y (for facing)
    uint8_t rotX = 0;         // 0/90/180/270 around X (for half=top of stairs)
    uint8_t rotZ = 0;         // 0/90/180/270 around Z (rare, e.g. some orientations)
};

// A variant entry: which model + which transform for a given block state.
struct ModelVariant {
    const BlockModel* model = nullptr;
    ModelTransform transform;
};
```

### 4.4 模型加载与注册：`BlockModelRegistry`

新增 `src/world/block/BlockModelRegistry.h/.cpp`：

```cpp
class BlockModelRegistry {
public:
    // Load all model JSON files under assets/models/blocks/.
    // Parses format, textures, elements, faces. Caches by model name.
    static void init(ResourceMgr* resourceMgr);

    // Returns nullptr if model not found.
    static const BlockModel* get(const std::string& name);

private:
    static std::unordered_map<std::string, std::unique_ptr<BlockModel>> s_models;

    // Parse one model JSON file into a BlockModel.
    static std::unique_ptr<BlockModel> parseModel(const nlohmann::json& j,
                                                   const std::string& name);

    // Parse a single element's from/to/faces.
    static ModelElement parseElement(const nlohmann::json& j);

    // Parse one face (texture/uv/cullface/rotation/tintindex).
    static std::unique_ptr<ModelFace> parseFace(const nlohmann::json& j);
};
```

**加载流程**：

1. 遍历 `assets/models/blocks/` 下所有 `.json` 文件
2. 校验 `format == "mecraft_model_v1"`
3. 解析 `textures` 表（变量名→纹理名）
4. 解析 `elements` 数组，每个元素解析 `from`/`to`/`faces`
5. 每个 `faces` 中存在的方位解析 `ModelFace`，不存在的方位保持 `nullptr`
6. `cullface` 字符串转 `Direction` 位掩码（一个面可对多方向剔除？Minecraft 仅单方向，这里也用单方向，存为 bits 以便扩展）
7. 缓存到 `s_models[name]`

#### 4.6.1 `buildModelBlock` 算法

```cpp
void ChunkMeshBuilders::buildModelBlock(ChunkMeshData& meshData,
                                        const SubChunkMeshingSnapshot& snapshot,
                                        BlockID blockId,
                                        const BlockDef& def,
                                        int x, int y, int z) {
    // 1. Get state key index from snapshot
    const uint16_t stateKeyIndex = snapshot.getStateKeyIndex(x, y, z);

    // 2. Look up model variant (model + transform)
    const ModelVariant* variant = BlockStateRegistry::getModelVariant(blockId, stateKeyIndex);
    if (!variant || !variant->model) return;  // no model -> emit nothing
    const BlockModel& model = *variant->model;
    const ModelTransform& tf = variant->transform;

    // 3. Get per-state texture override (if any) for texture var resolution
    const StateTextureSet& stateTex = BlockStateRegistry::getStateTextures(blockId, stateKeyIndex);

    // 4. Determine target vertex buffer by render layer
    std::vector<BlockVertex>& target = vertexTargetFor(meshData, def);

    // 5. For each element, for each present face:
    for (const ModelElement& elem : model.elements) {
        for (int dir = 0; dir < 6; ++dir) {
            if (!elem.faces[dir]) continue;
            const ModelFace& face = *elem.faces[dir];

            // 5a. Cullface check: if neighbor in cullface direction is opaque
            //     full cube, skip this face.
            if (shouldCullModelFace(snapshot, x, y, z, face.cullfaceBits)) continue;

            // 5b. Compute 4 face corner positions in 0..16 local space,
            //     then scale to 0..1 block space (divide by 16).
            glm::vec3 corners[4];
            computeFaceCorners(elem, dir, corners);  // 0..16
            for (auto& c : corners) c /= 16.0f;

            // 5c. Apply state transform (rotY/rotX/rotZ) around block center (0.5,0.5,0.5)
            for (auto& c : corners) c = applyTransform(c, tf);

            // 5d. Translate to world block position
            for (auto& c : corners) c += glm::vec3(x, y, z);

            // 5e. Resolve texture var -> texture layer
            //     "#side" -> look up model.textures["side"] -> texture name
            //     -> resolve to AnimatedTextureRef via stateTex override or base lookup
            const AnimatedTextureRef& texRef = resolveModelTexture(
                face.textureVar, model.textures, stateTex, def);
            const uint16_t layer = texRef.firstLayer;

            // 5f. Compute UV: 0..16 -> 0..1, apply uvRotation
            float faceUV[4][2];
            computeFaceUV(face.uv, face.uvRotation, faceUV);

            // 5g. Compute AO for each corner (sample 3 neighbors per standard pattern)
            uint8_t ao[4];
            computeModelFaceAO(snapshot, x, y, z, dir, elem, tf, ao);

            // 5h. Compute lighting (sunlight + blocklight) per corner
            uint8_t sunlight[4], blockLight[4];
            computeModelFaceLight(snapshot, x, y, z, dir, corners, sunlight, blockLight);

            // 5i. Pack tint info
            uint16_t tintPacked = packTint(face.tintIndex, def);

            // 5j. Emit 4 vertices + 6 indices (two triangles)
            appendFaceVertices(target, corners, faceUV, dir,
                               sunlight, blockLight, ao, layer,
                               texRef, tintPacked, def);
        }
    }

    // 6. Update mesh bounds
    meshData.expandBounds(glm::vec3(x, y, z), glm::vec3(x+1, y+1, z+1));
}
```

#### 4.6.2 关键子函数

**`shouldCullModelFace`**（cullface 剔除）：

```cpp
// Returns true if the face should be culled (not rendered).
bool shouldCullModelFace(const SubChunkMeshingSnapshot& snapshot,
                         int x, int y, int z, uint8_t cullfaceBits) {
    if (cullfaceBits == 0) return false;  // no cullface set -> never cull
    // For each direction bit set in cullfaceBits, check neighbor.
    // (Minecraft only sets one direction per face, but we support bitmask.)
    for (int d = 0; d < 6; ++d) {
        if (!(cullfaceBits & (1 << d))) continue;
        const glm::ivec3 off = kDirOffset[d];
        const BlockID neighborId = snapshot.getBlock(x+off.x, y+off.y, z+off.z);
        if (neighborId == BlockIds::AIR) continue;
        const BlockDef& nbDef = BlockRegistry::getFast(neighborId);
        // Only full opaque cubes cull model faces (same as Minecraft).
        if (nbDef.renderShape == BlockRenderShape::Cube &&
            nbDef.renderLayer == BlockRenderLayer::Opaque &&
            nbDef.isSolid) {
            return true;
        }
    }
    return false;
}
```

**`applyTransform`**（状态变换，绕方块中心 0.5 旋转 90°的倍数）：

```cpp
glm::vec3 applyTransform(glm::vec3 p, const ModelTransform& tf) {
    p -= glm::vec3(0.5f);
    if (tf.rotX) p = rotate90X(p, tf.rotX);
    if (tf.rotY) p = rotate90Y(p, tf.rotY);
    if (tf.rotZ) p = rotate90Z(p, tf.rotZ);
    p += glm::vec3(0.5f);
    return p;
}
```

90° 旋转通过坐标分量交换 + 取反实现（无需三角函数），保证数值精确。

**`resolveModelTexture`**（纹理变量→层）：

```cpp
const AnimatedTextureRef& resolveModelTexture(
    const std::string& textureVar,                    // "#side"
    const std::unordered_map<std::string,std::string>& modelTextures,
    const StateTextureSet& stateTex,
    const BlockDef& def) {
    // Strip leading '#'
    const std::string varName = textureVar.substr(1);
    // 1. Per-state texture override takes priority
    auto stIt = stateTex.varOverrides.find(varName);
    if (stIt != stateTex.varOverrides.end()) return stIt->second;
    // 2. Look up model texture table -> texture name
    auto mtIt = modelTextures.find(varName);
    if (mtIt == modelTextures.end()) return kEmptyTextureRef;  // error, log
    const std::string& texName = mtIt->second;
    // 3. Map texture name to AnimatedTextureRef
    //    (复用 BlockRegistry 已有的 name->layer 查找表)
    return BlockRegistry::getTextureRefByName(texName);
}
```

> **纹理名→层查找**：`BlockRegistry` 已在 `init()` 时建立纹理名→`AnimatedTextureRef` 的映射（加载 `blocks.json` 解析六面纹理时所用）。新增一个 `getTextureRefByName(name)` 公开方法复用该表。模型中出现的纹理名必须在 `blocks.json`/`block_textures.json` 体系中已注册。

**`computeModelFaceAO`**（AO 采样）：

对模型面四角，按标准 AO 算法采样每个角附近的 3 个邻居方块（side1、side2、corner）。由于异形方块的面可能小于完整面，AO 是**近似**的——以面所在方向的邻居采样为准，与 Minecraft 行为一致。对模型自身内部产生的相邻面，AO 取满值（3）。

### 4.7 贪婪合并与优化策略

异形方块的贪婪合并是本设计的重点难点。完整立方体的贪婪合并之所以高效，是因为相邻同纹理方块的面是完美对齐的完整 1×1 面。异形方块的面是任意大小、任意位置的小面，跨方块合并极其复杂且收益低（Minecraft 本身也不做跨方块贪婪合并）。

因此采用**分层优化策略**：

#### 4.7.1 第一层：cullface 邻居剔除（必须实现，收益最大）

如 4.6.2 所述，模型面带 `cullface` 时，若该方向邻居是完整不透明立方体，则该面不发射。这是最大的三角形削减手段。例如：

- 楼梯贴着泥土墙：朝墙的面被剔除
- 台阶叠在完整方块上：底面被剔除

**收益**：典型场景下可减少 30%~60% 的异形方块三角形。

#### 4.7.2 第二层：模型内部面合并（推荐实现）

同一模型内，若两个元素的面共面、相邻、同纹理、同 UV 旋转，可合并为一个大面。在 `BlockModelRegistry::parseModel()` 解析后做一次合并预处理，结果缓存。

示例：某些锅/铁砧模型可能由多个小长方体拼成一个大面，合并后三角形数减半。

**实现**：对模型的每个元素每个面，按 `(方向, 纹理变量, UV旋转, tintindex)` 分组；同组内检测共面（法线方向坐标相同）且在切平面内相邻（边重合、UV 连续），合并 UV 和 corners。

#### 4.7.3 第三层：模型网格缓存（推荐实现）

同一个 `BlockModel + ModelTransform` 组合的网格（局部 0~1 空间内的顶点+索引）解析一次后缓存。区块网格生成时只需：

1. 查缓存得局部网格
2. 平移到方块坐标 `(x,y,z)`
3. 逐顶点查邻居重算 AO 和光照（AO/光照依赖位置，不能缓存）

**收益**：省去每方块重复的几何计算；缓存命中率高（楼梯只有少数变体）。

#### 4.7.4 第四层：硬件实例化（高级，可选）

对出现频繁的模型方块（如成片楼梯、台阶），用 `glDrawElementsInstanced` 实例化绘制。每个实例只需一个 `mat4` 实例矩阵 + 光照/AO 数据。需渲染管线支持实例化顶点属性。

**收益**：大幅降低 draw call，适合楼梯/台阶密集的建筑。

#### 4.7.5 第五层：特殊形状降级为立方体贪婪合并（高级，可选）

对**几何上等价于完整立方体的子集**的形状，可走贪婪合并路径：

- **台阶（slab）**：半高立方体，可视为高度减半的 Cube，参与 Y 方向贪婪合并
- **竖板砖（垂直 slab）**：宽度减半的 Cube，参与 X/Z 方向贪婪合并

实现方式：为这些形状注册专门的 `MeshBuilderFn`，内部调用改造版的贪婪合并算法（面尺寸改为 0.5 而非 1.0）。这是最复杂的优化，作为长期目标。

#### 4.7.6 优化层级总结

| 层级 | 技术 | 实现难度 | 收益 | 阶段 |
|------|------|----------|------|------|
| 1 | cullface 剔除 | 低 | 高（30~60% 三角形） | MVP 必须 |
| 2 | 模型内面合并 | 中 | 中（视模型而定） | MVP 后 |
| 3 | 模型网格缓存 | 中 | 中（CPU 时间） | MVP 后 |
| 4 | 硬件实例化 | 高 | 高（draw call） | 长期 |
| 5 | slab 降级贪婪合并 | 高 | 中（特定形状） | 长期 |

## 五、Python 转换脚本设计

### 5.1 目标

将 Minecraft 原版模型 JSON（`D:\project\minecraft-vanilla-assets\models\block\*.json`）转换为 Mecraft 模型 JSON（`assets/models/blocks/*.json`）。

### 5.2 脚本位置

`tools/convert_mc_model.py`

### 5.3 脚本职责

1. **解析 `parent` 继承**：递归读取父模型，合并 `textures`、`elements`、`ambientocclusion`（子覆盖父）
2. **解析纹理变量引用**：保留 `#var` 形式在 `faces.texture` 中；`textures` 表的值从 Minecraft 路径转为 Mecraft 纹理名
3. **纹理路径映射**：
   - `"block/oak_planks"` → `"oak_planks"`
   - `"minecraft:block/oak_planks"` → `"oak_planks"`
   - `"#var"` 保持不变
4. **保留 `from`/`to`/`faces`/`uv`/`cullface`/`rotation`/`tintindex`** 原样
5. **丢弃** `display`、`gui_light`、`__comment`、元素级 `rotation`（带 `origin`/`axis`/`angle` 的，转换时记录警告，因为 Mecraft 暂不支持）
6. **补全缺省 `uv`**：若面无 `uv`，按 Minecraft 规则用 `from`/`to` 在该面的投影计算 UV
7. **输出**：写入 `assets/models/blocks/<name>.json`，带 `format: "mecraft_model_v1"`


### 5.5 脚本核心逻辑（伪代码）

```python
def load_model_with_inheritance(mc_root, model_path, cache):
    """Recursively resolve parent inheritance."""
    if model_path in cache:
        return cache[model_path]
    raw = read_json(os.path.join(mc_root, model_path))
    merged = {"textures": {}, "elements": [], "ambientocclusion": True}
    if "parent" in raw:
        parent = load_model_with_inheritance(mc_root, raw["parent"] + ".json", cache)
        merged["textures"].update(parent["textures"])
        merged["elements"] = deepcopy(parent["elements"])
        merged["ambientocclusion"] = parent["ambientocclusion"]
    if "textures" in raw:
        merged["textures"].update(raw["textures"])
    if "elements" in raw:
        merged["elements"] = raw["elements"]   # child fully replaces elements
    if "ambientocclusion" in raw:
        merged["ambientocclusion"] = raw["ambientocclusion"]
    cache[model_path] = merged
    return merged

def remap_texture(value, texture_map):
    """block/oak_planks -> oak_planks; #var -> #var (unchanged)."""
    if value.startswith("#"):
        return value
    name = value.split(":")[-1]          # strip namespace
    if name.startswith("block/"):
        name = name[len("block/"):]
    return texture_map.get(name, name)

def fill_default_uv(element, face_name, face):
    """If face has no uv, compute from from/to projection on that face."""
    if "uv" in face:
        return face["uv"]
    frm, to = element["from"], element["to"]
    # down/up: uv from x,z; north/south: x,y; west/east: z,y
    if face_name in ("down", "up"):
        return [frm[0], frm[2], to[0], to[2]]
    if face_name in ("north", "south"):
        return [frm[0], frm[1], to[0], to[1]]
    if face_name in ("west", "east"):
        return [frm[2], frm[1], to[2], to[1]]

def convert(mc_root, input_path, output_path, texture_map):
    cache = {}
    merged = load_model_with_inheritance(mc_root, input_path, cache)
    out = {"format": "mecraft_model_v1"}
    out["ambientocclusion"] = merged.get("ambientocclusion", True)
    out["textures"] = {k: remap_texture(v, texture_map)
                       for k, v in merged["textures"].items()}
    out["elements"] = []
    for elem in merged["elements"]:
        if "rotation" in elem:
            warn(f"element rotation not supported, skipping transform in {input_path}")
        new_elem = {"from": elem["from"], "to": elem["to"], "faces": {}}
        for fname, fdata in elem.get("faces", {}).items():
            new_face = {
                "texture": fdata["texture"],   # keep #var
                "uv": fill_default_uv(elem, fname, fdata),
            }
            if "cullface" in fdata: new_face["cullface"] = fdata["cullface"]
            if "rotation" in fdata: new_face["rotation"] = fdata["rotation"]
            if "tintindex" in fdata: new_face["tintindex"] = fdata["tintindex"]
            new_elem["faces"][fname] = new_face
        out["elements"].append(new_elem)
    write_json(output_path, out)
```

## 八、风险与注意事项

1. **AO 近似**：异形方块面的 AO 采样按完整面方向取邻居，与 Minecraft 略有差异（Minecraft 对小面也按面方向采样，行为一致；但 Mecraft 需确保 `computeModelFaceAO` 的邻居采样坐标正确，避免越界）。

2. **纹理名一致性**：转换脚本产出的纹理名必须与 Mecraft `block_textures.json`/`blocks.json` 中的纹理名一致，否则 `getTextureRefByName` 查找失败。建议建立纹理名映射表 `texture_map.json` 处理命名差异。

3. **元素级 rotation 丢弃**：少数 Minecraft 模型使用元素 `rotation`（如火把的倾斜），转换脚本会丢弃并告警。这类方块需用 Mecraft 已有的 `torch` builder，或后续扩展元素级旋转支持。

4. **内拐角/外拐角楼梯**：`shape=inner_left/inner_right/outer_left/outer_right` 需要 `inner_stairs`/`outer_stairs` 模型 + 朝向变换，`modelVariants` 条目较多（每方向每形状一条），需仔细核对变换矩阵。

5. **状态键格式**：`modelVariants` 的键必须与 `BlockStateRegistry` 的状态键串格式完全一致（属性排序、分隔符），否则查表失败。建议复用 `BlockStateRegistry::makeStateKey(props)` 生成键。

6. **性能**：异形方块三角形数远多于立方体（一个楼梯 3 元素最多 18 面 = 36 三角形 vs 立方体最多 12 三角形）。cullface 剔除和网格缓存是控制三角形数与 CPU 时间的关键。密集异形方块区域（如楼梯农场）需关注帧率，必要时启用实例化。

## 附录 B：UV 旋转计算

给定面 UV `[x1,y1,x2,y2]`（0~16）和旋转角度，四角 UV 计算如下（顺时针旋转纹理）：

```
rotation=0:   (x1,y1) (x2,y1) (x2,y2) (x1,y2)
rotation=90:  (x2,y1) (x2,y2) (x1,y2) (x1,y1)
rotation=180: (x2,y2) (x1,y2) (x1,y1) (x2,y1)
rotation=270: (x1,y2) (x1,y1) (x2,y1) (x2,y2)
```

## 附录 C：90° 空间旋转矩阵（绕方块中心 0.5）

绕 Y 轴（用于 facing 朝向）：

```
rotY=0:   (x, y, z)
rotY=90:  (1-z, y, x)
rotY=180: (1-x, y, 1-z)
rotY=270: (z, y, 1-x)
```

绕 X 轴（用于 half=top 楼梯上下翻转）：

```
rotX=0:   (x, y, z)
rotX=180: (x, 1-y, 1-z)
```

这些变换通过对坐标分量交换 + 取反实现，数值精确，无浮点误差累积。
