# Mecraft 内置光影完整渲染管线设计

> 目标：不做可替换 shaderpack 系统，而是在 Mecraft 内部实现一个 DerivativeMain-inspired 的内置光影预设。Renderer 负责 pass graph、frame data、render target、material contract 和 debug 工具；shader 只作为该内置预设的实现细节。

## 1. 当前结论

当前项目已经从“原版前向渲染 + 阴影”推进到了 **Hybrid Deferred 光影地基**：

- 架构完成度：约 **60%**。核心原因是 G-buffer、scene lighting target、transparent composite、half-res volumetric、sky capture、shadow projection data、RenderFrameData 和材质契约已经存在。
- 视觉完成度：约 **25%**。目前画面仍接近“原版 + 阴影 + 基础调色”，水体、体积云、复杂大气、反射、雨天湿润材质、软阴影质量、体积光和最终后处理还没有形成 DerivativeMain 级别的组合效果。
- 下一阶段重点：继续补 **管线契约和资源槽**，而不是先追具体效果。尤其是 history/temporal、water/reflection、shadow V2、volumetric/cloud、post mip chain 这些高级效果的输入输出要先稳定。

可以把当前状态理解为：**能承载光影包效果的主梁已经搭起来，但很多专用房间还没有布线、没有水管、也没有家具。**

## 2. 设计范围

本项目的光影目标是“内置预设”，不是 Iris/OptiFine 的通用 shaderpack 兼容层。

因此不需要实现：

- 外部 shaderpack 加载、宏展开、program 切换体系。
- `colortex0-7` 原样模拟。
- LabPBR/资源包完整兼容。
- Iris/OptiFine 全套动态 uniform 命名兼容。
- 让第三方开发者任意替换 pass 的开放式资源图。

需要实现：

- 项目自有的稳定 pass graph。
- 项目自有的 G-buffer/material/light/sky/water/volumetric/post contract。
- 与 Minecraft 光影思路相同的前向/延迟混合路径。
- DerivativeMain 的核心效果：软阴影、屏幕空间接触阴影、云影、半分辨率体积雾/体积光、水体折射/反射/吸收、体积云、物理启发光照、HDR 后处理和风格化调色。

## 3. 目标管线总览

目标帧结构如下：

```text
Frame Setup
  RenderFrameData
  Camera / weather / time / sky / shadow light
  Jitter / previous frame data              [未实现]

Sky / Atmosphere
  sky analytic or LUT background
  sky capture / irradiance

Geometry
  GBuffer: opaque terrain
  GBuffer: cutout terrain
  optional material classification

Shadow
  stable shadow projection
  depth shadow
  optional transparent shadow / cloud shadow / RSM

Screen Space Base Effects
  SSAO / bent visibility
  contact shadow
  optional SSR / reflection mask

Deferred Lighting
  direct sun/moon
  sky ambient
  voxel block light
  material BRDF
  shadowing
  aerial perspective base
  -> SceneLighting HDR

Volumetric
  half-res volumetric fog
  volumetric light
  cloud shadow contribution
  depth-aware composite

Transparent / Water
  generic transparent
  water surface forward/composite
  refraction from SceneLighting + depth
  SSR/reflection
  absorption, foam, caustic-like highlights
  underwater resolve

Cloud
  half-res / low-frequency volumetric cloud
  cloud lighting
  cloud history / reprojection               [后期]

Post
  exposure
  bloom mip chain
  tonemap ACES/AgX
  color grading
  sharpen / CAS
  dither

UI / Overlays
  crosshair
  dashboard
  text
```

## 6. 当前已经实现的关键能力

### 6.1 Hybrid Deferred 主骨架

已具备 Forward Legacy 与 Hybrid Deferred 双路径。Hybrid Deferred 下，世界 opaque/cutout 进入 G-buffer，再进行 shadow、SSAO、deferred lighting、volumetric 和 transparent composite。

意义：

- 后续水、雾、反射、后处理可以读取统一的 scene/depth/G-buffer 输入。
- 光照模型可以逐步从经验 diffuse 演进到物理启发 BRDF。

不足：

- 还没有显式 pass graph/资源注册层。
- 某些 pass 之间仍通过手写 blit 和当前 framebuffer 状态衔接，长期会增加维护成本。

### 6.2 G-buffer 与材质契约

当前 G-buffer 已有 albedo、normal/AO、voxel light、material、material aux、depth，并且 `gbuffer_contract.glsl` 定义了 GPU 侧 `SurfaceMaterial` / `SurfaceMaterialAux` 和材质参数。

意义：

- 这已经不是“只有颜色和法线”的早期延迟管线，可以承载 roughness、f0、emission、subsurface 等基础材质差异。
- CPU 方块材质与 shader 材质逻辑已经开始对齐。
- `GMaterialAux` 已承载 material kind、wetness mask、porosity、metalness，deferred lighting 和 reflection placeholder 已能读取这些数据。

不足：

- 当前 wetness 是天气驱动的全局响应，还没有雨滴遮挡、局部积水、水坑 mask 或 biome/height 分布。
- 水、玻璃、叶子、矿石、发光方块还需要继续调内置材质参数。

### 6.3 RenderFrameData

当前 frame data 已统一 view/projection、camera position、sky colors、time、fog、weather、moon shadow active 等信息。

意义：

- 避免每个 pass 自己算一套天空、时间、雾和天气。
- 是后续 Iris/OptiFine 类 uniform 短板的正确替代方案：不用兼容名字，但要拥有同等信息。

不足：

- 缺 previous frame data、jitter、velocity、history index。
- 缺维度/生物群系级的光影预设入口。

### 6.4 Shadow Projection Foundation

当前已有 `ShadowProjectionData`，显式保存 shadow model-view、projection、inverse、viewProj、extent、texelWorldSize。Projection V2 第一版已开始落地：CPU 侧使用相机位置稳定中心、light-space 正交覆盖和 texel snapping，避免 shadow map 随 yaw/pitch 转动重排；运行时暂时保持 no-warp，quartic/radial warp 保留在研究/debug 方向。

意义：

- 避免继续把所有阴影逻辑堆到一个 `viewProj` 上。
- 给后续稳定 shadow projection、PCSS 半影半径、bias 标定、receiver coverage 打了基础。

不足：

- 还不是完整 DerivativeMain 式 shadow projection；当前优先选择相机位置稳定覆盖，牺牲一点分辨率换取转头时阴影不漂移。
- 只有单 shadow depth，没有 cascade/pseudo-cascade、transparent shadow、colored shadow、RSM。

### 6.5 SceneLighting 与 TransparentComposite

Deferred lighting 已输出到 `SceneLighting` HDR target。透明合成有独立 `TransparentComposite` color/depth，避免透明 pass 直接读写同一颜色缓冲。

意义：

- 水体折射、SSR、体积合成、透明合成终于有稳定的 scene input。
- generic transparent 与 water 已在收集层开始拆分。

不足：

- 水体还没有自己的 dedicated draw/composite path。
- 透明排序、折射、厚度、透明阴影还未完善。

### 6.6 Half-res Volumetric Shell

当前已有 half-res target、`volumetric_fog.fs` 和 composite pass。

意义：

- 体积雾/体积光不需要从零开始加资源槽。
- DerivativeMain 的“半分辨率高级效果 + 深度合成”方向已可承载。

不足：

- 当前更像基础雾壳，不是完整体积 ray marching 系统。
- 缺 temporal、深度感知上采样质量、phase function、云/天气耦合。

### 6.7 HDR Post 基础

已有 HDR scene、bloom extract/blur、auto exposure、tonemap、shaderpack grading、dither、水下 tint、sun rays 等基础。

意义：

- 最终画面风格化不需要重建整条 post stack。

不足：

- bloom 还不是完整 mip chain。
- emissive 材质与 bloom/HDR 强度没有形成稳定契约。
- 色彩还没有围绕 DerivativeMain-like preset 完成校准。

## 7. 关键缺口

### 7.1 Temporal / History 是最大架构缺口

很多光影高级效果不是靠单帧硬堆采样，而是靠历史复用稳定质量：

- TAA。
- 体积云低频更新。
- SSR 稳定。
- 体积雾降噪。
- 自动曝光稳定。

当前缺：

- jittered projection。
- previous view/proj/invViewProj。
- velocity/motion vector。
- history scene/depth/cloud/reflection targets。
- reprojection rejection 规则。

建议：先实现非常小的 Temporal Foundation，不急着开启完整 TAA。只要资源和 frame data 稳定，后续云、SSR、雾都能复用。

### 7.2 水体需要从“透明方块”升级为“专用 composite 系统”

DerivativeMain-like 水体至少需要：

- 水面材质识别和独立 draw list。
- 程序化波浪/法线。
- Fresnel。
- scene color 折射。
- depth thickness / absorption。
- SSR 或 sky fallback reflection。
- 岸边 foam/扰动。
- 水下颜色、雾、折射和曝光响应。

当前只具备：

- 水体 material kind。
- 水体与普通透明在 pass plan 上的初步分离。
- SceneLighting/Depth 可作为折射输入。

下一步应做：

- `renderWaterCompositePass` 从普通透明中独立出来。
- 水 shader 读取 SceneLighting、Depth、GBuffer、SkyCapture、Noise。
- 先做无 SSR 的 refraction + absorption + Fresnel，再接 SSR。

### 7.3 阴影还需要 Projection V2

当前阴影已经比原版强，并且 Projection V2 第一版算法已经接入，但距离 shaderpack 式软阴影还差：

- 更完整的 receiver coverage 视觉验证。
- 更精细的 projection fade/边界处理。
- PCSS blocker search 与半影估计继续视觉校准。
- normal offset 和 bias 已统一到 shadow texel/world scale，仍需实机场景调参。
- contact shadow 与 shadow map 的层次关系。
- cloud shadow 与天气/云层耦合。
- transparent/colored shadow。

建议：不要急着恢复 quartic warp。先用当前 no-warp Projection V2 做稳定性和 PCSS 视觉验证，再考虑 DerivativeMain distortion。

### 7.4 大气、雾、云需要统一参数

当前 sky、aerial perspective、volumetric fog 是可工作的，但还不像一个统一大气系统。

缺：

- 统一的 atmosphere settings。
- sky transmittance / irradiance / aerial perspective 参数共享。
- fog/cloud/weather 的 density、height、phase、noise 入口。
- 云影来自真实云层或至少来自同一套 cloud settings。
- 下界/末地等维度差异。

建议：先做 `AtmosphereSettings`/`VolumetricSettings`/`CloudSettings` 的数据入口，再实现更复杂视觉。

### 7.5 反射与湿润材质是 DerivativeMain-like 观感的中期关键

当前材质有 roughness/f0，但没有真正把反射和天气拉起来。

缺：

- SSR/reflection target。
- roughness-aware reflection。
- wetness 修改 roughness/f0/diffuse darkening。
- 雨天地表高光、水坑感、树叶/草湿润响应。

建议：等水体 pass V1 可用后，实现通用 SSR/reflection，这样水和湿地共用一套能力。

## 8. 推荐阶段

### M0：管线文档与 Debug 基线

状态：基本完成。方向已固化，debug/timer 已覆盖主要资源和 pass。

目标：

- 将当前 pass graph、target contract、shader contract 固化。
- 增加 resource/debug view 清单。
- GPU timer 扩展到 Volumetric、Water、Post、Reflection、Cloud。

完成标准：

- 每个高级效果都有明确输入/输出。
- Dashboard 能看见关键 pass cost 和当前资源视图。

### M1：Temporal Foundation

目标：

- `RenderFrameData` 增加 previous matrices、jitter、frame index。
- `DeferredRenderTargets` 增加 history scene/depth/velocity 资源。
- 第一版只建立资源和 debug，不强制开启 TAA。

完成标准：

- resize/history ping-pong 稳定。
- shader 可以读取 current/previous frame data。
- debug view 能显示 velocity/history reject mask。

### M2：Water Composite V1

目标：

- 水体从普通透明中独立 pass。
- 实现 Fresnel、折射、吸收、噪声法线、水下 tint。
- 暂不追求最终 SSR。

完成标准：

- 水看起来不再只是半透明蓝色面。
- 岸边、浅水、深水有可解释差异。
- 普通透明不被水 shader 影响。

### M3：Shadow V2

目标：

- Projection V2 第一版已接入：相机位置稳定中心、light-space texel snapping、no-warp runtime。
- 当前阶段冻结为稳定硬阴影占位；soft shadow、PCSS、contact shadow、cloud shadow 默认关闭，不再阻塞后续管线。
- Shadow Projection debug view 已能基于真实 depth 显示覆盖、边缘风险与 texel density。
- Shadow Visibility / Shadow Bias debug view 已加入，用于定位 shadow compare margin、acne 临界区、bias texels 和 normal offset texels。

完成标准：

- 移动/转动相机时阴影边界稳定。
- 近景接触阴影和远景 shadow map 层次清楚。
- 高 shadow distance 下无明显弯曲边界/跳动。

剩余：

- 后续若要恢复软阴影，应直接参考 DerivativeMain 的 PCSS/contact/cloud shadow 实现，而不是继续修当前临时 soft shadow。
- cloud shadow 默认强度暂时降为 0，避免动态云影噪声干扰 M3 shadow map 稳定性验证。
- contact shadow 默认强度降为低值，只作为近处接触暗部补充，不再承担主阴影。
- 仍未做 transparent/colored shadow、RSM、pseudo-cascade。

## 9. 什么时候可以开始真正做“光影预设”

严格来说，现在已经可以做局部效果；但如果目标是避免后面反复返工，建议达到以下条件后再进入“大量调视觉参数”的阶段：

- `SceneLighting + TransparentComposite + HalfRes + SkyCapture` 已稳定：当前基本达成。
- G-buffer/material contract 已稳定：当前基础达成，material kind/wetness/porosity/metalness aux 已补；后续主要是材质库调参和动态湿润分布。
- 水体有独立 pass：已达成基础链路，待视觉验证与参数调校。
- shadow projection V2 有 debug 和稳定采样：部分达成，算法链路已接入，待视觉验证。
- temporal/history 资源槽存在：已达成资源槽，待真实写入/reprojection。
- atmosphere/fog/cloud settings 有统一入口：已达成基础入口。
- GPU timer/debug view 能覆盖主要 pass：基本达成。

因此建议判断：

- **当前阶段**：可以继续做管线地基和少量验证性视觉。
- **M2 + M3 后**：可以开始认真打磨水体、阴影、光照的第一版观感。
- **M5 后**：可以开始把它称为“内置 DerivativeMain-like 光影预设 V1”。
- **M7 后**：才算完整可交付的内置光影体验。

## 10. 下一步最小行动清单

按“先补地基，不追效果”的原则，下一步建议这样做：

1. 补 `RenderFrameData` 的 temporal foundation 字段：frame index、jitter、previous view/proj/viewProj/invViewProj。
2. 在 `DeferredRenderTargets` 里加入 history/velocity 资源槽，但先只做 debug，不急着 TAA。
3. 把 transparent pass plan 落到真正的 `renderWaterCompositePass` 入口，水体与 generic transparent 分开执行。
4. 扩展 debug/timer：Volumetric、Water、Post，并增加 material/volumetric/scene/transparent debug view。
5. 开始 Shadow Projection V2 的 debug 可视化，确认稳定后再继续 PCSS/warp。

这套顺序能最大限度减少返工：Temporal 给云/SSR/雾铺路，Water pass 给水体铺路，Shadow V2 给软阴影铺路，Debug/timer 让之后所有视觉调参都可验证。
