## 1. 调试铁律

- **先复现，再定位**：不能复现的 bug 先补可复现路径（固定种子、固定输入录制、确定性验证场景）。
- **定位根因，禁止绕过**：临时改数据、屏蔽代码、放宽断言都不是修复；只有找到"为什么"并改正才叫修好。
- **一次只改一处**：定位后小步验证，避免多个疑似因素叠加。
- **修完必回归**：跑相关契约测试 + 单元测试 + perf 基准（如涉及热路径）。

## 2. 启动选项一览

`src/app/AppLaunchOptions.h` 集中了全部命令行开关（`main.cpp` 解析，`validateAppLaunchOptions` 校验交叉约束）：

**基准/自动运行**：

| 选项 | 作用 |
| --- | --- |
| `--auto-start-gameplay` | 启动即进游戏 |
| `--benchmark-seed` / `--benchmark-render-distance` | 固定世界种子/视距 |
| `--benchmark-duration-seconds` / `--benchmark-report-path` | 定时跑测并输出报告 |
| `--benchmark-enable-saving` | 是否写存档 |

**调试开关**：

| 选项 | 作用 |
| --- | --- |
| `--enable-debug-dashboard` | 是否开启运行时 Dashboard |
| `--enable-rhi-debug-output` | RHI 层调试输出（Vulkan 校验层日志） |
| `--rhi-backend <opengl/vulkan>` | 强制渲染后端 |

**输入录制回放**：

| 选项 | 作用 |
| --- | --- |
| `--record-input` / `--replay-input` | 录制/回放输入流 |
| `--input-record-path` / `--input-replay-path` | 录制文件路径 |
| `--input-replay-scope` | App 级或 Gameplay 级回放 |
| `--exit-when-playback-ends` | 回放结束自动退出 |

**验证运行**（第 5 节）：`--validation-scene-path`、`--validation-capture-path`、`--validation-report-path`、warmup/sample 帧数与分辨率。

排查建议：`--enable-rhi-debug-output` + Vulkan 后端能直接看到驱动校验层报错；渲染相关的疑难先开它。

## 3. Dashboard 运行时诊断

`src/ui/Dashboard.cpp`（`--enable-debug-dashboard`）：

- 呈现 FPS、帧时间历史曲线、渲染各阶段 CPU 时间。
- 配合 `DebugFrameProfiler`（仅 Debug 构建）看 fixedUpdate 子阶段耗时；配合 `RenderDebugService` 看 GPU pass 耗时（详见 09 篇）。
- 网络统计：包收发计数/丢弃（`GameServer`/`GameClient` 计数器）。

## 4. 输入录制与回放

- 录制：`--record-input --input-record-path out.bin` 正常玩一遍，把问题操作录下来。
- 回放：`--replay-input --input-replay-path out.bin` 以完全相同输入复跑，用于：
  - bug 复现（同一输入必现）；
  - 修复验证（回放前后行为对比）；
  - 确定性回归（配合 `--exit-when-playback-ends` 自动化）。
- 回放与录制的版本/作用域必须一致（`App` vs `Gameplay`），否则输入事件错位。

## 5. 确定性验证系统（Validation Run）

`src/app/validation/ValidationRunController.h`：

- 目的：**确定性渲染回归**——固定相机路径（`CameraPathContract`）、固定时钟（`kValidationFrameDeltaSeconds = 1/60`）、固定场景（Voxel/Model），跑 warmup + sample 帧，最终捕获参考图。
- 生命周期错误码 `ValidationRunError`：场景加载/匹配失败、相机采样失败、渲染失败、捕获失败等，逐项可查。
- 工作流：
  1. 修渲染 bug 或改渲染效果前，跑一次验证运行留下基准（capture + report）；
  2. 改动后重跑同一场景，对比捕获结果与报告指标；
  3. 渲染画面差异=像素对比，性能指标差异=帧时间统计（`collectPerformance`）。
- 参考图捕获通过 `reference_capture_manifest`（`tests/reference_capture_manifest_test.cpp`）管理；改动默认输出时 manifest 必须同步更新。

## 6. 游戏内命令

`src/game/states/CommandState.*`：

- 输入框提交 → `sendCommandRequest(text)` → 服务器执行 → `ServerCommandResult`/`ServerCommandError` 回显（见 06 篇消息清单）。
- 历史记录/上下键回滚（`commitCommandToHistory`、`recallPreviousCommand`）。
- 排查用途：游戏中直接跑命令验证世界状态（生成、模式、传送等），无需重启。

## 7. 契约测试：特性的守门人

`tests/*_contract_test.cpp` 是渲染/GPU/网络特性的"编译期+运行期合同"：

- GPU 特性（`gpu_light_contract_test`、`rtgi_nrd_signal_contract_test` 等）在 RHI 迁移期确保功能不被悄悄破坏；
- `renderer_removed_feature_test.cmake` 用脚本检查被移除特性是否彻底清理干净；
- `app_shutdown_contract_test` 校验 `GameManager::shutdown` 的**销毁顺序**（先 `waitIdle` → 再销毁状态机 → 最后关设备），防止退出路径损坏 GPU 资源。

**排查惯例**：渲染/GPU 问题先在对应契约测试上复现——契约测试是"最小可控复现环境"，跑绿说明主程序问题，跑红直接定位到契约覆盖的模块。

## 8. 常见故障排查路径

| 现象 | 优先排查路径 |
| --- | --- |
| 渲染画面错误/黑屏/花屏 | `--enable-rhi-debug-output` 看校验层 → 对应 `*_contract_test` → 验证系统前后对比 |
| 帧率下降/卡顿 | Dashboard FPS 曲线 → `DebugFrameProfiler` CPU 分阶段 → `GpuFrameStats` GPU pass → perf 基准对比（09 篇） |
| 联机同步异常（方块不一致/实体瞬移） | 先切单机复现 → `traceId` 双端断点对比（06 篇）→ `client_server_authority_test` |
| 方块交互无响应 | 服务器 `handleBlockAction` 校验逻辑 → 客户端发送意图是否到达 → 权威测试 |
| 退出崩溃 | `app_shutdown_contract_test` 销毁顺序 → 检查各系统 `shutdown()` 释放顺序 |
| 存档问题 | `chunk_save_serializer_test` → 保存/加载路径代码审查 |
| 输入异常（卡键/错位） | 录制回放对比 → `App`/`Gameplay` 作用域一致性检查 |

## 9. 排查禁忌

- **禁止兜底**：报错就静默、失败就跳过、功能缺失就降级——一律禁止（第 08 篇）。
- 禁止依赖 `printf` 插桩上线：临时日志要清理，改用统一调试路径。
- 禁止"玄学修复"：没找到根因的改动（换个写法恰好好了）要回退重查，否则隐患仍在。
- 禁止跨版本比对基准：perf 基准/验证捕获必须在相同构建配置（Release）、相同后端、相同硬件下对比。
