## 1. 项目定位

Mecraft 是一个**从零构建的桌面端体素沙盒游戏引擎**，目标是：

- 还原 Minecraft 的核心玩法体验（方块世界、生存、红石、合成、怪物）。
- 提供一套**电影级画质的现代渲染管线**（硬件 RTGI、NRD 降噪、FSR 3.1、反射探针、体积云/雾）。
- 提供**真正的客户端/服务器联机架构**，且单机模式与联机模式共用同一套 C/S 代码——单机时客户端连接的是一个进程内嵌的权威服务器。

关键数据（截至 2026-08）：

| 指标 | 数值 |
| --- | --- |
| 语言 / 标准 | C++17（禁用 RTTI 与异常，详见 `AGENTS.md`） |
| 代码规模 | 约 19.5 万行，801 个源文件（461 .h + 340 .cpp） |
| 核心静态库 | `mecraft_core`（单库，无 DLL 拆分） |
| 可执行目标 | `mecraft`（客户端）、`mecraft_server`（专用服务器） |
| 测试 | 139 个测试源文件，自研轻量 harness，`ctest` 驱动 |
| ECS 框架 | EnTT（`find_package(EnTT)`） |
| 图形 API | 统一 RHI 抽象：Vulkan 1.3 现代后端 + OpenGL 4.5 基础后端 |
| 依赖管理 | vcpkg manifest（`vcpkg.json`） |

项目存在两条平行的"游戏性世界线"：体素世界（主世界）与 glTF 模型展示场景（`ModelSceneAppState`，与体素世界共用同一套 Deferred / RTGI / NRD 渲染链）。新手建议**先只关注体素世界线**，模型场景是渲染验收用的独立沙盒。

## 3. 分层架构总览

整个程序从入口到 GPU 提交分成五层：

```
┌─────────────────────────────────────────────────────────────────────┐
│ L0 入口层        main.cpp / dedicated_server.cpp                    │
│                  └── 命令行解析 → AppLaunchOptions                  │
├─────────────────────────────────────────────────────────────────────┤
│ L1 应用层        src/app/GameManager（主循环 + 全局依赖装配）        │
│                  AppStateMachine（MainMenu → Loading → Gameplay）   │
├─────────────────────────────────────────────────────────────────────┤
│ L2 会话层        src/game/session/GameSession（会话聚合根）          │
│                  GameStateMachine（游戏内状态机：Gameplay/UI/Command│
│                  /Sleeping）                                        │
├─────────────────────────────────────────────────────────────────────┤
│ L3 玩法层        src/ecs（GameplayScene：EnTT Registry + Services + │
│                  GameplayPipeline 双管线）                           │
│                  src/world（权威 World：区块/光照/流体/红石/天气）    │
│                  src/server GameServer / src/client GameClient      │
│                  src/physics、src/item、src/crafting、src/particle  │
├─────────────────────────────────────────────────────────────────────┤
│ L4 呈现层        src/game/render → RenderScene（帧编排）             │
│                  DeferredPipeline / ForwardPipeline（RenderGraph）   │
│                  src/renderer/rhi（Vulkan / OpenGL 双后端）          │
│                  src/renderer/*（passes、contracts、nrd、shadow…）   │
│                  src/ui（HUD + 屏幕 UI）                             │
└─────────────────────────────────────────────────────────────────────┘
```

层与层的调用方向**自上而下**，同层横向通过接口/事件协作。特别注意：

- L3 与 L4 之间通过 `GameplayPresentationBuilder`（`src/game/presentation/`）把 ECS 世界状态转换成语义化渲染请求（灯光、实体网格、粒子列表），`RenderScene` 只消费请求，不反向查询 ECS。
- 渲染层内部又分三个子层：**RHI 后端**（最底层，管 GPU 资源）→ **核心中台**（RenderGraph / Pipeline / Bindless）→ **业务渲染**（passes / renderers / shadow）。

### 两个正交的运行时循环

玩法逻辑存在两条**时间语义不同的更新流水线**，新手最容易混淆：

| 流水线 | 频率 | 驱动者 | 职责 |
| --- | --- | --- | --- |
| `fixedUpdate` | 固定步长（默认 1/60s，可配置） | `GameplayPipeline::runFixedUpdate` | 输入采样、物理、方块交互、战斗、物品、粒子模拟 |
| `tick` | 20 TPS（1/20s） | `GameplayPipeline::runOneTick` | 权威模拟：流体刻、随机刻、红石、漏斗、方块支持、坠落方块 |

两者都由 `GameFrameOrchestrator::runFixedUpdate` 驱动：先以 fixed 步长累积服务器 tick（`m_serverAccumulator`，每次最多 4 tick），再跑 ECS fixed 系统，最后用 `tickClock` 决定本轮是否补跑 tick。详见 02 篇。

## 5. 核心对象生命周期

### 应用级：GameManager → Game

```
main
 └─ GameManager.init(window, rhi, input, audio, resource, threadpool)
      └─ AppStateMachine.pushState(MainMenuAppState)
 └─ GameManager.run()                      ← 主循环
      ├─ pollEvents / Time::update
      ├─ AppStateMachine.update(dt, acc)   ← 由当前 AppState 驱动（通常是 GameplayAppState）
      │    └─ Game.updateFrame(dt) → GameFrameOrchestrator（fixed + frame 逻辑）
      ├─ AppStateMachine.render(dt)
      │    └─ Game.renderFrame() → GameFrameOrchestrator::renderFrame → RenderScene::renderFrame
      └─ 循环直到 window.shouldClose
```

关键点：`Game` 是**一次游戏会话**（从创建世界到回主菜单）的生命周期对象；`GameSession` 是其内部聚合根。主菜单界面阶段没有 `Game`，只有 `GameManager` + UI。

### 会话级：GameSession 的初始化顺序

`GameSession::init`（在 `GameplayAppState` 进入时被调用）依次：

1. `init(config, resourceMgr, threadPool)` — 装配子对象外壳。
2. `initWorld(seed)` — 创建 `World` + `DayNightSystem` + `WeatherSystem`。
3. `initECS(deps)` — 创建 `GameplayScene`，绑定 `GameplayServices`（World/Server/Client…），创建玩家实体，注册 system；创建 `GameServer` / `GameClient` 与传输（单机用 `InProcessTransport`）。
4. `initStateMachine(deps)` — 创建 `GameStateMachine` 并 push `GameplayState`。
5. 加载：`pumpInitialChunkLoad` 流式加载出生点区块 → `InitialLoadProgress.complete` → `stabilizeLocalPlayerAfterInitialLoad` → `loadLocalPlayer()` 恢复玩家存档。

### 渲染级：RenderScene 的帧内对象

`RenderScene::renderFrame(worldView, camera, window, sizes, dayNight, weather, frameClock)`：

1. `prepareFrameResources` — 帧缓冲尺寸变化检查。
2. `executeFrameBeginGraph` — 独立小图：计时器重置。
3. `m_terrainStreamingService.beginFrame` / `m_sceneTlasCache.beginFrame` — 网格流式与 TLAS 更新准备。
4. `buildFrameContext` — 汇总相机、时域参数（jitter、帧索引）、天气派生数据成 `FrameContext`。
5. `m_activePipeline->renderFrame(ctx, settings)` — Deferred 或 Forward 管线执行完整 RenderGraph，返回 `FrameOutput`（sceneColor / sceneDepth 等）。

## 6. 依赖方向与分层纪律

项目没有显式的依赖检查工具，但代码库遵守如下约定（新增代码必须遵守）：

1. **`src/world` 不依赖 `src/renderer`**——渲染只能通过 `IWorldView` 只读接口访问世界。`World` 上的网格/光照刷新信号通过回调或标记机制暴露（如 `TerrainRenderCache` 订阅 chunk mesh 修订号）。
2. **`src/ecs` 不直接依赖 UI 与 RenderScene**——ECS 系统通过 `GameplayServices` 访问受限服务；跨层副作用（如打开背包界面）通过事件总线（`entt::dispatcher`）发出，由 `GameplayState` 等上层消费。
3. **`src/server` 与 `src/client` 只通过 `src/net` 通信**，不直接共享对象；单机走 `InProcessTransport` 也只是换传输实现，协议层不变。
4. **渲染业务层（passes/renderers）只能通过 `RhiDevice`/RenderGraph 访问 GPU**，不允许直接调用 Vulkan/OpenGL 原生 API；后端特有逻辑（如 `VkRhiInternal.h`）封闭在 `rhi/vulkan/` 内。
5. **`GameSession` 是玩法层唯一聚合根**——它不向外部暴露私有子对象，外部（UI、渲染）通过显式 accessor 拿句柄。

违反这些方向通常会表现为：需要把某个头文件 include 到不该 include 的地方，此时应停下来考虑引入接口（如 `IWorldView` 模式）或事件。

## 8. 建议的阅读顺序

**目标：能改代码、能修 bug、能加功能。** 按此顺序读源码，每步约 30–60 分钟：

1. **跑起来**（01 篇）→ 用 `./build.sh` 编译并运行，F3 打开调试面板看帧时间。
2. **读主循环**：`main.cpp` → `GameManager::run` → `GameFrameOrchestrator::runFixedUpdate` / `renderFrame`（02 篇并行阅读）。
3. **读会话装配**：`GameSession::init` → `GameplayScene` 构造 → `GameplayPipeline` 的系统列表。此时你能回答"加一个 ECS 系统挂哪里"。
4. **读世界核心**：`Chunk` → `SubChunk` → `World::setBlockState` → `BlockStateRegistry`。此时你能回答"方块状态怎么存、怎么改"。
5. **读渲染中台**：`RenderScene::renderFrame` → `DeferredPipeline::renderFrame` → 挑 2–3 个简单 Pass（如 `VelocityPass`、`SsaoPass`）跟一遍 addPass/readTexture/writeTexture。此时你能回答"加一个 Pass 挂哪里"。
6. **按兴趣分支**：红石→`src/world/redstone`；联机→`src/net`+`src/server`；UI→`src/ui`；模型场景→`src/scene`。
7. 改完代码后按 07 篇补测试，按 08 篇验证性能与画质。

**新手不要**一开始就啃 `src/renderer/rhi/vulkan/` 或 NRD 桥接——那是全项目最深的两块，等有具体需求再深入。
