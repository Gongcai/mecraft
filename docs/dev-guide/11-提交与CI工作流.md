## 1. 仓库与分支

- 远端：`origin` → `git@github.com:Gongcai/mecraft.git`。
- 当前主干：本地 `main`（远端跟踪 `origin/main`）。仓库还有历史分支 `PBR`、`dev/rhi-rendering-migration`、`refactor/rhi-vulkan`。
- **注意**：CI workflow 触发分支写的是 `master`，而仓库实际主干是 `main`——当前 push/PR 到 `main` **不会触发 CI**（详见第 6 节，需修复）。

## 2. CI 现状（GitHub Actions）

`.github/workflows/cmake-single-platform.yml`（starter 模板，尚未定制）：

- 触发：`push` / `pull_request` 到 `master`（如上，与 `main` 不一致）。
- 平台：`windows-latest`，Release。
- 步骤：装 CMake 4.1 → vcpkg 装依赖（glfw3/glm/glad/nlohmann-json）→ Configure → Build → `ctest`。
- 覆盖：**仅编译 + 全部 ctest**；未包含：

  - `format-check`（格式化把关）；
  - 契约测试的资源/后端参数（GPU 类契约测试在无 GPU runner 下需显式跳过策略）；
  - 性能基准对比（perf test 未纳入）。

## 3. 提交粒度与消息

格式（详见 08 篇）：`<type>(<scope>): <中文subject>`。

- 一轮工作一个提交（AGENTS.md），粒度以"可独立理解、可独立回滚"为准：
  - 好：`feat(world): 新增落叶粒子` → `fix(light): 修复跨区块光照泄漏` 分两条；
  - 不好：`feat: 各种改动` 一条含世界+渲染+UI。
- 提交内容只含本轮相关文件：源码、测试、文档、有意义的基准更新；**不顺手带入** perf 测试运行产生的噪音 JSON、构建产物。
- 提交前检查：`git status` / `git diff` 确认无多余文件；确认无密钥、绝对路径、临时日志。

## 4. 提交前本地把关

按顺序执行（缺一不可）：

```bash
# 1. 格式化
cmake --build cmake-build-linux-manifest --target format
# 2. 编译（零新增警告）
./build.sh -t mecraft
# 3. 相关测试
ctest --test-dir cmake-build-linux-manifest -R <相关测试> --output-on-failure
# 4. 涉热路径：跑对应 perf 基准并对比 tests/perf_baselines/
ctest --test-dir cmake-build-linux-manifest -R <相关_perf_test>
# 5. 涉渲染/GPU：跑对应契约测试 + 验证系统（10 篇第 5 节）
```

Windows 对应 `build.ps1` + ctest。

## 5. 功能开发工作流

```
1. 从 main 切功能分支：git checkout -b feat/<模块>-<简述>
2. 小步开发，每轮完成即按规范提交（不攒堆）
3. 每轮提交前执行第 4 节把关
4. 联机/玩法功能补权威测试（client_server_authority_test 风格）
5. 渲染/GPU 功能补契约测试
6. 合并回 main 前：git rebase main，重跑全部测试
7. PR（CI 跑通后合入）
```

## 6. CI 覆盖缺口与补强方向

当前 CI 只是"能编译能跑测"，与实际把关要求有明显差距，建议补强（任一项改动需先与仓库维护者确认）：

| 缺口 | 建议 |
| --- | --- |
| 触发分支 `master` ≠ 实际主干 `main` | workflow 的 `branches` 改为 `main` |
| 无格式化把关 | CI 增加 `cmake --build build --target format-check`（需 runner 安装 clang-format 22） |
| 依赖列表与 `CMakeLists.txt` 不一致 | CI 的 vcpkg 安装列表应覆盖项目全部 `find_package`（EnTT/OpenAL/Freetype/glslang/spirv-cross/glfw 等），或改为使用仓库 vcpkg 配置 |
| 无性能回归把关 | 增加手动/定时 job 跑关键 perf test，与 `tests/perf_baselines/` 对比并生成报告 |
| 契约测试 GPU 需求 | 分类测试：无 GPU job 只跑纯逻辑；GPU job（自托管/带 GPU runner）跑 `*_contract_test` + 验证系统 |

**在 CI 补强之前**：`format-check`、perf 基准、契约测试的本地把关是唯一防线，务必按第 4 节执行。
