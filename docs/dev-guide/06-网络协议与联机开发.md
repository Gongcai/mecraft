## 1. 架构总览：两种传输一种协议

```
┌─────────────┐   Packet   ┌─────────────┐
│  GameServer │ ◄────────► │  GameClient │
│  (权威世界)  │  二进制包   │ (渲染/预测)  │
└─────┬───────┘            └─────┬───────┘
      │                          │
      ▼                          ▼
  ITransportEndpoint         ITransportEndpoint
      │                          │
      ├── InProcessTransport（单机，同进程 shared_ptr 直传）
      └── ENetTransport（联机，UDP + ENet 可靠通道）
```

- **协议层**（`src/net/Protocol.h`、`PacketCodec.h`）与传输无关——同一套 `Packet` 结构在两种传输下含义一致（InProcess 额外带 `shared_ptr<Chunk>` 零拷贝载荷）。
- **权威模型**：服务器持有 `World`，是方块/实体/生命值的唯一仲裁者；客户端只有 `ClientWorld` 镜像和本地预测。
- **单机 = 联机**：单机时客户端进程内嵌一个 `GameServer`，通过 `InProcessTransport` 通信；`GameSession::initECS` 里 `svc.world` 只在单机模式绑定（多人客户端为 null，防止客户端直接改世界）。

## 2. 协议分层：Packet / MessageType / Payload

`src/net/Protocol.h:97`：

```cpp
struct Packet {
    PacketChannel channel = PacketChannel::ReliableControl;
    MessageType type = MessageType::ClientHello;
    std::vector<uint8_t> payload;              // 序列化后的消息体
    std::shared_ptr<Chunk> inProcessPayload;   // 仅 InProcess：区块零拷贝直传
    uint64_t traceId = 0;                      // 调试追踪
};
```

布线格式（`PacketCodec#encode`）：

```
[channel:u8] [type:u8] [payloadSize:u32] [payload...]
```

`inProcessPayload` 不参与网络编码（`PacketCodec` 注释明确：仅 payload 字节序列化）。

## 3. 消息类型清单

`MessageType`（`Protocol.h:46`）分两组：

**客户端 → 服务器**：

| 消息 | 用途 | 携带 |
| --- | --- | --- |
| `ClientHello` | 握手 | 协议版本、玩家名 |
| `ClientInput` | 输入意图（每 fixedUpdate 发送一次） | `ClientInputMessage`（按键/朝向/TickId） |
| `ClientReady` | 客户端准备完毕 | — |
| `ClientViewConfig` | 视距/渲染配置 | 视距半径 |

| `ClientChatMessage` / `ClientCommandRequest` | 聊天与命令 | 文本 |

| 消息 | 用途 | 携带 |

## 4. 传输通道（Channel）

`PacketChannel`（`Protocol.h:38`）映射到 ENet 的 4 条通道：

| 通道 | 可靠性 | 用途 |
| --- | --- | --- |
| `ReliableControl` | 可靠有序 | 握手、配置、断线 |
| `ReliableWorld` | 可靠有序 | 区块数据、方块更新、容器状态 |
| `UnreliableState` | 不可靠（最新值优先） | 实体快照、玩家输入 |
| `ReliableChat` | 可靠 | 聊天、命令、系统消息 |

选择准则：

- 可丢失、只关心"最新"的状态 → `UnreliableState`（实体位置每 tick 都发，丢弃旧包影响小）。
- 必须送达且有序的操作 → `ReliableWorld` 或 `ReliableControl`（区块、方块变更）。
- 每次输入只发一次、不可重放 → `ReliableControl`；高频输入则放 `UnreliableState` 并带序列号。

## 5. 编解码：PacketCodec

`src/net/PacketCodec.h` 是**仅有的**序列化入口：

- `encode(packet)` → `std::vector<uint8_t>`；`decode(data, size, out)` → bool。
- 解码失败返回 false（长度不足/载荷越界），调用方丢弃该包并记录计数。
- 具体消息体的序列化（如 `ClientInputMessage`）在 `Protocol.h` 中对应结构体的自定义 `encode`/`decode` 函数（或 `PacketCodec` 内实现），**新增字段必须同时更新编码与解码**，否则线上与内存布局不一致。

## 6. 服务器端：GameServer

`src/server/GameServer.cpp`：

### 6.1 主循环 tick

```
GameServer::tick(worldTickIndex)（GameServer.cpp:51）
 ├─ receiveMessages()               # 处理客户端上行包
 ├─ m_world->tick(worldTickIndex)   # 世界权威模拟（方块刻/光照）
 ├─ m_world->flushInteractiveLighting()
 └─ broadcastSnapshot()             # 广播状态快照与实体
```

- `tick` 由谁调用：单机 = `GameFrameOrchestrator::runFixedUpdate` 里的服务器 tick 循环（`kServerStep = 1/20`，每次最多 4 tick）；联机 = `GameServer` 拥有自己的 tick 线程（`dedicated_server` 主循环按 20Hz 调）。
- `receiveMessages` 是**单 dispatch 点**：`while (tryReceive(packet)) { switch (packet.type) { ... } }`。新增上行消息就在这加 case。

### 6.2 下行发送辅助

- `sendToClient(channel, packet)`：按 channel 发送。
- `broadcastSnapshot()`：构造 `ServerSnapshot` + `EntitySnapshot` 列表，每 tick 发。
- 区块发送在客户端请求触发（`ChunkTicketManager` 决定给谁发哪块，见第 11 节）。

### 6.3 方块交互处理

`handleBlockAction`（`GameServer.cpp:160`）是服务器权威机制的核心：客户端发 `ClientBlockAction`（种类：放置/破坏/交互），服务器校验后直接操作 `World`，然后通过 `BlockUpdateBatch` 广播结果。**注意：服务器不执行任何客户端 ECS 方块交互系统**——那是纯客户端呈现，权威在 `World`。

## 7. 客户端：GameClient

`src/client/GameClient.h`/`.cpp`：

- `receiveMessages()`：与服务器 `receiveMessages` 对称的 dispatch 点（`ServerHello → ChunkData → BlockUpdateBatch → ServerSnapshot → EntitySpawn/Despawn/...`），应用写进 `ClientWorld` 与 `ClientEntityStore`。
- `sendClientInput(snapshot, tickIndex, fixedStep)`：由 `GameFrameOrchestrator::sendClientInput`（`GameFrameOrchestrator.cpp:50`）在每个 fixedUpdate 末尾调用，打包 `ClientInputMessage` 发服务器。
- `sendBlockAction(kind, pos, message)`：方块交互意图（点击右键、破坏）——**只有客户端发意图**，服务器执行。
- `updateWorldAroundLocalPlayer(pos)`：通知服务器更新区块票据中心。
- 初始加载：`isInitialChunkLoadComplete()` / `areSpawnChunksReady()` 控制出生区块就绪后才渲染。

## 8. 单机模式：InProcessTransport 零拷贝路径

- 选择开关：`GameSessionConfig.transportKind = MainGameTransportKind::InProcess / ENet`；`isMultiplayer` 区分。
- `InProcessTransport`（`src/net/InProcessTransport.h`）两端在**同一进程**：`send` 把 `Packet` 塞进对方队列（`tryReceive` 直接取），`Packet.inProcessPayload` 携带 `shared_ptr<Chunk>` 时走零拷贝（不序列化区块数据）。
- 协议层行为完全一致：`GameServer::tick` 的 `receiveMessages` 循环同样适用于 InProcess（只是队列源不同）。
- **单机联机行为一致性**由 `client_server_authority_test` 等测试保障：同样的方块交互在两种传输下结果一致。

## 9. 新增一条消息的完整步骤

以新增"服务器方块动画"消息（`ServerBlockAnimation`）为例：

**① 定义 MessageType**：`Protocol.h` 的 `MessageType` 枚举（服务器 → 客户端组）追加 `ServerBlockAnimation`。**不要在枚举中间插入**——会破坏已有包的类型编号（协议兼容性）。

**② 定义消息结构体**（`Protocol.h`，服务器 → 客户端组）：

```cpp
struct BlockAnimationMessage {
    glm::ivec3 position = glm::ivec3(0);
    uint32_t animationKind = 0;

    bool encode(std::vector<uint8_t>& out) const { /* 追加字段 */ }
    bool decode(const uint8_t* data, size_t size, size_t& offset) { /* 读取字段 */ }
};
```

**③ 实现编解码**：在 `PacketCodec.h`（或消息结构体的 encode/decode）里序列化/反序列化。**新增字段 = 同时改 encode 和 decode**，并保持与已有消息的编码顺序一致。

**④ 服务器发送**：在 `GameServer` 需要触发动画的地方构造消息、`sendToClient(PacketChannel::ReliableWorld, ...)`。

**⑤ 客户端接收**：`GameClient::receiveMessages` 的 switch 加 `case MessageType::ServerBlockAnimation: handleBlockAnimation(packet); break;`，实现 `handleBlockAnimation` 解码并应用（写到 `ClientWorld` 动画状态）。

**⑥ 打包输入**（若该消息依赖客户端意图）：在 `ClientInputMessage` 增加字段并用 `ClientInputActions` 位掩码扩展。

**⑦ 测试**：

- 编解码测试：编码后解码，断言字段一致。
- 权威测试：`client_server_authority_test.cpp` 风格——启动 InProcess 双端，发消息，断言客户端世界变化。

**⑧ 提交**：`feat(net): 新增服务器方块动画消息`。

## 10. 权威服务器与客户端预测

- 客户端不直接改世界；所有方块/实体变更走服务器。
- 本地预测：玩家的移动与方块交互在客户端有瞬时反馈（放置/破坏立刻显示），服务器回复 `BlockUpdateBatch` 修正（`GameServer::tick` 的 `ServerSnapshot` 含 `authoritativePosition` + `ackInputSequence` 供客户端校准）。
- **新玩法功能必须考虑权威一致性**：如果客户端和服务器都改了同一块数据（如耐久），必须由服务器为唯一写者，客户端只显示预测结果。

## 11. 区块同步与票据管理

- `ChunkTicketManager`（`src/server/ChunkTicketManager.h`）：维护每个客户端的加载票据（按视距半径的圆形区域）。
- 客户端 `updateWorldAroundLocalPlayer` → 服务器重算票据 → 未加载区块从 `World` 序列化并通过 `ChunkData` 发送（InProcess 零拷贝）。
- 已卸载区块发 `ChunkUnload`；客户端 `ClientWorld` 释放并同步 `Chunk` 重建。
- 区块数据包含 `revision`（修订号），客户端依据它判断是否替换本地缓存（参考 `ClientWorld::applyChunkData`）。
