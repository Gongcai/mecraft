## 1. 测试体系总览

- **无第三方测试框架**（没有 Catch2/GTest）：每个测试是一个独立的可执行文件，`main` 在测试源码内，退出码 0 = 通过，非 0 = 失败。
- **ctest 统一编排**：`CMakeLists.txt` 里 `add_test` 注册，`ctest` 批量运行并汇报失败。
- **四类测试**：

| 类型 | 命名后缀 | 代表 |
| --- | --- | --- |
| 单元测试 | `*_test.cpp` | `block_state_registry_test.cpp`、`fluid_flow_test.cpp` |
| 集成/权威测试 | `*_test.cpp` | `client_server_authority_test.cpp`（双端联动） |
| 契约测试 | `*_contract_test.cpp` | `gpu_light_contract_test.cpp`、`rhi_render_graph_test.cpp`（渲染特性完整性） |
| 性能基准 | `*_perf_test.cpp` | `meshing_perf_test.cpp`、`light_solver_perf_test.cpp`（产出 JSON 基准） |

## 2. 注册测试：add_mecraft_test

`CMakeLists.txt:985` 提供辅助函数：

```cmake
function(add_mecraft_test TEST_NAME SOURCE_FILE)
    add_executable(${TEST_NAME} ${SOURCE_FILE})
    target_compile_features(${TEST_NAME} PRIVATE cxx_std_17)
    target_link_libraries(${TEST_NAME} PRIVATE mecraft_core)
    mecraft_apply_project_warnings(${TEST_NAME})
    mecraft_apply_msvc_defaults(${TEST_NAME})
    mecraft_disable_rtti(${TEST_NAME})
    mecraft_disable_exceptions(${TEST_NAME})
    mecraft_apply_ipo(${TEST_NAME})
    add_test(NAME ${TEST_NAME} COMMAND ${TEST_NAME})
    set_tests_properties(${TEST_NAME} PROPERTIES WORKING_DIRECTORY "${PROJECT_SOURCE_DIR}")
endfunction()
```

注册示例（`CMakeLists.txt:1010` 附近）：

```cmake
add_mecraft_test(world_flat_test tests/world_flat_test.cpp)
add_mecraft_test(block_state_registry_test tests/block_state_registry_test.cpp)
mecraft_copy_runtime_assets(block_state_registry_test)   # 需要运行时资源（blocks.json 等）
```

要点：

- 链接 `mecraft_core`；`WORKING_DIRECTORY` 固定为项目根目录，所以测试内相对路径应基于项目根。
- **全局禁用 RTTI 与异常**（与主程序一致）——测试里同样禁止 `try/catch`、`dynamic_cast`。
- 需要运行时资源（注册表 JSON、着色器、参考图）时追加 `mecraft_copy_runtime_assets(<target>)`。
- 物理测试例外：`physics_mvp_test` 需要 `MECRAFT_NO_TEXTURES` 宏，单独 `add_executable`。

## 3. 测试文件结构规范

以 `tests/chunk_mesher_test.cpp` 为模板：

```cpp
#include <cstdlib>
#include <iostream>

#include <glm/vec3.hpp>

#include "../src/world/block/BlockStateRegistry.h"
// ... 按需 include 被测模块（相对路径 ../src/...）

namespace {

int fail(const char* message) {           // 统一的失败出口
    std::cerr << "[chunk_mesher_test] FAIL: " << message << '\n';
    return EXIT_FAILURE;
}

// 测试辅助函数（构建世界、生成区块、设置环境）
// ...

} // namespace

int main() {
    // Arrange：准备输入
    // Act：执行被测逻辑
    // Assert：断言，失败即 return fail("英文描述");
    // 所有断言通过后：
    std::cout << "[chunk_mesher_test] PASS\n";
    return EXIT_SUCCESS;
}
```

规范：

- 所有辅助代码放匿名命名空间，`main` 之外不允许任何全局可执行副作用。
- `fail()` 的命名含 `[测试名]` 前缀，便于 ctest 失败时定位。
- 末尾必须输出 `PASS` 并 `return EXIT_SUCCESS`。
- **多场景测试**：一个 main 内顺序执行多个场景（如 `meshing_perf_test` 的 Scenario 1/2），每个场景输出行首带场景标记。

## 4. 断言与失败报告

- 无断言宏；全部显式判断 + `return fail(...)`：

```cpp
if (stateId == INVALID) {
    return fail("torch should expand into dedicated state ids");
}
if (!approxEqual(vertex.y, 1.0f / 128.0f)) {
    return fail("wire container floor vertex should sit at slab height");
}
```

- 浮点比较一律用近似比较（`approxEqual`），禁止 `==` 直接比 float。
- 失败消息必须**描述期望行为而非复述代码**（如"should report facing=north"），让不看代码的人也能理解语义。
- 关键路径的失败建议携带上下文：坐标、索引、状态值。

## 5. 测试分类与选型

**单元测试**——单模块纯逻辑：

- 适合：注册表、序列化器、状态机、网格生成、光照规则、UI 布局。
- 原则：不依赖 GPU/网络/资源文件，确定性输入 → 确定性输出。

**集成/权威测试**——多模块联动：

- `client_server_authority_test.cpp`：构造 `World` + ECS 注册表，走 InProcess 双端收发，断言服务器权威结果落地客户端镜像。写玩法/网络联动必须参考它。
- `redstone_*`、`fluid_flow_test`：块级系统在 `World` 上多次 `tick` 后的状态演化断言。

**契约测试**（`*_contract_test.cpp`）：

- 用途：GPU 特性、渲染管线特性被破坏时立刻报错（例如 RHI 迁移期每个特性都有契约测试守住）。
- 特点：常需要 `MECRAFT_TEST_SOURCE_DIR` 编译宏定位项目根（加载着色器/参考 JSON），需要 GPU 环境，通常带 `--rhi-backend` 参数运行。

**性能基准**（`*_perf_test.cpp`）：

- 见第 7 节。

## 6. 依赖资源与编译宏的测试

两类依赖：

| 依赖 | 处理方式 | 例子 |
| --- | --- | --- |
| 运行时资源（JSON/纹理/着色器） | `mecraft_copy_runtime_assets(<target>)` 复制到测试工作目录 | `block_state_registry_test`（blocks.json） |
| 项目根路径（参考图/材质目录） | `target_compile_definitions(<target> PRIVATE MECRAFT_TEST_SOURCE_DIR="${PROJECT_SOURCE_DIR}")` | `render_feature_contract_test`、`reference_capture_manifest_test` |

规则：

- **资源依赖不可隐式**：测试要么声明需要资源，要么不碰资源；禁止"有资源就测、没有就跳过"的兜底逻辑。
- 测试内读取资源路径一律经 `MECRAFT_TEST_SOURCE_DIR` 拼路径，不要硬编码工作目录。

## 7. 性能测试与基准纪律

机制（参考 `tests/meshing_perf_test.cpp`）：

- 结构：warmup 轮 + measure 轮；输出 `median/avg/p95/min/max` 与 `checksum`（防"结果对但输出被改"）。
- 结果写入 `tests/perf_baselines/<bench>_baseline_<时间戳>.json`，内容含 `benchmark`、`build.config`、`captured_at`、各场景统计。
- 统计一致：median/avg/p95/checksum 命名与 JSON 字段一一对应。

纪律：

- **基准必须可复现**：固定构建配置（Release）、固定线程数、固定输入规模；`build.config` 记录在 JSON 里。
- 变更热路径后，跑对应 perf test 并对比 `perf_baselines/` 中最近基准；单线程场景回归超阈值需要解释（本仓库不强制阈值，但回归必须说明）。
- 性能测试的 JSON 属于**数据产物**：有意义的基线才提交，临时跑出的噪音数据不要混进仓库（当前 git status 里的 `meshing_perf_baseline_*.json` 为本地运行产物，未提交）。
- checksum 防止"规模变了结果还对"的假象——改测试用例规模时同时更新基线。

## 8. 运行测试

```bash
# 构建并运行全部测试
./build.sh --target <某个测试名>   # 单测可执行
ctest --test-dir cmake-build-linux-manifest --output-on-failure
# 只跑某一个
ctest --test-dir cmake-build-linux-manifest -R world_flat_test --output-on-failure
# 契约/GPU 测试通常需要指定后端
ctest --test-dir cmake-build-linux-manifest -R gpu_light_contract_test --output-on-failure
```

Windows 对应 `build.ps1` + `ctest` 同理。

## 9. 新增一个测试的完整步骤

以新增 `falling_block_test`（落沙系统单元测试）为例：

1. **写测试文件** `tests/falling_block_test.cpp`：按第 3 节模板，构造 `World`，放一个沙块，`tick` 若干次，断言沙块落到底。
2. **注册**：`CMakeLists.txt` 测试段追加：

   ```cmake
   add_mecraft_test(falling_block_test tests/falling_block_test.cpp)
   ```

3. **编译运行**：

   ```bash
   ./build.sh --target falling_block_test
   ctest --test-dir cmake-build-linux-manifest -R falling_block_test --output-on-failure
   ```

4. **失败修复原则**：测试红了先查被测代码是否真 bug，禁止在测试里放宽断言"让测试过"（兜底禁止）。
5. **提交**：`test(world): 新增落沙系统单元测试`。

## 10. 注意事项与禁忌

- **禁止 try/catch**：与全局禁用异常一致；失败即 `fail()` 返回退出码。
- **禁止兜底断言**：测试里也不允许"若 A 成立则断言，否则跳过"式逻辑——断言必须无条件成立。
- **确定性**：不使用真随机（如需随机用固定 seed 的确定性生成器）；不依赖系统时间/时区。
- **不写死绝对路径**：只用项目根相对路径与 `MECRAFT_TEST_SOURCE_DIR`。
- **英文注释**：测试代码注释同样遵循全英文、讲清意图。
- **性能测试不进默认回归**：perf test 是手动/CI 专项跑的，避免慢测拖慢日常 ctest。
