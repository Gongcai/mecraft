## 1. 环境要求

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| 编译器 | GCC / Clang（Linux）、MSVC 2022+（Windows） | C++17，注意项目**禁用 RTTI 与异常**（`mecraft_disable_rtti` / `mecraft_disable_exceptions`） |
| CMake | 3.20+ | 强制使用 |
| 生成器 | Ninja（推荐，脚本默认） | 也支持其他生成器，但 `build.sh` / `build.ps1` 固定 `-G Ninja` |
| vcpkg | 任意版本，配 `builtin-baseline` | `vcpkg.json` 已锁定版本基线 |
| Vulkan SDK | 仅当启用 Vulkan 后端时需要 | 现代渲染（NRD/FSR3.1）依赖 Vulkan 1.3 |
| 显卡驱动 | 支持 Vulkan 1.3 | 仅编译 OpenGL 后端则无此要求 |

Linux 下还需要 xcb / xlib 开发包（`vcpkg.json` 中 `vulkan-loader` 已声明 `xcb`、`xlib` features）。

## 2. 依赖获取：vcpkg

依赖清单在根目录 `vcpkg.json`，`builtin-baseline: d87340acc46bdeda386037b38aca30136e667e47` 锁定所有包的版本。

外部包（`find_package` 解析）：

- `entt`、`freetype`、`glfw3`、`glslang`、`glm`、`libvorbis`、`nativefiledialog-extended`、`nlohmann-json`、`openal-soft`、`spirv-cross`、`vulkan`、`vulkan-loader`（linux）、`vulkan-memory-allocator`、`vulkan-validationlayers`

内置源码（`third_party/`，随项目编译，**不通过 vcpkg**）：

- `glad`（OpenGL loader，`mecraft_rhi_gl_loader`）、`enet`、`imgui`、`imguizmo`、`stb`、`cgltf`、`mikktspace`、`nrd`（NRD 4.17.3，`add_subdirectory(third_party/nrd)`）、`fidelityfx_fsr31`（FSR 3.1）

安装方式二选一：

```bash
# 方式 A：全局安装（一次性，推荐）
vcpkg install glfw3 glm nlohmann-json openal-soft libvorbis freetype entt \
  glslang spirv-cross vulkan vulkan-loader vulkan-memory-allocator \
  vulkan-validationlayers nativefiledialog-extended

# 方式 B：由 CMake 按 vcpkg.json 自动安装（manifest 模式）
# 在 build 命令中带 -DCMAKE_TOOLCHAIN_FILE=.../vcpkg.cmake 即可，
# 首次 configure 会自动安装清单中的包（见第 4 节 build.sh 用法）。
```

> 本项目推荐 **manifest 模式**（方式 B）：`vcpkg.json` 是唯一依赖清单，版本由 baseline 锁定，换机器不担心包版本漂移。

## 3. 构建系统全貌

顶层 `CMakeLists.txt` 的布局（共约 1300 行，结构如下）：

```
CMakeLists.txt
├── 0. 项目声明、vcpkg 引导、开关定义（1–130 行）
├── 1. 源码文件列表收集（SRC_* 变量，131–730 行）
│      CORE_SOURCES 聚合 SRC_APP/ENGINE/GAME/WORLD/RENDERER/UI/ECS/...
├── 2. 公共工具函数（131–215 行）
│      mecraft_apply_ipo / mecraft_apply_msvc_defaults /
│      mecraft_apply_project_warnings / mecraft_disable_rtti /
│      mecraft_disable_exceptions / mecraft_copy_runtime_assets
├── 3. 预编译头 mecraft_pch（730–765 行）
├── 4. 依赖查找 + 第三方库目标（216–848 行）
│      mecraft_third_party（imgui/enet/stb/...）
│      mecraft_nrd / mecraft_fidelityfx_fsr31 / mecraft_rhi_gl_loader
├── 5. mecraft_core 静态库（849–930 行）
├── 6. mecraft / mecraft_server 可执行文件（931–980 行）
├── 7. 测试（985–1300 行）
└── 8. Windows 运行时 DLL 部署（1300+ 行）
```

关键认知：

1. **新增源码必须手工登记**：`SRC_*` 变量是**显式列表，不是 GLOB**。在 `src/` 下新建 .cpp 后，需要把路径加进对应 `SRC_*` 列表（详见第 9 节）。
2. **`mecraft_core` 是唯一核心库**：所有功能都编进这一个静态库，`mecraft` 与 `mecraft_server` 都只链接它。测试也通过链接 `mecraft_core` 拿到全部代码。
3. **MECRAFT_DEBUG 宏**：`Debug` 与 `RelWithDebInfo` 配置自动定义 `MECRAFT_DEBUG`（供性能插桩、调试面板、断言使用）；`RelWithDebInfo` 额外定义 `MECRAFT_ENABLE_CONSOLE_OUTPUT`。
4. **MECRAFT_NO_TEXTURES**：`mecraft_server` 与 `physics_mvp_test` 定义此宏，跳过纹理加载（服务器无渲染）。

## 4. Linux 构建

### 4.1 标准流程

```bash
# 克隆与首次构建（默认 Release，目标 mecraft）
git clone git@github.com:Gongcai/mecraft.git
cd mecraft
./build.sh

# 常用变体
./build.sh -t mecraft_server          # 专用服务器
./build.sh -c RelWithDebInfo          # 带调试信息（性能插桩开）
./build.sh -j 32                      # 并行度
./build.sh -- --DMECRAFT_BUILD_TESTS=ON   # 追加 CMake 参数（-- 之后传给 cmake）
./build.sh --configure-only           # 只配置不编译
./build.sh --skip-configure           # 跳过配置直接编译（目录已配好时提速）
./build.sh --vcpkg-root /path/to/vcpkg   # 自定义 vcpkg 路径
```

`build.sh` 全参数：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `-t, --target` | `mecraft` | 要构建的目标 |
| `-b, --build-dir` | `cmake-build-linux-manifest` | 构建目录 |
| `-c, --config` | `Release` | 构建类型 |
| `-j, --jobs` | `nproc` | 并行编译任务数 |
| `--vcpkg-root` | `$HOME/.local/share/vcpkg` | vcpkg 根目录 |
| `--configure-only` | — | 只 configure |
| `--skip-configure` | — | 跳过 configure |
| `--` | — | 之后全部参数透传给 cmake |

### 4.2 测试构建

```bash
# 用单独目录构建全部测试（139 个测试目标，耗时较长）
./build.sh -b cmake-build-linux-tests -- -DMECRAFT_BUILD_TESTS=ON -DMECRAFT_DEFAULT_RHI_BACKEND=OpenGL
cmake --build cmake-build-linux-tests -j "$(nproc)"

# 运行测试
cd cmake-build-linux-tests
ctest --output-on-failure                 # 全部
ctest -R chunk_mesher_test                # 按名字过滤
ctest -R "rhi_core_test|rhi_render_graph_test"
```

> 提示：测试目标有 100+ 个，全量编译较慢。可以先 `cmake --build . -j n` 全编一次，之后增量很快。

### 4.3 常用手动 cmake 命令（绕过脚本）

```bash
cmake -S . -B build-dir -G Ninja \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DCMAKE_TOOLCHAIN_FILE=$HOME/.local/share/vcpkg/scripts/buildsystems/vcpkg.cmake \
  -DMECRAFT_BUILD_TESTS=ON \
  -DMECRAFT_DEFAULT_RHI_BACKEND=Vulkan
cmake --build build-dir -j 16
```

## 5. Windows 构建

### 5.1 脚本方式

```powershell
# 默认：cmake-build-fsr31-relwithdebinfo，目标 mecraft，RelWithDebInfo，测试开
./build.ps1

# 带 Streamline（DLSS 3 Frame Gen，需先准备 SDK 目录 .cache\streamline\sdk-v2.12.0）
./build.ps1 -EnableStreamline -StreamlineRoot ".cache\streamline\sdk-v2.12.0" -StreamlineApplicationId 0

# 只配置
./build.ps1 -ConfigureOnly
```

`build.ps1` 参数：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `-BuildDirectory` | `cmake-build-fsr31-relwithdebinfo` | 构建目录 |
| `-Target` | `mecraft` | 目标 |
| `-Jobs` | `18` | 并行任务数 |
| `-EnableStreamline` | `$false` | 启用 Streamline/DLSS |
| `-StreamlineRoot` | `.cache\streamline\sdk-v2.12.0` | Streamline SDK 路径 |
| `-StreamlineApplicationId` | `0` | NGX 应用 ID |
| `-ConfigureOnly` | — | 只配置 |

脚本会尝试加载 Visual Studio 18 Community 的 DevShell；`$cmake` 硬编码为 `D:\JetBrain\CLion\bin\cmake\win\x64\bin\cmake.exe`，若你的环境不同请直接改脚本或使用 CLion（推荐，CMakeSettings.json 已配好 x64-Debug / x64-Release / x64-RelWithDebInfo 三套）。

### 5.2 CLion / Visual Studio 方式

- `CMakeSettings.json` 提供三套 Ninja 配置，用 VS 的"打开 CMake 项目"即可识别。
- CLion 直接打开仓库根目录，Toolchain 指向 MSVC，CMake 选项按第 6 节开关矩阵填写。

## 6. CMake 开关矩阵

| 开关 | 默认 | 含义 |
| --- | --- | --- |
| `MECRAFT_RHI_BACKEND_OPENGL` | ON | 编译 OpenGL 4.5 RHI 后端 |
| `MECRAFT_RHI_BACKEND_VULKAN` | ON | 编译 Vulkan 1.3 RHI 后端 |
| `MECRAFT_DEFAULT_RHI_BACKEND` | `Vulkan` | 默认后端（`OpenGL` / `Vulkan`），可由 `--rhi-backend` 运行时覆盖 |
| `MECRAFT_ENABLE_NRD` | ON | NVIDIA NRD 降噪（**要求 Vulkan 后端**，否则 configure 直接报错） |
| `MECRAFT_ENABLE_FSR31` | ON | AMD FSR 3.1（要求 Vulkan 后端） |
| `MECRAFT_ENABLE_STREAMLINE` | OFF | NVIDIA Streamline / DLSS 3（仅 Windows + Vulkan，需 SDK 路径） |
| `MECRAFT_BUILD_TESTS` | ON | 构建测试与基准 |
| `MECRAFT_ENABLE_PCH` | ON | 预编译头（加速编译） |
| `MECRAFT_ENABLE_IPO` | ON | LTO/IPO（Release 下生效） |
| `MECRAFT_USE_SOURCE_ASSETS` | OFF | 直接使用源码树 `assets/`（不复制到 build 目录） |
| `MECRAFT_STREAMLINE_ROOT` | "" | Streamline SDK 根目录 |
| `MECRAFT_STREAMLINE_APPLICATION_ID` | "0" | NGX 应用 ID |

典型组合速查：

```bash
# 仅 OpenGL、无 NRD/FSR（最轻量，跑逻辑/测试最快）
-DMECRAFT_RHI_BACKEND_VULKAN=OFF -DMECRAFT_ENABLE_NRD=OFF -DMECRAFT_ENABLE_FSR31=OFF -DMECRAFT_DEFAULT_RHI_BACKEND=OpenGL

# 完整现代渲染（默认即此）
-DMECRAFT_DEFAULT_RHI_BACKEND=Vulkan

# 服务器（无渲染）
./build.sh -t mecraft_server
```

## 8. 多套 build 目录的约定

仓库当前并存多套构建目录，各有用途（见 `.gitignore` 均被忽略，不会提交）：

| 目录 | 用途 |
| --- | --- |
| `cmake-build-linux-manifest` | Linux 日常构建（manifest 模式 vcpkg） |
| `cmake-build-linux-tests-relwithdebinfo` | Linux 全量测试 + 性能基准（RelWithDebInfo，MECRAFT_DEBUG 开） |
| `cmake-build-linux-relwithdebinfo` | Linux 渲染调试 |
| `cmake-build-linux-nrd-off` | Linux 关闭 NRD 的对照构建 |
| `cmake-build-relwithdebinfo` | Windows 侧（旧） |
| `cmake-build-fsr31-relwithdebinfo` | Windows 脚本默认（build.ps1） |

约定：**性能与验证类工作用 RelWithDebInfo 目录**（`MECRAFT_DEBUG` 宏开启，才有性能插桩与诊断面板）；发布用 Release。日常快速编译 `./build.sh`（默认 Release + manifest 目录）即可。

> 注意 `MECRAFT_DEBUG` 依赖构建类型（Debug/RelWithDebInfo 才有），与 `NDEBUG` 行为不完全相同，勿用 `#ifdef NDEBUG` 判断调试路径。

## 9. 新增源码文件时的构建规则

**这是新开发者最容易踩的坑**：`CMakeLists.txt` 不用 GLOB，新建 .cpp/.h 后**必须手动登记**。

步骤：

1. 在对应子目录建文件（如 `src/world/chunk/MyThing.cpp`）。
2. 编辑 `CMakeLists.txt`，找到对应 `SRC_*` 变量（`SRC_WORLD` 等在 300–730 行区间），把新 .cpp 追加进列表：

```cmake
set(SRC_WORLD
    # ... 已有文件 ...
    src/world/chunk/MyThing.cpp        # ← 新文件加在这里
)
```

3. 重新 configure（`./build.sh --configure-only` 或直接 `cmake --build`，Ninja 会在文件列表变化时自动重跑 configure——CMake 会检测 CMakeLists.txt 变化）。

> 头文件不需要登记（由 include 引用），只有 .cpp 需要。

## 10. 常见构建问题排查

### 10.1 vcpkg 相关

| 症状 | 原因与解决 |
| --- | --- |
| `Error: Could not find a valid baseline` / `Missing toolchain file` | vcpkg 未安装或路径不对。确认 `vcpkg_root/scripts/buildsystems/vcpkg.cmake` 存在；用 `--vcpkg-root` 指定 |
| configure 卡在下载/安装包 | 首次需要下载依赖。检查网络；`vcpkg install` 单包安装后重试 |
| 包版本报错与 baseline 不符 | `vcpkg.json` 的 `builtin-baseline` 与你本地 vcpkg 不匹配。`git -C <vcpkg> fetch && git checkout <baseline>` 或升级 vcpkg |
| `VulkanMemoryAllocator` target 找不到 | vcpkg 里 `vulkan-memory-allocator` 未安装或版本旧。`vcpkg install vulkan-memory-allocator` |

### 10.2 编译错误

| 症状 | 原因与解决 |
| --- | --- |
| `error: 'mecraft_core' does not ...` / 新类未定义 | 新 .cpp 没登记进 `SRC_*`（见第 9 节） |
| 大量模板错误出现在 entt/glm 头里 | PCH 依赖顺序问题，`./build.sh` 全量重建（删 build 目录） |
| `MECRAFT_ENABLE_NRD requires the Vulkan RHI backend` | NRD 与 Vulkan 后端强绑定；要么开 Vulkan，要么 `-DMECRAFT_ENABLE_NRD=OFF` |
| `error: 'vkhpp' ...` / Vulkan SDK 缺失 | Linux 需安装 vulkan-sdk；Vulkan 头文件来自 vcpkg `vulkan` 包或 SDK |
| MSVC 编译报 `C4005` 宏重定义 | 通常是 `MECRAFT_DEBUG` 与 `_DEBUG` 混用导致，检查代码里的 `#define` |
| OOM 编译崩溃 | `-j` 减小；PCH 开可显著降内存 |
| `LNK1104 cannot open ... OpenAL32.lib`（Windows） | OpenAL 的 bin 未进 PATH；把 vcpkg 的 `installed/x64-windows/bin` 加 PATH 或用 `windeployqt` 式部署 |

### 10.3 链接错误

| 症状 | 原因与解决 |
| --- | --- |
| `undefined reference to 'xxx'` | 目标源码没链接到 `mecraft_core`（新测试请用 `add_mecraft_test` 宏）；或函数只声明未定义 |
| NRD / FSR 符号缺失 | `MECRAFT_ENABLE_NRD`/`FSR31` 与链接的不一致：configure 后改过开关要重新 configure |

### 10.4 运行时问题

| 症状 | 原因与解决 |
| --- | --- |
| 启动即崩溃 `Failed to create RhiDevice` | 显卡驱动不支持 Vulkan 1.3；`./mecraft --rhi-backend opengl` 或改默认后端 |
| 窗口黑屏但日志正常 | assets 未复制：确认 build 目录下有 `assets/`（`mecraft_runtime_assets` 目标）；或 `-DMECRAFT_USE_SOURCE_ASSETS=ON` |
| 找不到着色器文件 | `MECRAFT_ASSETS_DIR` 编译宏指向 build 内 `assets`；确认资产复制完成 |
| 打开游戏报 `BGM` 相关警告 | 仓库不含 BGM wav（版权），按 `assets/bgm/bgm.json` 自备音频即可（见 .gitignore 说明） |

## 11. 运行时资源与资产

### 11.1 资产目录结构

```
assets/
├── shaders/          # GLSL 着色器（162 个），运行时由 RhiShaderSourceLoader 加载编译
├── textures/         # 方块/UI 纹理
├── models/           # glTF 模型（showcase、实体）
├── audio/            # 音效
├── bgm/              # BGM（json 清单 + 本地 wav，不入库）
├── fonts/            # 字体
├── config/           # keybindings.txt 等运行时配置
├── themes/           # UI 主题（light/dark json）
├── locale/           # 本地化文本
└── validation/       # 7 个验收场景 + 参考图（08 篇详述）
```

### 11.2 资产复制机制

- `MECRAFT_USE_SOURCE_ASSETS=OFF`（默认）：构建时 `mecraft_runtime_assets` 把整个 `assets/` 复制进 build 目录，文件变化会触发重新复制（`CONFIGURE_DEPENDS`）。
- `MECRAFT_USE_SOURCE_ASSETS=ON`：直接使用源码树 assets，编译宏 `MECRAFT_ASSETS_DIR` 指向源码目录，适合迭代开发（不复制）。

### 11.3 新增资产的规则

1. 新资产放 `assets/` 对应子目录即可，**无需改 CMakeLists**（GLOB 复制）。
2. 若新增了**新子目录**且 `CONFIGURE_DEPENDS` 未触发，重新 configure 一次。
3. 着色器新增时，确认 `RhiShaderCompiler` 支持的目标阶段与绑定点约定（详见 05 篇）。
