## 1. 两层规范：工具强制 + 人为约定

| 层 | 手段 | 覆盖 |
| --- | --- | --- |
| 工具强制 | `clang-format 22` + `.clang-format` | 缩进、括号、行宽、指针对齐、空行等布局 |
| 人为约定 | `AGENTS.md` + 本文档 | 注释语言、异常禁用、兜底禁止、提交消息 |

**任何代码先过工具、再过人为规范**。工具能管的交给工具，人为规范聚焦工具管不了的语义与工程纪律。

## 2. 格式化目标：format / format-check

- 入口脚本：`cmake/RunClangFormat.cmake`（`ClangFormat.cmake` 注册两个 custom target，**不依赖构建顺序**）。
- 主版本校验：`find_program(clang-format)` 后强制版本为 `22.x`，其他主版本直接 `FATAL_ERROR`——不同版本布局不一致，必须与 CI 一致。
- 格式化范围：`src/**`、`tests/**`、`main.cpp`、`dedicated_server.cpp`。`third_party/` 与生成文件**刻意排除**。

```bash
# 原地格式化
cmake --build cmake-build-linux-manifest --target format
# 只检查（有差异返回非零）
cmake --build cmake-build-linux-manifest --target format-check
```

Windows 换对应构建目录（见 `docs/code-formatting.md`）。

**CI 语义**：提交前必须保证 `format-check` 通过；`format` 后的差异不要用 `git add -A` 连带无关文件。

## 3. clang-format 关键规则

`.clang-format` 基于 `LLVM`，C++17，核心项：

| 规则 | 值 | 含义 |
| --- | --- | --- |
| `IndentWidth` / `TabWidth` | 4 | 缩进 4 空格，禁用 Tab |
| `ColumnLimit` | 120 | 行长上限 120 |
| `PointerAlignment` | Left | `Type* name`（星号靠左） |
| `AccessModifierOffset` | -4 | class 内访问修饰符回退 4 格 |
| `BreakBeforeBraces` | Attach | 大括号不换行（K&R 风格） |
| `SpaceBeforeParens` | ControlStatements | 控制语句 `if (`，函数调用 `foo(` |
| `SortIncludes` | Never | include 不自动排序（保持手写顺序） |
| `BreakConstructorInitializers` | BeforeColon | 构造初始化列表冒号换行 |
| `AllowShortFunctionsOnASingleLine` | Inline | 短内联函数可单行 |
| `FixNamespaceComments` | true | 命名空间结尾补注释 `} // namespace` |

**两个易踩点**：

- `SortIncludes: Never`——include 顺序靠人工维护：先本项目相对头（`../src/...`），再第三方（glm 等），再标准库，分组空行隔开。
- `PointerAlignment: Left`——写 `BlockID* ptr` 而非 `BlockID *ptr`，review 时以此为准。

## 4. 编译选项纪律

`CMakeLists.txt:169` 的 `mecraft_apply_project_warnings`：

- GCC/Clang：`-Wall -Wextra -pedantic`
- MSVC：`/W4 /WX-`

全局约束（所有 target 统一）：

- `-fno-rtti`（/GR-）：**禁止 RTTI**，禁止 `dynamic_cast`、`typeid`。
- `-fno-exceptions`（/EHs-c-、`_HAS_EXCEPTIONS=0`）：**禁止异常**，见第 6 节。

**纪律**：新代码必须零新增警告（`-Wall -Wextra -pedantic` 下）。编译出现警告 = 提交被拒；不得用 `#pragma` 压制警告掩盖问题（属于兜底行为）。

## 5. 注释规范

**全部英文**，禁止中文注释与不规范缩写（如 `tmp2`、`ret`）。注释必须说明：

- 函数：目的、每个参数意义、返回值含义。
- 算法：思路与关键不变量（例：光照求解器的迭代次序为什么这样）。
- 结构体：字段语义；位掩码/魔法数必须解释。

参考格式（`src/world/World.h` 风格）：

```cpp
/// Attempts to place a block at world position.
/// @param worldX/Z The block coordinate in world space.
/// @param state    Target block state; invalid states are rejected.
/// @return True if the placement succeeded and neighbors were notified.
bool setBlock(int32_t worldX, int32_t worldY, int32_t worldZ, BlockStateId state);
```

注释与代码分开时（如实现细节在 .cpp），头文件声明处给语义、实现处给算法细节。

## 6. C++17 与错误处理规范

- **C++17 强制**：`target_compile_features(... cxx_std_17)` 已应用到所有目标；优先使用现代特性：结构化绑定、`if constexpr`、`std::optional`、`std::variant`、范围 for、`std::string_view`、智能指针。
- **禁用异常**（全局 `-fno-exceptions`）：错误处理只能用：

  - 返回 `std::optional<T>`（可失败但无附加信息）；
  - 返回错误码/`bool` + 出参；
  - 返回值 + `std::error_code` 风格（参考 `PacketCodec::decode` 返回 bool）。

  任何 `try/catch`、`throw` 都是编译错误，**没有例外**。

- **不返回裸指针所有权**：工厂返回 `std::unique_ptr`/`shared_ptr`；跨线程传递用 `shared_ptr`（如 `Packet.inProcessPayload`）。

## 7. 禁止兜底（fallback）规则

**这是本仓库最严格的规则，违反即惩罚**：

- 出现 bug 必须修复根因，禁止"降级处理""回退""如果没有就……"式绕过。
- 禁止的错误形态包括但不限于：

  - 资源加载失败时用占位纹理/占位模型顶替；
  - 特性不可用时静默关闭而不报错；
  - 查询失败时返回默认值假装成功；
  - 解码失败时忽略包而不记录；
  - `#pragma warning(push/pop)` 压制。

- 正确做法：明确报告失败（返回 optional/错误码、日志 + 计数、FATAL 断言），让问题可被发现、可被修复。

## 8. Git 提交规范

格式：`<type>(<scope>): <subject>`，`type`/`scope` 英文，`subject` **中文**。

```text
feat(world): 新增落叶粒子特效
fix(light): 修复跨区块光照泄漏
test(redstone): 新增比较器单元测试
docs(dev-guide): 新增网络协议与联机开发指南
perf(mesh): 优化子区块网格合并
refactor(ecs): 抽取方块交互系统公共基类
```

- type 参考：`feat` / `fix` / `docs` / `test` / `perf` / `refactor` / `build` / `chore`。
- scope 参考：`world` / `renderer` / `net` / `ecs` / `ui` / `audio` / `redstone` / `dev-guide` 等模块名。
- 一轮工作完成即提交（AGENTS.md 要求），避免大而全的堆积提交。
- **只提交相关文件**：性能基准 JSON 等数据产物、本地构建产物不随手带进 commit。

## 9. 提交前检查清单

1. `cmake --build <build-dir> --target format`（或确认 format-check 通过）。
2. 编译零新增警告（-Wall -Wextra -pedantic / /W4）。
3. 相关测试通过：`ctest --test-dir <build-dir> -R <相关测试> --output-on-failure`。
4. 代码无 try/catch、无 dynamic_cast、无兜底逻辑。
5. 注释全英文且描述语义。
6. 按 `<type>(<scope>): <中文subject>` 提交，只暂存本轮的源码/文档改动。
