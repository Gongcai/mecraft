## 1. 核心概念：BlockID / BlockStateId / ItemID

三个 ID 层级，千万别混：

```
ItemID    —— 物品栏里是什么（RuntimeId，items.json 注册顺序决定）
BlockID   —— 方块"定义"是什么（RuntimeId，blocks.json 注册顺序决定，minecraft:air 必须为 0）
BlockStateId —— 一个方块位上的"具体状态"（BlockID + 属性组合编码后的索引）
```

- `using BlockID = RuntimeId;`（`src/world/block/Block.h:26`），`RuntimeId` 来自 `src/engine/registry/IdRegistry.h`，是 `uint16_t` 一类的紧凑索引。
- `BlockStateId`（`src/world/block/BlockStateRegistry.h:19`）内部是**注册表全局索引**（`uint16_t`），用 `BlockStateRegistry::getStateId` 系列函数获取，**禁止手工拼接**。
- 世界存储：`SubChunk` 的 palette 里存的是 `BlockStateId`，不是 `BlockID`——一个方块位可以带任意属性状态（如原木朝向、水的 level）。
- 转换关系：
  - `BlockStateRegistry::getBlockId(stateId)` → BlockID
  - `BlockStateRegistry::getDefaultState(blockId)` → 默认状态
  - `ItemDef::placeBlock` → 物品放置时生成的 BlockID

**常见误区**：拿到 `BlockID` 直接拿去 `World::setBlock`，会丢掉属性状态（永远变成默认状态）。正确姿势是拿 `BlockStateId`。

## 2. 数据驱动：blocks.json 全字段解析

方块定义 99% 在 `assets/config/blocks.json`（3053 行，约 300+ 方块），解析代码在 `BlockRegistry::init`（`src/world/block/Block.cpp:515` 起）。文件是一个 `{"blocks": [...]}` 数组，**数组顺序即 RuntimeId 分配顺序**，`minecraft:air` 必须排第一。

字段总览（斜体为常用）：

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 必填 | `minecraft:stone` 命名空间 ID |
| `drop` | string | `minecraft:air` | 破坏后掉落的**物品** ID（BlockDropTable 映射） |
| *`isSolid`* | bool | true | 是否参与碰撞 |
| *`isTransparent`* | bool | false | 是否透明（渲染层选择 + 光照传导） |
| `isSelectable` | bool | true | 能否被选为目标（空气/水为 false） |
| `allowsFluidCoexistence` | bool | false | 能否与流体共存（如藤蔓） |
| *`affectedByGravity`* | bool | false | 悬空时生成坠落方块实体（沙/砾石） |
| *`renderShape`* | string | "cube" | 网格形状，见第 8 节（cube/cross/torch/water/model/redstone_wire…） |
| `renderLayer` | string | "opaque" | 渲染层（opaque/cutout/transparent） |
| `materialKind` | string | "default" | 材质大类（stone/dirt/grass/wood/leaves/glass/water/ore/emissive…），影响 PBR 参数 |
| `biomeTint` | string | 无 | 群系着色（none/grass/foliage） |
| *`lightLevel`* | int | 0 | 方块自身发光（0–15） |
| `opacity` | int | 15 | 光衰减（0 = 全透，15 = 全挡） |
| `timeToBreak` | int | 1000 | 挖掘耗时（毫秒），附魔/工具修正 |
| `properties` | object | — | 状态属性定义（见第 10 节） |
| `defaultState` | object | — | 默认属性组合 |
| `placementStrategy` | string | "simple" | 放置策略（见第 9 节） |
| `supportRule` | string | — | 支撑规则（如植物需要下方方块） |
| `textures` | object | — | 面纹理映射（`all`/`top`/`bottom`/`side`/`north`…），值为纹理名 |
| `animatedTextures` | object | — | 动画纹理（`water_still` 32帧 6fps 等） |
| `namedTextures` | object | — | 命名纹理引用（供 stateTextureRules 使用） |
| `stateTextures` | object | — | 按属性值的纹理切换（如 `axis: {"x": {...}}`） |
| `randomTick` | object | — | 随机刻行为（生长等） |
| `containerUi` | string | — | 容器 UI 标识（如箱子 → `minecraft:chest`） |
| `interaction` | string | — | 交互行为标识（见第 12 节） |
| `tags` | array | — | 标签（`minecraft:logs` 等），供工具/树生成/合成查询 |
| `pistonPushReaction` | string | "normal" | 活塞推拉反应（normal/block/destroy/push_only） |
| `redstone*` | 多字段 | — | 红石属性（见第 13 节） |
| `analyticLight` | object | — | 分析光（点光代理：color/positionOffset/range/pointEmitterRadius…） |
| `use_on_block` | array | — | 仅物品（见第 3 节） |
| `surfaceFriction` / `surfaceSpeedFactor` / `surfaceDamping` | float | — | 表面物理（行走速度/摩擦） |
| `attachmentFaces` | object | — | 附着面几何（异形方块系统） |

一个完整示例（原木）：

```json
{
  "id": "minecraft:oak_log",
  "drop": "minecraft:oak_log",
  "tags": ["minecraft:logs"],
  "properties": { "axis": ["x", "y", "z"] },
  "defaultState": { "axis": "y" },
  "placementStrategy": "axis_oriented",
  "timeToBreak": 1000,
  "textures": {
    "top": "oak_log_top",
    "bottom": "oak_log_top",
    "side": "oak_log"
  }
}
```

## 3. 数据驱动：items.json 全字段解析

| `icon` | string | 图标来源方块（用于方块类物品的图标渲染） |

## 4. 配方：recipes.json

`assets/config/recipes.json`，加载于 `CraftingSystem::loadRecipes`（`src/crafting/CraftingSystem.cpp:137`）。

**有序配方（3×3 网格）**：

```json
{
  "pattern": ["III", " S ", " S "],      // 字符画，空格=空位
  "key": { "I": "minecraft:iron_ingot", "S": "minecraft:stick" },
  "result": "minecraft:iron_pickaxe",
  "resultCount": 1
}
```

**无序配方（shapeless）**：

```json
{
  "shapeless": true,
  "ingredients": ["minecraft:redstone", "minecraft:iron_ingot"],
  "result": "minecraft:redstone_torch",
  "resultCount": 1
}
```

- `pattern` 行数 ≤ 3、每行 ≤ 3 字符；不要求占满 3×3，会自动对齐匹配。
- `key` 的值也可以是数组（多个备选物品，如"任意木板"）。
- 熔炼配方在 `SmeltingSystem`（`src/crafting/SmeltingSystem.cpp`），格式类似（`input` / `result` / `cookingTime`）。

## 5. 最快路径：新增一个简单方块（9 步）

以新增"平滑石砖"（smooth_stone_bricks）为例：

**第 1 步 · 贴图**：把 `smooth_stone_bricks.png`（16×16）放入 `assets/textures/blocks/`。运行一次构建，确认纹理被 `BlockTextureCatalog` 收录（如果 texture 清单是手动的，则需在 `src/resource/BlockTextureCatalog.cpp` 注册，看第 7 节）。

**第 2 步 · blocks.json 注册**：在 `assets/config/blocks.json` 的 `blocks` 数组**末尾**追加：

```json
{
  "id": "minecraft:smooth_stone_bricks",
  "drop": "minecraft:smooth_stone_bricks",
  "timeToBreak": 1500,
  "textures": { "all": "smooth_stone_bricks" }
}
```

**第 3 步 · items.json 注册**：在 `assets/config/items.json` 追加：

```json
{
  "id": "minecraft:smooth_stone_bricks",
  "icon": "minecraft:smooth_stone_bricks",
  "maxStack": 64,
  "placeBlock": "minecraft:smooth_stone_bricks",
  "renderBlock": "minecraft:smooth_stone_bricks"
}
```

**第 4 步 · 配方**（可选）：`recipes.json` 追加合成表。

**第 5 步 · 生成**（可选）：若要让该方块自然生成，修改 `src/world/gen/TerrainGenerator.cpp` 的矿石/地层生成逻辑。

**第 6 步 · 编译并运行**：

```bash
./build.sh --configure-only
./build.sh
./cmake-build-linux-manifest/mecraft --rhi-backend opengl   # 或直接跑
```

进游戏按 `E` 打开创造模式物品栏找到该方块 → 放置、破坏、掉落验证。

**第 7 步 · 测试**：仿照 `tests/block_state_registry_test.cpp` 写一个方块定义测试（见 07 篇）。

**第 8 步 · 特殊行为**：如果需要交互/红石/支持规则等，跳到对应章节。

**第 9 步 · 提交**：commit 信息格式 `feat(world): 新增平滑石砖方块`。

> **重要**：blocks.json/items.json 的顺序变更会改变 RuntimeId 分配，导致旧存档错位。**新方块只追加在数组末尾，永远不要插入/重排已有项**（见第 15 节）。

## 6. 新增一个纯物品

纯物品（不可放置）与方块物品的区别只在 `placeBlock` / `renderBlock` 为 `minecraft:air`。以"苹果"为模板：

```json
{
  "id": "minecraft:example_gem",
  "iconTexture": "example_gem",
  "maxStack": 64,
  "icon": "minecraft:example_gem",
  "placeBlock": "minecraft:air",
  "renderBlock": "minecraft:air",
  "tags": ["minecraft:gems"]
}
```

如需"对方块右键使用"行为，加 `use_on_block`（见第 3 节）。如需自定义更多行为（如食物），在 ECS 侧注册：物品被使用时的事件 → `ItemUseDispatcher` 或方块交互注册表（第 12 节）。

## 7. 纹理：从贴图到 TextureArray

体素渲染使用**纹理数组（TextureArray）**，不是每方块独立纹理：

```
assets/textures/blocks/*.png
   ↓ BlockTextureCatalog（资产清单，可能硬编码纹理名列表）
   ↓ BlockTextureLibrary 构建 TextureArray（每层 16×16，最多 N 层）
   ↓ BlockTextureColorProvider 群系着色 / BlockIconAtlasBuilder 生成物品栏图标
   ↓ BlockDef.faceTop/faceBottom/... = AnimatedTextureRef{firstLayer, frameCount, fps, tint}
```

关键点：

1. `AnimatedTextureRef.firstLayer` 是纹理数组**层号**，`BlockDef::getFaceLayer(face)` 用它取面纹理（face 编号：0=top 1=bottom 2=front 3=back 4=left 5=right）。
2. `textures: {"all": "name"}` 简写会把六面设为同一纹理；`top/bottom/side` 或 `north/south/east/west/up/down` 可分别指定。
3. 动画纹理：`animatedTextures` 里 `{"texture": "...", "frames": N, "fps": F}`，帧按 TextureArray 连续层排列。
4. 群系着色：`biomeTint: "grass"` 时，`BlockTextureColorProvider` 按群系色板乘色。
5. 方块图标：`ItemDef.icon` 指向一个方块 ID，`BlockIconAtlasBuilder` 用它的面纹理渲染物品栏图标；`iconTexture` 是独立 2D 图标时的备用路径。

**若新纹理在游戏中显示为紫色/黑色**，通常是纹理名未进 `BlockTextureCatalog` 清单——检查 `src/resource/BlockTextureCatalog.cpp` 中的收录表（项目是白名单制而非扫描目录）。

## 9. 放置策略：Placement Strategy

`placementStrategy` 决定"右键放置时生成什么状态"。注册在 `PlacementStrategyRegistry::initBuiltinStrategies`（`src/world/block/Placement.cpp:552`）：

| 策略 | 行为 |
| --- | --- |
| `simple` | 直接放默认状态（默认） |
| `attach_wall` | 附着到四面墙（火把、藤蔓） |
| `horizontal_facing` | 水平朝向 = 玩家朝向（熔炉、箱子） |
| `six_way_facing` | 六向朝向（南瓜灯类） |
| `axis_oriented` | 轴朝向：点地面→y，点侧面→按玩家朝向 x/z（原木） |
| `hopper_facing` | 漏斗专属朝向 |
| `stairs` / `slab` / `vertical_slab` | 楼梯/台阶（自动选择上下/方向） |
| `bed` / `door` / `trapdoor` | 床/门/活板门（成对方块生成） |
| `fence` / `wall` | 围栏/墙（连接逻辑） |
| `redstone_wire_face` / `redstone_logic_unit_face` | 红石线/元件附着面 |

新策略实现：在 `src/world/block/Placement.cpp` 写 `BlockStateId strategyXxx(const PlacementContext&)` 并注册。

## 10. 方块状态属性：properties 与 BlockStateRegistry

**为什么需要属性**：一个"方块定义"可以有很多摆放形态，属性让每个形态有独立 `BlockStateId`，存进 SubChunk palette。

```json
"properties": { "axis": ["x", "y", "z"] },
"defaultState": { "axis": "y" }
```

- 属性名与值都在 `BlockStateRegistry` 做**字符串驻留**（intern），得到 `propKey`/`propValue` 的 `uint16_t` 索引（`src/world/block/BlockStateRegistry.h`）。
- `registerBlockProperties` 为每个 BlockID 建立属性布局，`explodeAllStates` 生成笛卡尔积的**全部状态**（数量爆炸时需注意，如 `facing`×`half`×`open`…）。
- 常用 API：
  - `getDefaultState(blockId)`、`getState(blockId, propKey, propValue)`
  - `withProperty(state, propKey, newValue)` → 只改一个属性的新状态
  - `getPropertyIndex(state, nameIndex)` → 读当前状态某属性值
  - `stateToString(state)` → `minecraft:oak_log[axis=y]` 形式（调试/存档用）
- 特殊方块逻辑（床/门/活塞）直接操作属性：见 `BedBlock.h`、`DoorBlock.h`、`PistonBlock.h`、`FarmlandRules.cpp`。

**性能注意**：`withProperty` 走哈希查找；热路径（每 tick 的方块更新）应缓存 propKey/propValue 索引，不要反复做字符串转换。

## 11. 特殊方块行为（C++ 特例）

数据驱动覆盖不了的逻辑写在 `src/world/block/` 下的 C++ 类，命名 `XxxBlockLogic` 或 `XxxRules`：

| 文件 | 职责 |
| --- | --- |
| `BedBlock.h` | 床：检测 `isBedState`、设定朝向/双格、夜晚睡觉条件 |
| `DoorBlock.h` / `DoorBlock.cpp` | 门：开合、双格联动 |
| `PistonBlock.h` / `PistonBlock.cpp` | 活塞：推动/拉回、方块 `pistonPushReaction` 处理 |
| `FarmlandRules.cpp` | 耕地：湿润、踩踏还原 |
| `BlockCollision.cpp` | 非立方体碰撞盒（台阶/门/栅栏的 AABB 计算） |
| `BlockRandomTick.cpp` | 随机刻分发（生长等） |
| `BlockNeighborUpdateQueue.cpp` | 邻居更新队列（方块被改后通知 6 邻居） |
| `AttachmentFaceGeometry.h` | 附着面几何定义 |
| `PropIndices.cpp` | 常用属性索引的缓存（热路径加速） |

这些类通过 `BlockDef` 的字段（`interaction`、`supportRule`、`redstoneBehavior` 等字符串标识）被系统识别并调用，**不是继承关系**——游戏逻辑查询 `BlockDef` 字段/属性，而不是 virtual 分派。

## 12. 交互系统：interaction 字段与 BlockInteractionRegistry

右键方块的行为注册在 `BlockInteractionRegistry`（`src/game/interaction/BlockInteractionRegistry.h`）：

```
流程：
GameplayState::handleBlockContainerInteraction（GameplayState.cpp:111）
  → game::interaction::hasBlockInteraction(blockId)     // 查注册表
  → game::interaction::applyBlockInteraction(world, pos) // 执行
      多人模式：打包 net::ClientBlockAction(Interact) 发服务器，服务器执行
```

- 注册表把 BlockID（或名称）→ `BlockInteraction`（带优先级）。内置交互见 `BlockInteractionDispatcher.cpp`（门开合、床睡觉、容器打开、红石元件操作等）。
- `containerUi` 字段决定开哪种容器界面（`ContainerStateFactory::create`），UI 定义在 `src/ui/inventory/ContainerUiRegistry.cpp`。
- 加新交互：在 `src/game/interaction/` 写一个 `registerXxxInteraction` 并在初始化时调用；注意**多人必须走服务器执行**，客户端只发意图。

## 13. 红石接入

`BlockDef` 的红石字段（`src/world/block/Block.h:321-336`）：

| 字段 | 说明 |
| --- | --- |

| `isRedstonePowerSource` | 是否主动输出能量 |

## 14. 光照与阴影

- **方块光（体积）**：`lightLevel`（0–15）。`LightSolver` 负责传播；`VoxelLightRegistry`（`src/renderer/lighting/`）把方块光汇总成 GPU 光照网格（`WorldLightGridContract`）。
- **分析光（点光）**：`analyticLight` 字段定义物理点光（火把、熔炉、萤石），进 `ClusteredLighting`（`GpuLight` 缓冲），吃局部阴影（`BlockAnalyticLightShadowPolicy::RasterCached` → `LocalShadowPass`）。注意 `enabledStatePropertyIndex` 可做"仅某状态发光"（如火把的 `lit`）。
- **发光材质**：`materialKind: "emissive"` 或 `derivativeMaterialId` 让方块在 HDR 域发射，配合 RTGI 会被追踪为光源。
- **半透明**：`renderLayer: "transparent"` + `opacity` 控制光照衰减；水/玻璃走特殊渲染路径（`usesWaterRendering`）。

火把是最完整的分析光示例，直接搜 `assets/config/blocks.json` 里的 `minecraft:torch` 抄配置。

## 15. 存档兼容性

**红线规则**：

1. **RuntimeId 由 JSON 数组顺序决定**。新方块/物品只允许 append 到数组末尾；修改已有项的先后顺序 = 全部旧存档错位（方块变成另一块）。
2. `BlockStateId` 是全局索引，`explodeAllStates` 的顺序也影响它——**不要重排 properties 的属性值列表**（可以追加值，但会改变部分 state 索引，谨慎）。
3. 存档里的 palette 存的是 state 索引（MCHK 格式），索引解析依赖注册表内容。方块**定义改名**（如 `minecraft:stone_bricks` → `minecraft:stone_brick`）不迁移旧存档。
4. 删除方块定义=旧存档该位置变未知，存档加载器会 fail-safe 为空气——**不建议删除**，用 `drop: air` 或禁止生成即可。
