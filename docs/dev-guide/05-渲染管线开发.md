## 1. 渲染三层架构

```
┌─────────────────────────────────────────────────────────┐
│ 业务渲染层  src/renderer/passes + renderers + shadow     │
│   GBufferPass / ShadowPass / SsaoPass / DeferredLighting │
│   Pass 之间通过 RenderGraph 声明依赖，不直接互调          │
├─────────────────────────────────────────────────────────┤
│ 核心中台    src/renderer/core                           │
│   RenderScene（帧入口）→ DeferredPipeline/ForwardPipeline│
│   （RenderGraph 装配）→ GlobalBindlessSet / GpuScene     │
├─────────────────────────────────────────────────────────┤
│ RHI 层      src/renderer/rhi                           │
│   RhiDevice / RhiCommandList / RhiResources / RhiDescriptor
│   └── Vulkan 1.3（VkRhiDevice）│OpenGL 4.5（GlRhiDevice）│
└─────────────────────────────────────────────────────────┘
```

**铁律**：业务渲染层只能通过 `RhiDevice`/`RhiCommandList`/RenderGraph 访问 GPU；不得直接调用 `vk*` / `gl*`。后端特有代码（`VkRhiInternal.h` 等）封闭在 `rhi/vulkan/` 内。违反此规则 = 双后端直接崩。

## 2. RHI 对象模型

`src/renderer/rhi/` 下按 Vulkan 语义建模的完整资源体系：

| 对象 | 头文件 | 对应 Vulkan | 说明 |
| --- | --- | --- | --- |
| `RhiDevice` | `RhiDevice.h` | VkDevice + 实例 + 队列 | 资源创建/销毁总入口，带 `capabilities()` 能力查询 |
| `RhiCommandList` | `RhiCommandList.h` | VkCommandBuffer | 命令录制：beginRendering / setPipeline / draw / dispatch / barriers |
| `RhiCommandListPool` | `RhiCommandListPool.h` | VkCommandPool | 每帧命令列表复用池 |
| `RhiBuffer` / `RhiTexture` | `RhiResources.h` | VkBuffer / VkImage | 显存资源（desc 描述格式/大小/用途） |
| `RhiSampler` | `RhiResources.h` | VkSampler | 采样器 |
| `RhiBindGroup` / `RhiBindGroupLayout` | `RhiDescriptor.h` | VkDescriptorSet/Layout | 描述符组（绑定模型类似 WebGPU/wgpu） |
| `RhiPipeline` / `RhiPipelineLayout` | `RhiPipeline.h` | VkPipeline | 图形/计算管线 |
| `RhiShader` | `RhiPipeline.h` | VkShaderModule | 着色器模块 |
| `RhiSwapchain` | `RhiSwapchain.h` | VkSwapchainKHR | 交换链 |
| `RhiGrowableBuffer` | `RhiGrowableBuffer.h` | — | 自动增长的设备缓冲（如 GpuScene 表） |
| 加速结构 | `SceneBlasResource.h` / `SceneTlasCache.h` / `StaticMeshBlasCache.h` | VkAccelerationStructure | 光追 BVH |

所有 handle 都是 `{index, generation}` 带代际的句柄（`RhiHandles.h`），防止悬垂引用。资源创建返回句柄，检查 `.isValid()`；销毁走 `rhiDevice.destroy*`。**句柄是值类型，可自由拷贝**。

典型管线创建流程（见 `VelocityPass::ensureRhiPipeline`，`VelocityPass.cpp:127`）：

```
loadShaderSource(vert) + loadShaderSource(frag)
  → device.createShader ×2
  → device.createSampler
  → device.createBindGroupLayout（声明 binding 类型与 stage）
  → device.createPipelineLayout（bindGroupLayouts + pushConstantBytes）
  → device.createGraphicsPipeline（shader + layout + raster + depthStencil + colorFormats + blend）
  → device.createBindGroup（把 textureView+sampler 绑到 layout 的 binding 上）
```

## 3. RenderGraph 工作流

`src/renderer/rhi/RhiRenderGraph.h` 是渲染正确性的基石：**自动推导同步与资源生命周期**。

### 3.1 核心 API

```cpp
auto& graph = m_renderGraph;
graph.reset();                                   // 每帧重置

// 导入既有资源（GPU 创建的、帧间复用的目标/历史缓冲）
RgTextureHandle depth = graph.importTexture({name, textureHandle, desc, ...});
// 创建转瞬资源（帧内临时，生命周期自动管理 + 内存别名）
RgTextureHandle ssgi = graph.createTexture({"SSGI", desc, finalState});

// 添加 Pass：声明依赖 + 读写 + 执行体
RenderGraphPassBuilder pass = graph.addPass({"My.Pass", RgPassType::Graphics, RhiQueueType::Graphics});
pass.dependsOn(prevTail)                          // 显式排序（可选）
    .readTexture(depth, RhiResourceState::DepthRead)
    .writeTexture(ssgi, RhiResourceState::RenderTarget)
    .setExecute([&](RgPassContext& p) {           // 执行体：录制命令
        return myPass->execute(p.commandList(), ctx, settings, targets);
    });
RgPassHandle graphTail = pass.handle();           // 链式尾指针

// 编译 + 执行（自动生成 barriers、提交批次、GPU 计时）
const RgCompileResult compiled = graph.compile();
const RgExecuteResult executed = graph.execute(*rhiDevice, *commandListPool);
```

### 3.2 关键机制

| 机制 | 说明 |
| --- | --- |
| **依赖推导** | 同一资源前一个 writer → 后一个 reader/writer 自动产生依赖与 barrier，无需手动插 barrier |
| **`dependsOn`** | 无资源依赖但要保证顺序时（如"所有清屏 Pass 先跑"）显式声明 |
| **转瞬资源** | `createTexture/createBuffer` 的生命周期由 graph 计算（firstPass→lastPass），帧末释放；支持**内存别名**（`setTextureAliasingEnabled`，寿命不重叠的转瞬共享内存页） |
| **队列分离** | `RhiQueueType::Graphics/Compute/Transfer`；async compute（SSAO/Cloud）会自动排到独立 compute 队列并插入信号量依赖 |
| **多批次提交** | 每 8 个 pass 一批（`kRgMaxPassesPerSubmissionBatch`），批间按 token 同步 |
| **GPU 计时** | 每 pass 自动插入 timestamp，`pollTimings()` 非阻塞取回 `RgTimingSnapshot` |
| **线程安全录制** | Pass 声明 `threadSafeRecord: true` 后可放到工作线程录制（Vulkan 后端） |

### 3.3 资源状态

`RhiResourceState` 枚举（`RhiTypes.h`）是资源"当前用途"：`ShaderRead / RenderTarget / DepthWrite / DepthRead / StorageImage / StorageBuffer / Present / TransferSrc / TransferDst / Undefined`。**写一个资源时声明的 state 必须与实际 GPU 用法一致**（写 RenderTarget 却声明 ShaderRead → 驱动错误）。这正是契约测试重点覆盖的部分。

## 4. Pass 的两种形态

项目里并存两种 Pass 编写风格，**新代码必须用 RenderGraph 形态**：

### 4.1 旧式（直接执行，不走 graph）

```cpp
class VelocityPass {
public:
    bool execute(RhiCommandList& cmd, const FrameContext& ctx, const RenderSettings& settings,
                 DeferredRenderTargets& targets);
};
```

- 由 Pipeline 手动调 `execute`，同步/生命周期全靠 Pipeline 手写。
- 仅历史遗留 Pass（`VelocityPass` 等）还这样写，正在被 graph 化。

### 4.2 RenderGraph 形态（新标准）

```cpp
class HiZPass {
public:
    RgPassHandle addGraphPasses(RenderGraph& graph, const FrameContext& ctx, DeferredRenderTargets& targets,
                                const GraphResources& resources, const RgPassHandle dependency);
};
```

- Pass 自己用 `graph.addPass` 声明依赖与执行体，返回 graphTail。
- 例子：`SkyIblPass::addGraphPasses`、`HiZPass::addGraphPasses`（DeferredPipeline.cpp:1709、1734）。
- **对照阅读**：`DeferredPipeline::executeFrameGraph`（`DeferredPipeline.cpp:902`）是最完整的 RenderGraph 装配范例（约 2000 行），覆盖了条件 Pass、async compute、外部几何、NRD、时域历史、debug 视图切换等全部模式。

## 5. Pass 生命周期：init / execute / shutdown

`src/renderer/passes/RenderPass.h` 定义 `IPass` 基类：

```cpp
class IPass {
public:
    virtual ~IPass() = default;
    virtual void init(ResourceMgr& resourceMgr) = 0;      // 加载资源/构建非帧相关状态
    virtual void shutdown() = 0;                          // 释放 RHI 资源
    virtual bool execute(RhiCommandList& cmd, const FrameContext& ctx,
                         const RenderSettings& settings) = 0;
};
```

约定（见 VelocityPass 的完整示例）：

1. `init`：只做轻量准备；GPU 资源用**惰性创建**（`ensureRhiPipeline` 风格——首次执行时才创建，因为 `RhiDevice` 在 init 后才有）。
2. `execute`：先 `ensure*` 全部资源与 bind group，任何一步失败返回 `false`（**不要 try/catch，返回错误码**）。
3. 资源在 `m_rhiDevice` 变化时重建（`m_rhiDevice != &rhiDevice → destroyRhiResources()`），支持多设备/后端切换。
4. `shutdown`：全部 `destroy*`，句柄清零，`m_rhiDevice = nullptr`。
5. bind group 依赖 textureView 句柄：**句柄变了要重建 bind group**（`VelocityPass::ensureRhiBindGroup` 里 `sameTextureView` 比较）。

## 6. 着色器系统

### 6.1 加载与编译

- 源码目录：`assets/shaders/`（218 个文件，GLSL）。
- 加载：`renderer::rhi::loadShaderSource("assets/shaders/xxx.frag")` → `std::optional<std::string>`（`RhiShaderSourceLoader.h`）。
- 编译：`compileShaderToSpirv(desc, backend, ...)`（`RhiShaderCompiler.h`）——glslang 编译 GLSL → SPIR-V，spirv-cross 回译生成 OpenGL 后端需要的 GLSL；两后端共用同一份 shader 源。
- 运行时：`device.createShader({debugName, stage, source, size})`。

### 6.2 命名与阶段约定

- 后缀约定：`.vert` / `.frag` / `.comp` / `.glsl`（glsl 是被 include 的公共片段）。
- 公共片段按功能拆分：`cluster_lighting.glsl`、`gbuffer_contract.glsl`、`derivative_brdf.glsl`、`cloud_density.glsl` 等，通过 `#include` 进 shader。
- **GPU 数据布局以 contracts 为准**（第 8 节），shader 里对应 `*_contract.glsl` 的 `#include`。

### 6.3 修改着色器的流程

1. 改 `assets/shaders/xxx.frag`（运行时加载，无需重编译 C++）。
2. 涉及布局变更 → 改对应 contract + shader 里的 contract include（两边必须同步，契约测试会验证）。
3. `RhiShaderCompiler` 有缓存；调试期建议 `--rhi-debug-output` 开启看编译错误输出。

## 7. 帧资源：RenderTargets 与 FrameContext

### 7.1 DeferredRenderTargets（`src/renderer/targets/`）

GBuffer 全套目标（albedo / normalAo / voxelLight / material / materialAux / f0Metallic / objectMaterialId / depth / perObjectVelocity / velocity）+ 后处理链目标（sceneResolved / ssgi* / cloud / reflection / water* / transparencyMask / reactiveMask…）。方法名 = 资源名：`albedoTextureViewHandle()`、`depthTextureViewHandle()` 等。尺寸由 `ensureSize(width, height, shadowRes)` 管理，重建后 `consumeRebuiltFlag()` 让 Pipeline 清历史。

### 7.2 FrameContext（`src/renderer/core/FrameContext.h:152`）

每帧构造一次的**只读数据包**，所有 Pass 共享：

```
相机：camera / prevCamera（含 viewProj 系列）
时域：frameIndex / deltaTime / jitter / previousJitter / velocityClipToPrevClip /
      skyVelocityClipToPrevClip / temporalResetReasons / preExposure
输出：swapchain* / sceneCapture* 句柄与格式
环境：skyColors / skyIlluminance / weather / fog / volumetric / cloud / atmosphere
共享：shared（RenderResourceHub 指针）/ worldView / dayNightSystem / weatherSystem
```

**新 Pass 需要新数据 → 先加进 FrameContext**（`buildFrameContext` 在 `RenderScene.cpp:1241` 填充），不要在 Pass 里绕道拿全局对象。

## 8. GPU 数据契约（Contracts）

`src/renderer/contracts/` 定义 CPU↔GPU 的**数据结构、单位、枚举语义与版本号**，并有配套测试锁定布局。这是本项目渲染正确性的核心方法论：

| 契约 | 内容 |
| --- | --- |
| `GpuLightContract` | 灯光结构（`GpuLightType`、强度单位 Lux/Lumen/Candela、阴影策略、贡献通道） |
| `GpuMaterialContract` | PBR 材质结构（roughness / f0 / emission / subsurface…） |
| `GpuSceneContract` | GPU 场景表（材质/网格/变换槽位布局、Dirty Span） |
| `ClusteredLightingContract` | 集群灯光格子与计数 |
| `RtgiNrdSignalContract` | RTGI 输出信号（radiance / moments / 运动向量）与 NRD 输入布局 |
| `RtgiSamplingContract` | 射线采样参数（偏移、接缝修复） |
| `TemporalFrameContract` | 时域帧契约（尺寸/曝光/帧索引） |
| `TemporalReprojectionContract` | 重投影同伦变换 |
| `LocalShadowContract` / `ReflectionProbeContract` | 局部阴影/反射探针数据 |
| `TerrainRayTracingContract` / `StaticMeshRayTracingContract` / `TerrainMaterialSamplingContract` | 光追地形/模型采样 |
| `WorldLightGridContract` | 体素方块光网格 |
| `SceneIdentityContract` | 场景身份（版本 + 内容哈希） |
| `ContentHashContract` | 内容哈希工具（验证用） |

**契约开发流程**：
1. 在 contract 头文件定义结构 + 版本号 + 语义枚举 + 序列化/哈希。
2. shader 侧 include 对应 `*_contract.glsl`（数据布局 mirror）。
3. 写契约测试（`tests/*_contract_test.cpp` + `tests/shaders/*.comp`）验证 CPU 结构与 GPU 结构字节级一致（`gpu_light_contract_test`、`rtgi_nrd_signal_contract_test` 等是范例）。
4. 改动契约 = 改版本号，旧参考图/旧存档不兼容时走验收流程（08 篇）。

## 9. Bindless 与 GPU Scene

### 9.1 GlobalBindlessSet（`src/renderer/core/GlobalBindlessSet.h`）

全局 Bindless 描述符堆（Vulkan 的 descriptor indexing）：
- 统一槽位：2D 纹理、Cube 纹理、Sampler、Storage Buffer。
- `BindlessDescriptorSlotAllocator` 分配槽位，支持"代际保护"（槽位复用后旧代际写入无效）。
- GPU 侧通过整数索引访问（`SET_BINDLESS_TEXTURE(i)` 之类）。

### 9.2 GpuSceneBufferSet（`src/renderer/core/GpuSceneBufferSet.h`）

GPU 只读场景表：材质表、网格表、变换表。CPU 侧每次修改记录 Dirty Span，帧内连续上传（`uploadDirty`），避免逐对象更新。体素地形材质与模型场景共用（`GpuMaterialContract`）。

接入新数据源：往对应表添加条目 → 标记 dirty → 让 GPU 侧消费表索引。参考 `GpuSceneBufferSet` 的 API 与 `TerrainMaterialSamplingContract`。

## 10. 新增一个 Pass 的完整步骤

以新增"屏幕空间描边调试 Pass"为例（输出到一张新转瞬纹理）：

**① 新建 Pass 类**（`src/renderer/passes/MyOutlinePass.h/.cpp`）：

```cpp
// .h
class MyOutlinePass {
public:
    void init(ResourceMgr& resourceMgr);
    void shutdown();
    RgPassHandle addGraphPasses(RenderGraph& graph, const FrameContext& ctx, DeferredRenderTargets& targets,
                                const RgPassHandle dependency);
private:
    // ensure* + destroy* 全套（照抄 VelocityPass 的资源管理骨架）
};
```

**② 实现 execute**（核心部分）：

```cpp
bool MyOutlinePass::execute(RhiCommandList& cmd, const FrameContext& ctx, DeferredRenderTargets& targets) {
    if (!ensureRhiPipeline(cmd.device()) || !ensureRhiBindGroup(cmd.device(), targets.depthTextureViewHandle())) {
        return false;
    }
    RhiColorAttachment attachment;
    attachment.view = targets.myOutlineTextureViewHandle();
    attachment.loadOp = RhiLoadOp::Clear;
    attachment.storeOp = RhiStoreOp::Store;
    RhiRenderingInfo info;
    info.debugName = "MyOutline";
    info.renderArea = {0, 0, (uint32_t)targets.width(), (uint32_t)targets.height()};
    info.colorAttachments = &attachment;
    info.colorAttachmentCount = 1;
    cmd.beginRendering(info);
    cmd.setGraphicsPipeline(m_pipeline);
    cmd.setBindGroup(0, m_bindGroup);
    cmd.pushConstants(&constants, sizeof(constants), rhiFlag(RhiShaderStage::Fragment));
    cmd.draw(3, 1, 0, 0);
    cmd.endRendering();
    return true;
}
```

**③ 挂进 DeferredPipeline**：

- 在 `DeferredPipeline::init` 里 `m_myOutlinePass = std::make_unique<MyOutlinePass>(); m_myOutlinePass->init(*m_resourceMgr);`
- 在 `executeFrameGraph` 里（找到合适的位置，如 GBuffer 之后）：

```cpp
if (m_myOutlinePass != nullptr) {
    const RgPassHandle outlineHandle = m_myOutlinePass->addGraphPasses(m_renderGraph, ctx, targets, graphTail);
    if (!outlineHandle.isValid()) { return failGraphSetup(); }
    graphTail = outlineHandle;
}
```

**④ 目标纹理**：如果输出要保留（而非转瞬），加到 `DeferredRenderTargets`（建纹理、view、销毁、`ensureSize` 同步改尺寸）；否则用 `graph.createTexture` 转瞬资源即可。

**⑤ 着色器**：`assets/shaders/my_outline.frag`。

**⑥ 注册到 CMakeLists**：`src/renderer/passes/MyOutlinePass.cpp` 加进 `SRC_RENDERER` 列表（01 篇第 9 节）。

**⑦ 设置开关**（可选）：加进 `RenderSettings`（`src/renderer/core/RenderSettings.h`）+ 调试面板（`src/ui/Dashboard.cpp`）。

**⑧ 契约/测试**：若输出参与后续消费，写契约测试；纯调试 Pass 至少跑 `rhi_render_graph_test` 确认不破坏图编译。

**⑨ 验证**：`./build.sh --configure-only && ./build.sh` → 运行 → F3 面板看新 Pass 的 GPU 计时与诊断视图。

## 11. 双后端注意事项（Vulkan vs OpenGL）

| 维度 | 说明 |
| --- | --- |
| 后端选择 | 启动参数 `--rhi-backend opengl|vulkan` 或 `MECRAFT_DEFAULT_RHI_BACKEND` |
| 能力差异 | 用 `rhiDevice.capabilities()` 查询（`accelerationStructure` / `rayQuery` / `dedicatedComputeQueue` / `storageImageExtendedFormats` / `textureAliasing`），**不要硬编码假设** |
| 条件编译 | 后端无关代码一律用能力查询；`MECRAFT_ENABLE_NRD/FSR31/STREAMLINE` 才是编译开关 |
| 异步计算 | 只有 Vulkan 支持（`asyncComputeEnabled` 门控） |
| 坐标 | 捕获纹理 origin 不同（`TextureCaptureOrigin::TopLeft vs BottomLeft`），截图代码里有分支 |
| 窗口 vs 帧缓冲 | OpenGL 可能没有独立 UI target；`PresentationController` 已抽象 |
| 双后端验证 | 每次大改动跑一次 OpenGL 后端 + 一次 Vulkan 后端（`--rhi-backend` 切换），参考图验收矩阵见 08 篇 |

**调试技巧**：`MECRAFT_DEBUG`（RelWithDebInfo 构建）+ `--rhi-debug-output` 开验证层；F3 面板可查看每个 pass 的 CPU/GPU 时间、Bindless 占用、TLAS 状态。

## 13. 性能准则

1. **转瞬资源优于持久资源**：帧内临时中间缓冲用 `graph.createTexture`，让别名分配器合并内存。
2. **避免每帧重创建 pipeline/bind group**：全部惰性创建 + 句柄缓存（`ensure*` 模式），bind group 只在 view 变化时重建。
3. **CPU 侧不要在 execute 回调里做重计算**：回调每帧录制命令，只做状态组装；场景数据（灯光、实体网格）在 `PresentationBuilder` 阶段准备好。
4. **async compute 是免费午餐**（Vulkan）：SSAO/Cloud 已示范，新 compute pass 也走 `RhiQueueType::Compute` + 能力门控。
5. **资源状态声明要克制**：多余的 barrier 依赖会拖垮帧时间；宁可少声明（图会自动合并相邻访问）。
6. **GPU 计时是硬要求**：新 Pass 默认被 graph 计时；接入 `RenderDebugService` 后 Dashboard 自动可见。
