# Mecraft 渲染系统研究报告

> 本报告基于对 `d:\project\mecraft` 项目源码的完整通读与交叉验证，覆盖 `src/renderer`、`src/world`、`src/resource`、`src/game`、`src/engine`、`assets/shaders`、`DerivativeMain` 等目录的全部相关源文件。所有引用的类名、函数名、文件路径均来自源码。

## 一、总体概述

Mecraft 是一个使用 C++17 编写的 Minecraft 风格体素引擎，渲染后端为 **OpenGL 4.x (Desktop Core Profile)**，通过 `glad` 加载 GL 函数，使用 `GLFW` 创建窗口与上下文。引擎 ECS 基于 `entt`。

渲染系统的核心特征：

- **双管线架构**：`ForwardPipeline`（Vanilla 兼容）与 `DeferredPipeline`（完整 PBR 管线），通过 `RenderPipeline` 抽象接口统一调度，运行时可切换。
- **混合延迟渲染**：GBuffer（5-MRT）→ 延迟光照 → SSAO → SSR → 体积雾 → 体积云 → 场景合成 → TAA → 运动模糊 → 景深 → 后处理。
- **算法来源**：渲染管线的光照、阴影、BRDF、大气、色调映射等算法移植自 **DerivativeMain** 光影包（Iris/OptiFine 格式），相关版权归原作者所有。`assets/shaders/` 下以 `derivative_` 前缀命名的 GLSL include 文件即移植产物。
- **现代 GPU 特性**：Multi-Draw Indirect (MDI)、3D 纹理大气 LUT、Compute Shader、PBO 异步回读、纹理视图（`glTextureView`）、DSA 直接状态访问。
- **异步管线**：区块生成、光照求解、网格化、存档均通过 `ThreadPool` 异步执行，主线程仅做调度与 GPU 提交。

## 三、核心调度组件

### 3.1 RenderScene — 渲染场景入口

**文件**：`src/renderer/core/RenderScene.h` / `.cpp`

`RenderScene` 是渲染管线的顶层调度器，由 `GameplayRenderRuntime` 持有。它对外暴露两个主入口：

- `renderFrame(worldView, camera, window, target, break, dayNight, weather)` — 底层渲染入口，构建 `FrameContext` 并交给当前激活的管线。
- `renderGameplayFrame(RenderGameplayFrameRequest&)` — 完整游戏帧渲染，包含天气、第一人称手持物品、后处理、FSR 升采样等。

关键职责：

1. **管线切换**：`setPipelineMode(PipelineMode)` 关闭当前管线 → 切换 `m_activePipeline` 指针 → 在共享资源就绪时调用 `init()` → 调用 `invalidateFrameHistory()` 清除时域历史帧。
2. **构建帧上下文**：`buildFrameContext()` 从世界状态构建统一的 `FrameContext`，包含相机、天空颜色、天气、雾、体积、云、大气等数据。所有 Pass 通过 `FrameContext` 获取帧数据，无全局状态访问。
3. **TAA 抖动计算**：在 `buildFrameContext()` 中复现 DerivativeMain `shaders.properties` 中的抖动公式：
   ```cpp
   const float frameX = glm::fract(frameCounter / 1.3247179572f + 0.5f) * 2.0f - 1.0f;
   const float frameY = glm::fract(frameCounter / 1.7548776662f + 0.5f) * 2.0f - 1.0f;
   ```
4. **资源连接**：`setupResources()` 接收 `WorldRenderBuffer`、`DeferredRenderTargets`、`TerrainRenderer`、`GameplaySkyRenderer`、`ShadowRenderer` 等共享资源，填充 `SharedRenderResources` 结构传递给管线。

### 3.2 RenderPipeline — 管线抽象接口

**文件**：`src/renderer/core/RenderPipeline.h`

```cpp
class RenderPipeline {
public:
    virtual void init(SharedRenderResources& shared) = 0;
    virtual void shutdown() = 0;
    virtual FrameOutput renderFrame(const FrameContext& ctx, const RenderSettings& settings) = 0;
    virtual const char* name() const = 0;
    virtual bool supportsDeferred() const = 0;
    virtual bool supportsDebugView() const = 0;
};
```

两个实现：`ForwardPipeline` 与 `DeferredPipeline`，均位于 `src/renderer/core/`。

### 3.3 FrameContext — 单帧数据源

**文件**：`src/renderer/core/FrameContext.h`

`FrameContext` 是无全局状态的帧数据载体，每帧由 `RenderScene::buildFrameContext()` 构建，包含：

- `CameraData` — 当前帧 + 前一帧相机矩阵（含 TAA jitter 的 `jitteredViewProj`/`jitteredInvViewProj`）
- `SkyColorsData` / `SkyIlluminanceData` — 天空颜色与大气辐照度
- `WeatherData` / `FogData` / `VolumetricData` / `CloudData` / `AtmosphereData`
- `SharedRenderResources*` — 共享资源指针
- `IWorldView*` — 只读世界视图
- `RenderDebugService*` — 调试服务

### 3.4 RenderResourceHub — GPU 资源集线器

**文件**：`src/renderer/core/RenderResourceHub.h`

这是旧版 `Renderer` 类演化而来的资源持有者，拥有所有重量级 GPU 资源：`WorldRenderBuffer`、`TerrainRenderer`、`TerrainRenderCache`、`DeferredRenderTargets`、`GameplaySkyRenderer`、`shadow::ShadowRenderer`、`ChunkMeshingService`。同时管理雾、大气、体积雾、云等设置子结构。这些设置结构体的常量名直接对应 DerivativeMain 中的常量（如 `VolumetricSettings::fogCenterHeight = 63.0f` 对应 DerivativeMain 的 `SEA_LEVEL`，`CloudSettings::height = 1000.0f` 对应 `CLOUD_CUMULUS_CLEAR_ALTITUDE`）。

## 四、渲染管线详解

### 4.1 DeferredPipeline — 延迟渲染管线（主路径）

**文件**：`src/renderer/core/DeferredPipeline.h` / `.cpp`

`DeferredPipeline` 拥有 15 个渲染通道，`renderFrame()` 中的完整执行顺序如下：

| 序号 | Pass | 说明 |
|------|------|------|
| 1 | `SkyCapturePass` | 等距柱状天空辐照度捕获（IBL），256×514 equirectangular |
| 2 | `GBufferPass`（地形） | 地形 GBuffer，通过 `TerrainRenderer` 渲染不透明 + 收集 cutout/transparent |
| 3 | `GBufferPass`（实体/掉落/下落方块） | 实体、掉落物、下落方块写入 GBuffer |
| 4 | `VelocityPass` | 速度缓冲（TAA/运动模糊用） |
| 5 | `ShadowPass` | CSM 4 级联阴影贴图 + PCSS |
| 6 | `SsaoPass` | SSAO 4 阶段（base→filter→upsample→temporal） |
| 7 | `DeferredLightingPass` | 从 GBuffer 计算全场景 PBR 光照 |
| 8 | `ReflectionPass` | SSR 3 阶段（probe→filter→temporal） |
| 9 | `CloudPass` | 光线步进体积云 + 时间重投影 |
| 10 | `SceneCompositePass` | 合成光照/反射/云/大气到 HDR 场景 |
| 11 | `WaterCompositePass`（pre-TAA） | 水面延迟着色合成 |
| 12 | 通用透明物 | 透明地形合成 |
| 13 | 粒子 | 粒子渲染到 SceneResolved |
| 14 | `VolumetricPass` | 体积雾光线步进 + 时间重投影 + 合成 |
| 15 | `TemporalResolvePass` | TAA 时域抗锯齿 |
| 16 | `MotionBlurPass` | 运动模糊 |
| 17 | `DepthOfFieldPass` | 景深 |
| 18 | `WaterCompositePass`（post-TAA 回退） | 水面合成回退路径 |
| 19 | History update | 历史帧更新（TAA/SSAO/SSR/体积雾 ping-pong） |

最终 `targets.blitSceneResolvedTo(capturedFramebuffer)` 与 `targets.blitDepthTo(capturedFramebuffer)` 将结果 blit 回捕获的帧缓冲。

### 4.2 ForwardPipeline — 前向渲染管线（简易路径）

**文件**：`src/renderer/core/ForwardPipeline.h` / `.cpp`

前向管线无 GBuffer、阴影、SSAO、SSR、体积雾等高级特性，仅执行：

1. 天空渐变
2. 不透明 + 镂空地形（`forward_basic_terrain` 着色器，含 `chunk_lit_common.frag` 共享光照）
3. 实体与粒子
4. 透明地形
5. 简单雾

该管线作为低配设备或调试回退路径存在，调用链与延迟管线一致。

### 4.3 RenderPass 基类

**文件**：`src/renderer/passes/RenderPass.h`

```cpp
class RenderPass {
public:
    virtual void init(ResourceMgr& resourceMgr) = 0;
    virtual void shutdown() = 0;
    [[nodiscard]] virtual const char* name() const = 0;
protected:
    static void renderFullscreen(GLuint vao, Shader& shader);  // 全屏三角形辅助
};
```

所有 Pass 继承自 `RenderPass`，通过 `ResourceMgr` 加载着色器，在 `execute()` 中执行 GL 调用。

## 五、地形渲染系统

地形渲染是 Mecraft 渲染系统的核心，涉及网格构建、缓存、流式调度、视锥剔除、MDI 绘制五个环节。

### 5.1 ChunkMesher — 贪心网格化

**文件**：`src/renderer/mesh/ChunkMesher.h` / `.cpp`

`ChunkMesher::buildSubChunkMeshData()` 是网格构建主入口，流程：

1. **`scanMeshClassPresence()`** — 扫描 4096 个方块，分类为 Opaque/Transparent/Water/Cutout/CutoutDistance/Other/CustomBlock/FluidLayer，用于提前跳过不需要的网格化阶段。
2. **`buildOpaqueGreedyFaces()`** — 不透明方块贪心网格化
3. **`buildCutoutGreedyFaces()`** — 镂空方块贪心网格化
4. **`buildTransparentGreedyFaces()`** — 透明方块贪心网格化
5. **`buildStillWaterTopGreedyFaces()`** — 静水面顶部贪心合并
6. 自定义形状方块遍历 — 对 Cross/Torch/Water 等非立方体方块逐个构建

#### 5.1.1 贪心网格化算法

核心在 `emitGreedyPlaneRuns()` 与 `buildCubeGreedyFaces<Face, NX, NY, NZ>()` 模板函数：

- 对每个面方向（6 个面），逐 slice 遍历 16×16 平面
- `populateCell()` 调用 `shouldRenderFaceImpl()` 做面剔除，生成 `FaceCell`（含渲染数据 + `FaceMergeKey`）
- **`FaceMergeKey`** 包含：`blockId`、`tileIndex`、`flipDiagonal`、`tintKind`、`tintU/tintV`、`derivativeMaterialId`、`uvQuarterTurns`、4 顶点的 AO/sun/block 光照值，以及 FNV-1a 哈希
- **贪心合并**：从 (u,v) 出发，先沿 u 方向扩展 `runWidth`（比较 `samePlaneFaceCell()`），再沿 v 方向扩展 `runHeight`（整行验证），生成大四边形
- **T-junction 修复**：`expandGreedyFaceCornersInPlane()` 将合并后四边形角点在平面内微膨胀 `kGreedyFaceOverlapEpsilon = 1/1024`，避免相邻大小不同四边形间的光栅化裂缝
- UV 按合并后宽高重复，支持 `uvQuarterTurns` 旋转

6 面构建通过模板 `buildOpaqueGreedyPlane<Face, NormalX, NormalY, NormalZ>()` 编译时特化，内联法线常量，避免运行时分支。

#### 5.1.2 面剔除算法

`shouldRenderFaceImpl()` 通用判断：

- 透明立方体同类型相邻 → 不渲染（避免水内部面）
- 邻居为空气 → 渲染
- 邻居不固体 → 渲染
- 邻居透明但当前不透明 → 渲染
- 邻居透明且当前也透明：仅当类型不同时渲染

特化路径：

- `shouldRenderOpaqueCubeFace()` — 不透明立方体快速路径
- `shouldRenderWaterFace()` — 水面可见性（检查 waterlogged 流体层）
- `shouldSkipSubChunk()` — 子区块级跳过：Air 类型直接跳过；Solid 类型检查是否完全被不透明固体包围

#### 5.1.3 环境光遮蔽（AO）

`computeVertexAO(side1, side2, corner)` — 标准 Minecraft AO 算法：

- side1 和 side2 都为实体 → AO = 0（最暗）
- 否则 AO = 3 - (side1 + side2 + corner)，值域 0~3

每顶点 AO 从 halo 数据（18×18×18 外围方块）采样 3 个邻居方块（2 个边邻 + 1 个角邻）计算。

#### 5.1.4 水面渲染

- `computeWaterCornerHeight()` — 对水面 4 角高度加权平均，采样周围流体方块的 `FluidState::level`，模拟水面波动
- 顶面四边形按角高度变形，支持流向旋转
- `buildStillWaterTopGreedyFaces()` — 对静水面贪心合并

#### 5.1.5 顶点格式

**`BlockVertex`**（32 字节）— 网格构建用：
- 位置 x/y/z (float)、UV u/v (float)
- normal (int8_t) — 0~5 表示面法线，-1/-2 为 cross 形状标记
- sunlight/blockLight (uint8_t, 归一化 0~255)
- ao (uint8_t, 0~3)
- layer (uint16_t) — 纹理数组层
- 动画数据 (animationFrameCount, animationFps, animated)
- tintPacked (uint16_t) — 生物群系着色 + 材质 ID 打包

**`PackedBlockVertex`**（16 字节）— GPU 上传用，通过 `packBlockVertices()` 压缩：位置 12-bit 定点、UV 16-bit 定点、光照/AO/layer 打包到 32 位。

**`ChunkMeshData`** — 网格构建结果，分 5 个顶点缓冲：`opaqueVertices`、`cutoutVertices`、`cutoutDistanceVertices`、`transparentVertices`、`waterVertices`，含 greedy 前后面计数统计。

#### 5.1.6 网格形状注册表

`MeshBuilderRegistry` 支持的形状：

- `cube` (CUBE_TAG) — 走贪心网格化路径
- `cross` (CROSS_TAG) — 十字植物（花、草）
- `torch` (TORCH_TAG) — 火把
- `water` (WATER_TAG) — 水方块

### 5.2 ChunkMeshingService — 异步网格化调度

**文件**：`src/renderer/mesh/ChunkMeshingService.h` / `.cpp`

- `submit(SubChunkMeshingJob, priority)` — 提交子区块网格化任务到 `ThreadPool`
- 工作线程调用 `ChunkMesher::buildSubChunkMeshData(snapshot)` 构建网格
- 使用 epoch 机制处理 shutdown 时的过期结果
- `tryPopCompleted()` — 主线程轮询获取完成结果
- `SpinLock` 保护完成队列，避免互斥锁开销

`SubChunkMeshingSnapshot` 为网格化捕获的子区块快照：16×16×16 核心 blocks/fluidBlocks/lightMap + 18×18×18 halo 数据 + 6 方向边界切片，用于处理子区块边界面剔除和 AO。

### 5.3 WorldRenderBuffer — GPU 顶点池与 MDI

**文件**：`src/renderer/mesh/WorldRenderBuffer.h` / `.cpp`

#### 5.3.1 VertexPoolAllocator — 空闲链表顶点缓冲分配器

- 初始容量 ~2M 顶点（~64MB）
- `allocate()` / `free()` — 空闲块链表管理
- `coalesceAt()` — 相邻空闲块合并
- 支持容量自动扩展

#### 5.3.2 三池架构

`WorldRenderBuffer` 管理 opaque + cutout + transparent 三个独立顶点池：

- `uploadSubChunk()` — 打包 `BlockVertex` 为 `PackedBlockVertex`（16 字节），上传到对应池
- **MDI 间接绘制**：`DrawArraysIndirectCommand` 命令缓冲，`flushOpaque()` / `flushCutout()` / `flushTransparent()` / `flushWater()` 批量提交
- `mergeAdjacentCommands()` — 合并相邻的间接绘制命令减少 draw call
- 每子区块元数据 `SubChunkDrawMetadata`（世界原点 + flags）通过 SSBO binding 0 传递

### 5.4 TerrainRenderer — 视锥剔除与渲染

**文件**：`src/renderer/mesh/TerrainRenderer.h` / `.cpp`

#### 5.4.1 视锥剔除

6 平面 AABB 测试（Gribb-Hartmann 方法）：

- `updateFrustum(viewProj)` — 从 viewProj 矩阵提取 6 个视锥平面
- `isChunkInFrustum(min, max)` — 对 AABB 做平面正顶点测试

**分层剔除**（3 层）：

1. **Region 级** — 多个区块列的聚合 AABB 测试
2. **Column 级** — 单区块列边界框测试
3. **Sub-chunk 级**（MDI 模式）— 每子区块边界框测试

#### 5.4.2 主渲染函数

`renderOpaqueChunksAndCollectPasses()`：

- 遍历 `chunkRenderColumns`，分层视锥剔除
- MDI 模式：将可见子区块的 `GpuMeshRange` 添加到 `WorldRenderBuffer`
- 非 MDI 模式：直接绑定 VAO 绘制
- 收集 cutout 和 transparent 条目供后续 Pass 使用
- 支持 `ShadowCasterCuller`（Iris BoxCuller 风格立方体裁剪）
- 支持 cutout 距离剔除（`m_cutoutRenderDistanceChunks = 4.0`）

#### 5.4.3 uniform 与纹理绑定

`bindChunkRenderState()` 绑定约 30 个 uniform + 约 15 个纹理（CSM 阴影数组、GBuffer 所需光照环境等）。

#### 5.4.4 透明排序

`WorldDrawBatch::sortTransparentBackToFront()` — 按 `distanceSq` 降序排列，保证透明物从后向前渲染。

### 5.5 TerrainRenderCache — 渲染缓存

**文件**：`src/renderer/mesh/TerrainRenderCache.h` / `.cpp`

`ChunkRenderColumnCache`（每区块列）：

- 聚合边界框（opaque + cutout）
- 列级边界框
- 每子区块网格修订版本与指纹
- 透明子区块列表与边界

**MDI 分配管理**：

- `SubChunkGpuKey` (chunkKey + scy) → `MdiMeshAllocation` 映射
- `releaseStaleMdiAllocations()` — 检查子区块修订版本，释放过期 GPU 顶点缓冲
- `drainMeshingResults()` — 取回完成的网格化结果，上传 GPU

### 5.6 TerrainStreamingService — 流式调度

**文件**：`src/renderer/mesh/TerrainStreamingService.h` / `.cpp`

每帧调度流程：

1. `beginFrame()` — 重置计数器
2. `releaseStaleMdiAllocations(world)` — 释放已变更子区块的 GPU 分配
3. `drainMeshingResults(world)` — 取回完成的网格化结果
4. （管线渲染地形）
5. `submitMeshingJobs(world, cameraPos)` — 按相机距离提交脏子区块网格化
6. `endFrame()` — 记录调试历史

**预算控制**：

## 六、光照系统

### 6.1 光照模型

**文件**：`src/world/light/LightTypes.h`、`LightSolver.h/.cpp`、`LightService.h/.cpp`、`LightCache.h/.cpp`

- **双通道光照**：`LightKind::Sky`（天空光照）与 `LightKind::Block`（方块光照）
- **打包格式**：每方块一个 `uint8_t`，高 4 位 = 天空光照（0~15），低 4 位 = 方块光照（0~15）
- **不透明度衰减**：`propagateLevelFromOpacity<Kind>()` — 光照传播时减去邻居方块的 opacity；天空光向下传播（DY=-1）时使用 opacity 而非 1

### 6.2 LightSolver — BFS 传播求解

类似 Minecraft 的光照引擎：

**`buildCurrentBasePacked()`** — 构建基础光照（无边界种子）：

- 天空光：从 y=255 向下逐列扫描，opacity >= 15 的方块阻断天空光，否则按 opacity 衰减
- 方块光：扫描所有光源方块，设置初始光照等级
- 应用边界种子（来自邻居区块的 `BorderUpdateBatch`）

**`runRemovePassTyped<Kind>()`** — 光照移除通道：

- 方块变化导致光照减少时，从变更点 BFS 传播，将依赖被移除光源的邻居降级到基础光照值
- 被降级但仍有光源的点加入 addQueue 重新传播

**`runAddPassTyped<Kind>()`** — 光照添加通道：

- 从 addQueue BFS 传播，光照按 opacity 衰减后写入邻居
- 仅当传播值大于邻居当前值时更新

**增量更新流程**：

1. 比较 `basePacked`（新基础光照）与 `workingPacked`（当前光照），生成 remove/add 队列
2. 先运行 removePass 清除过期光照
3. 再运行 addPass 传播新光照
4. 边界种子通过 `emitBoundarySeeds()` 输出到邻居区块

### 6.3 跨区块光照传播

`BorderUpdateBatch` — 边界光照传播包：

- 记录目标区块 key、源修订版本、方向（0=+X, 1=-X, 2=+Z, 3=-Z）
- 包含 `BorderLightNode` 列表（位置 + 光照等级 + 类型）
- 边界面 dirty mask 标记哪些子区块需要重新网格化

### 6.4 LightService — 主线程调度器

- `onChunkLoaded()` / `onBlockChanged()` — 标记区块为 dirty
- `submitJobs()` — 按相机距离优先提交光照任务到线程池
- `drainCompleted()` — 合并完成的光照结果，回调通知网格化
- **交互式优先**：`processInteractiveJobsInline()` — 玩家附近的光照变更同步处理，减少延迟
- **BaseLight 缓存**：`ensureBaseLightCache()` 增量维护基础光照缓存，避免 worker 每次全量计算

### 6.5 顶点光照编码

网格构建时，每顶点从 halo 光照数据采样并编码：

- `VertexLightData` — 含 ao、sunLight、blockLight、sunKey、blockKey（用于贪心合并比较）
- `sunNormalized` / `blockNormalized` — 归一化到 0~1 后打包到 uint8_t（乘以 180.0 再量化）

## 十五、区块管理与序列化

### 15.1 Chunk 结构

**文件**：`src/world/chunk/Chunk.h` / `.cpp`、`SubChunk.h` / `.cpp`

**Chunk（区块列）**：

- `SIZE_X=16, SIZE_Y=256, SIZE_Z=16, NUM_SUB_CHUNKS=16`
- 16 个 `std::unique_ptr<SubChunk>` 沿 Y 轴排列，nullptr 表示全空气（零存储）
- 4 方向水平邻居指针 `neighbors[4]`（+X, -X, +Z, -Z）
- 每子区块脏标记掩码 `m_dirtySubChunkMask`（uint32_t, 16 位使用）
- 网格修订版本 `m_subChunkMeshRevisions[16]` — 用于网格化过期检测
- 列级聚合网格 `m_columnMesh` + 每子区块的 `ColumnAggregateSlice`
- 高度图 `m_heightMap[256]`
- 光照修订版本 `m_lightRevision`，光照队列/飞行状态标记

**SubChunk**：

- 16×16×16 = 4096 方块
- 使用 **Palette + BitPackedArray** 存储方块 ID（调色板压缩）
- 独立流体层（Palette + BitPackedArray）— 支持 waterlogged 方块
- `SubChunkType` 枚举：`Air`（无存储）/ `Solid`（单方块类型）/ `Normal`（完整存储）
- 6 方向邻居指针（包括 +Y/-Y 跨子区块）
- 4096 字节光照地图 `m_lightMap`
- `SubChunkMesh` — 含 VAO/VBO + MDI 全局池范围

### 15.2 区块加载流程

**ChunkTicketManager**（`src/server/ChunkTicketManager.h`）— 票据系统：

- 4 种票据类型：`Spawn`（出生点常驻）、`PlayerSimulation`（模拟半径）、`PlayerView`（视距内）、`Forced`（强制加载）
- 三层半径：`simulationRadius`（默认 8）、`viewRadius`（默认 16）、`loadRadius = viewRadius + 1`、`unloadRadius = viewRadius + 3`（滞回带）
- `getChunksToLoad()` — 按距离排序返回需加载区块
- `getChunksToUnload()` — 返回超出卸载半径的区块

**World::updateStreaming()**（`src/world/World.h`）— 每帧流式加载：

1. `updateLoadQueue()` — 更新加载队列（按距离排序）
2. 提交区块生成任务（`kMaxGenerationInFlight = 3`，每帧最多提交 2 个）
3. 地形生成完成后 `finalizeChunkLoad()` — 设置邻居链接、初始光照、标记 dirty
4. 光照提交预算和合并预算

### 15.3 区块序列化

**MCHK 格式**（`src/save/ChunkSerializer.h`）：

- `serializePayload()` — 读取 SubChunk 的 Palette + BitPackedArray，将 RuntimeId 转为 NamespacedId 字符串
- `deserializePayload()` — 反序列化，未知方块 ID 回退为 AIR
- 文件格式：magic + version + payload + CRC32

**RegionFile**（`src/save/RegionFile.h`，.mcrg 格式）：

- 32×32 区块/区域文件
- RegionHeader (16 字节)：magic 'MCRG' + version + flags + regionX/Z
- ChunkIndex[1024] (16384 字节)：每条目 16 字节（offset + size + crc32 + timestamp）
- 区块数据追加写入文件末尾

**SaveManager**（`src/save/SaveManager.h`）— 存档总管：

- 管理 save 目录、`level.json`（种子/时间/天气）
- 异步区块保存（通过 ThreadPool）
- `tryLoadChunk()` / `submitSaveChunk()` / `flushPendingSaves()`

## 十九、技术特点总结

基于完整源码通读，Mecraft 渲染系统具有以下技术特点：

### 19.1 架构层面

1. **双管线可切换**：`RenderPipeline` 抽象接口统一 Forward/Deferred，运行时通过 `RenderScene::setPipelineMode()` 切换，切换时清除时域历史帧。
2. **无全局状态的帧数据流**：`FrameContext` 作为单帧数据源，所有 Pass 通过它获取数据，避免全局状态访问。
3. **分层网格化**：SubChunk 级别快照捕获 → 多线程贪心网格化 → GPU 顶点池上传 → MDI 间接绘制。
4. **ECS 驱动**：实体/粒子/相机等通过 entt 组件系统管理，渲染器通过 `GameplayRegistry` 查询。
5. **异步管线**：区块生成、光照求解、网格化、存档均通过 `ThreadPool` 异步执行，主线程仅做调度与 GPU 提交。

### 19.2 渲染算法层面

1. **完整延迟管线**：GBuffer（5-MRT）→ 照明 → SSAO → SSR → 体积雾 → 云 → 合成 → TAA → 后处理。
2. **PBR 光照**：Cook-Torrance 高光（GGX NDF + Smith G2 visibility）+ Hammon 漫反射 + Schlick/精确介电 Fresnel（移植自 `derivative_brdf.glsl`）。
3. **4 级 CSM + PCSS**：级联过渡混合 + 抖动级联选择 + 接触阴影 + 水焦散。
4. **Bruneton 大气散射**：预计算 3D LUT（256×128×33 RGBA32F）+ 等距柱状天空捕获 + L1 球谐天光。
5. **光线步进体积云**：多阶 3D 噪声 + Beer-Powder 散射 + 时域重投影。
6. **体积雾**：太阳方向光学深度 + 多瓣相函数 + 云影 + 水下光照。
7. **SSR**：反射探针 + 粗糙度自适应 + 双边滤波 + 时域重投影 + 天空捕获回退。
8. **水体**：波浪法线 + 视差 + 菲涅耳折射 + 水雾 + 水下效果 + SSR。
9. **SSS**：按材质 ID 区分强度（草=0.45, 树叶/雪=0.70, 旗帜=0.65）。
10. **天气表面**：雨水湿润度、水坑、涟漪法线、湿润反照率暗化。
11. **后处理**：自动曝光（13 级 mipmap 下采样）、7 级 Bloom、6 种色调映射（Reinhard/ACES/Filmic/AgX）、色彩分级、CAS 锐化、运动模糊、景深、FSR1 超分。

### 19.3 性能优化层面

1. **MDI 多绘制间接**：`WorldRenderBuffer` 通过 `DrawArraysIndirectCommand` 批量提交，`mergeAdjacentCommands()` 合并相邻命令减少 draw call。
2. **三级视锥剔除**：Region → Column → Sub-chunk 分层 AABB 测试。
3. **顶点池空闲链表**：`VertexPoolAllocator` 支持相邻空闲块合并，避免频繁 GPU 内存分配。
4. **网格化预算控制**：每帧提交/取回任务数、时间、顶点数预算。
5. **增量光照**：BFS 增量传播 + 基础光照缓存，避免全量重算。
6. **交互式光照优先**：玩家附近光照变更同步处理，减少延迟。
7. **时域重投影**：SSAO/SSR/体积雾/云/TAA 均使用时域累积，半分辨率计算后上采样。
8. **PBO 异步回读**：自动曝光通过 PBO + 3 帧环形缓冲异步读回亮度。
9. **子区块级跳过**：Air/Solid 类型子区块直接跳过网格化。

### 19.4 Iris/DerivativeMain 兼容层面

1. **ShaderpackDirectives**：映射光影包配置到 C++（`shadowDistance`、`sunPathRotation`、`resolution` 等）。
2. **ShadowCasterCuller**：参照 Iris-26.1 的 `BoxCuller`/`BoxCullingFrustum` 实现。
3. **天气遮罩**：`RainRenderer::renderWeatherMask()` 兼容 DerivativeMain `gbuffers_weather`。
4. **材质 ID 系统**：基于 DerivativeMain `block.properties` 的整数材质 ID 契约。
5. **TAA 抖动公式**：直接复现 `shaders.properties` 中的 `frameX`/`frameY` 公式。
6. **常量对应**：`RenderResourceHub` 中的设置结构体常量名直接对应 DerivativeMain 常量（`SEA_LEVEL`、`CLOUD_CUMULUS_CLEAR_ALTITUDE` 等）。
