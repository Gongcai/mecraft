## 二、各系统详细分析

### 2.1 阴影系统 ⚠️ Mecraft CSM 完成，DerivativeMain shadow 语义未全覆盖

**已实现：**
- CSM 4 cascade depth texture array（`GL_DEPTH_COMPONENT32F` × 4 layers）
- `ShadowRenderer` 从 `Renderer` 拆分，拥有 cascade 数据、光照方向、uniform 绑定
- `ShadowMatrices::buildCascades()` — frustum slice + bounding sphere + texel snapping + 正交投影
- `mecraft_shadow.glsl` CSM contract：cascade 选择、投影、bias、PCF 3x3、PCSS、cascade transition fade
- PCSS 近 cascade（blocker search 8 tap → penumbra estimation → variable 4x4 PCF）
- Contact shadow 16 步（距离自适应步长、zTolerance 0.015）
- Cascade-specific PCF radius（cascade 0 = 2.0x，cascade 3 = 1.0x）
- Water/stained glass 在 CSM depth-only pass 中 `discard`
- Hardware comparison sampler（`sampler2DArrayShadow` + `glTextureView`）
- Bias/normal offset 从 `RenderPipelineSettings` 通过 `ShadowRenderer::BiasSettings` 透传
- Debug views：CSM Cascade、CSM Depth 0-3、Cascade Info
- 旧 `shadowWarpMode`/`shadowWarpCutoff`/`derivativeExactShadow` 已从 settings/renderer/shader 中删除

**遗留问题：**

#### 2.13.4 自动曝光链路

**DerivativeMain** (`Temporal.vert:13-61`):
1. 从 mip chain（LOD 6，64×64）计算加权平均 log-luminance（中心加权）

3. 时序平滑：暗适应 1.5x，亮适应 1.0x

**Mecraft** (`PostProcessRenderer.cpp:318-339`):
1. 从 exposure_downsample.fs 计算加权平均 log-luminance（中心加权，`* 0.75` 压缩）
2. 同一 Sigmoid 曲线
3. 时序平滑：暗适应 1.5x，亮适应 1.0x
4. 2026-05-15 已移除非 DerivativeMain 的 `averageLum >= 0.02` 地板和 target exposure min/max clamp

**当前结论：** Mecraft 当前曝光响应公式已回到 DerivativeMain 语义。若夜晚阴影/昼夜过渡仍不对，下一步不应再调 exposure clamp，而应继续核对 Grade/Tonemap 集合、Bloomy Fog、Purkinje Shift、以及 deferred lighting 中仍属于 Mecraft extension 的项。

- `sampleSkyRadianceCloudy()` 坐标错误，可能只采到底部边缘行，而不是 cloudy sky 区域。

#### 2.14.3 大气追加差异

- `atmGetSkyRadiance()` 内部写死约 `Alt=100m`，而 metadata pass 使用 `uCameraAltitude + 100`；DerivativeMain 全局使用 `eyeAltitude`。这会让 sky radiance 与 metadata/验证程序在高度上不同源。
- `SKY_GROUND` 与 `AURORA/AURORA_STRENGTH` 不纳入当前目标；`FULL_AERIAL_PERSPECTIVE`、stars、night vision/lightning 对 sky/skylight/cloud 的贡献仍需按视觉收益评估。
- `MoonFlux` 与 `DoNightEye` 需要确认 C++ `uMoonPhaseFlux` 是否完全等价 DerivativeMain 的 `moonPhase/nightVision/NIGHT_BRIGHTNESS` 链。
- DerivativeMain 在 `VOLUMETRIC_FOG || VOLUMETRIC_LIGHT` 开启时会 `#undef LAND_ATMOSPHERIC_SCATTERING`，否则 land scattering 作为非体积路径的远景空气透视 fallback。Mecraft 当前 deferred lighting 的 `applyAerialPerspective()` 与半分辨率 `volumetric_fog.fs` 会叠加/分担职责，需要明确互斥关系，否则容易出现远景灰雾和体积雾都偏弱或都叠加的状态。
- `CommonFog()` 处理 blindness/darkness、lava、powder snow，并在粉雪里用 `skyIlluminance + directIlluminance` 生成亮雾；~~Mecraft 仍以普通 forward fog/水雾为主，没有完整纳入 deferred composite 链路。~~ ✅ 已实现：`fogs.glsl` 移植 CommonFog，`scene_composite.fs` 集成为最终 fog pass（水→CommonFog/lava/powder_snow/blindness/darkness）。

#### 2.14.4 水/透明/雨湿追加差异

- `water_composite.fs` 的 WaterFog 使用 `uSkyAmbientColor/uSunLightColor`，DerivativeMain 使用 `skyIlluminance/directIlluminance`。
- 水焦散在 DerivativeMain shadow pass 写 `shadowcolor0/1`；Mecraft 当前 water 在 CSM 中 discard，避免硬阴影但丢掉 caustics 数据。
- DerivativeMain terrain/entity/hand 雨湿会改 `specularData.rg`、normal、albedo，并由 `wetnessCustom`、`eyeSkylightFix`、biome precipitation 平滑驱动；Mecraft 目前有 terrain wetness mask/roughness 调整和水面雨涟漪，但没有完全复现实体/手/方块 pass 的雨湿 GBuffer 语义。
- 透明折射、stained glass absorption、ice tint 在 Mecraft 有近似，但没有完整 `depthtex1`/dual-depth 语义。

#### 2.14.5 后处理追加差异

- Mecraft 自动曝光公式接近 DerivativeMain，但执行在 CPU readback/downsample 链，且带 clamp；DerivativeMain exposure 存在 `colortex5(0).a` 并由 Temporal pass 写回 history。
- Mecraft bloom extract 对 HDR 有额外 clamp，说明上游 HDR 范围与 DerivativeMain 不同；DerivativeMain bloom 依赖 tiled mip 和 exposure compensation。
- `BLOOMY_FOG` 缺失是体积雾“不惊艳”的关键之一，不只是后处理小差异。
- DerivativeMain `CalculateBloomFog()` 会从 bloom tile 叠加多级模糊，再用 `colortex6.x` 的 `fogTransmittance` 混合：`color = mix(fogBloom * 0.5, color, fogTransmittance)`。Mecraft `volumetric_composite.fs` 只做 `scene * volumetric.a + volumetric.rgb`，后续 bloom 不知道哪些像素被雾衰减过。
- Final CAS/dither/CatmullRom upsample 与 DerivativeMain `Final.glsl` 不是同一 buffer 输入。

#### 2.14.6 Shadow/Colored Shadow 追加差异

- 当前正式阴影采样走 `uCsmShadowMap/uCsmShadowMapRaw` depth array；`uShadowColorTex/uShadowNormalTex` 绑定的是旧单层 shadow FBO 的 color/normal。由于正式 CSM layer pass 没有 color attachment，`sampleShadowColorTint()` 无法按 cascade texel 读取透明 caster 颜色。
- DerivativeMain 的 colored shadow 依赖 `shadowtex0`（含透明）与 `shadowtex1`（opaque-only）比较差异，再从 `shadowcolor0` 取 stained glass tint。Mecraft 目前只做 water/stained glass discard，避免硬阴影，但没有“透明 caster 仍投彩色光”的第二语义。
- 因为 CSM 是多 cascade array，不能简单复用旧 `shadowColorTex` 二维纹理；需要 `shadowColorArray/shadowNormalArray` 或单独 colored-shadow atlas，并明确 cutout/透明/水焦散各自写入规则。

#### 2.14.7 配置/Profile 差异

- DerivativeMain 默认 `FOG_TYPE=1`，但 UI 暴露 0/1/2/3；Medium/High/Ultra profile 分别把 `VOLUMETRIC_FOG_SAMPLES` 设为 9/12/16，而 shader 内默认常量是 20、滑块可到 500。Mecraft 当前只有单一 strength/density，不存在 profile 与质量档位的双层控制。
- DerivativeMain 的 `PC_SHADOW/VC_SHADOW` 会随 `CLOUDS_SHADOW` 和具体云开关自动启停；Mecraft 的 `cloudShadowsEnabled` 是简化的屏幕/世界噪声投影，未复用 planar/cumulus density。
- `eyeSkylightFix`、`wetnessCustom`、`volFogDensity`、`volFogWind`、`cloudDynamicWeather` 都由 `shaders.properties` 的表达式平滑计算；Mecraft 有部分 C++ 近似，但没有建立“shaderpack uniform 表达式 -> Mecraft frame uniform”的等价表。
