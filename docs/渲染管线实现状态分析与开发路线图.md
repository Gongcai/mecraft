> 本报告基于 2026-05-13 对 `src/renderer/`、`assets/shaders/`、`DerivativeMain/`、`Iris-26.1/` 源码的逐文件审计，并在 2026-05-14 结合当前截图、`D:\project\yanzheng` LUT 验证程序和最新 Mecraft 源码复核亮度/大气/云链路。

## 二、各系统详细分析

### 2.1 阴影系统 ⚠️ Mecraft CSM 完成，DerivativeMain shadow 语义未全覆盖

**已实现：**
- CSM 4 cascade depth texture array（`GL_DEPTH_COMPONENT32F` × 4 layers）
- `ShadowRenderer` 从 `Renderer` 拆分，拥有 cascade 数据、光照方向、uniform 绑定
- `ShadowMatrices::buildCascades()` — frustum slice + bounding sphere + texel snapping + 正交投影
- `mecraft_shadow.glsl` CSM contract：cascade 选择、投影、bias、PCF 3x3、PCSS、cascade transition fade
- PCSS 近 cascade（blocker search 8 tap → penumbra estimation → variable 4x4 PCF）
- Contact shadow 16 步（距离自适应步长、zTolerance 0.015）
- Cascade-specific PCF radius（cascade 0 = 2.0x，cascade 3 = 1.0x）
- Water/stained glass 在 CSM depth-only pass 中 `discard`
- Hardware comparison sampler（`sampler2DArrayShadow` + `glTextureView`）
- Bias/normal offset 从 `RenderPipelineSettings` 通过 `ShadowRenderer::BiasSettings` 透传
- Debug views：CSM Cascade、CSM Depth 0-3、Cascade Info
- 旧 `shadowWarpMode`/`shadowWarpCutoff`/`derivativeExactShadow` 已从 settings/renderer/shader 中删除

**遗留问题：**
- `deferred_debug.fs` modes 21/32/33/34 已改为 CSM/local wrapper 路径，不再引用旧 `warpDensity` / `localShadowDepthWorldScale()`；旧报告中的 debug 编译错误结论已过时
- 彩色阴影 `sampleShadowColorTint()` 是桩代码，返回白色
- 旧单层 `m_shadowFbo` 已有 `shadowColor/shadowNormal` 附件，但正式 CSM array pass 仍是 depth-only；lighting 绑定的 color/normal 不是当前 CSM cascade 语义的一部分
- SSS depth 恒为 0（CSM 路径无 blocker search 输出 SSS depth）

### 2.2 光照/BRDF/BlockLighting ⚠️ 主流程部分完成

**已实现：**
- `derivative_brdf.glsl` — 8 个 BRDF 函数逐字复刻（FresnelSchlick/Dielectric、GGX NDF、Smith visibility、DiffuseHammon、SpecularBRDF）
- `derivative_sunlight.glsl` — HenyeyGreensteinPhase、CalculateFakeBouncedLight、CalculateSubsurfaceScattering
- `derivative_shadow.glsl` — Common.inc 全量端口（30+ 辅助函数）、ShadowDistortion 全量
- BlockLighting 16+ 材质发射体完整端口（torch/fire/lava/glowstone/sea_lantern/redstone/soul_fire/amethyst/glowberry/rails/beacon/sculk/glow_lichen/emissive_ores）
- `deferred_lighting.fs` 主流程按 `deferred5.fsh` 重排（compositing 顺序精确匹配）
- 快速半程向量点积技巧、shadow *= saturate(voxelLight.r * 1e6)、specular *= 1.0 + wetness

**失效/缺失：**
- SSS：算法已移植但 `shadowSssDepth` 恒为 0，`CalculateSubsurfaceScattering` 永不执行
- GI（RSM）：未移植，仅有 fake bounce light
- 球谐光照（`FromSH`）：未移植，使用 5 方向半球采样替代
- Parallax shadow、aurora、lightning、night vision 未实现
- Nether blocklight 路径未实现（`IS_NETHER` ifdef）

### 2.3 大气 ⚠️ LUT 完成，SkyCapture 接入偏差

- Bruneton LUT 查询链完整：transmittance（256×64）、combined scattering（32×128×32×8）、irradiance（64×16）
- Rayleigh/HG phase function、sun limb darkening、moon disc
- `atmGetSunAndSkyIrradiance` 含 horizon correction
- Sky capture 256×514 equirectangular + metadata rows（illuminance）

**2026-05-14 复核新增问题：**
- `assets/shaders/render_contract.glsl` 的 `sampleSkyRadiance()` / `sampleSkyRadianceCloudy()` 仍把 256×514 纹理当成虚拟 `v in [0,2]` 的 sky atlas 使用。OpenGL `sampler2D` 坐标实际归一化到 0..1，`projectSkyCloudy()` 返回 `uv.y + 1.0` 会被 clamp 到纹理底边；raw sky 采样的 `v 0..1` 也会跨过 raw sky、cloudy sky 和底部行。这会导致主画面/反射/水体采样不到正确天空区域，是“SkyCapture debug view 有蓝带，但主画面天空灰白/不蓝”的 P0 根因。
- `gameplay_sky.fs` 的 mode 4 通过 `atmGetSkyRadiance()` 写入 sky capture；该函数已内置 `* 20.0`，与 DerivativeMain `Deferred0.glsl` 的 `GetSkyRadiance(...) * 20.0` 一致。但验证程序 `D:\project\yanzheng\shaders\atmos.frag` 的 mode 5 显示的是原始 `GetSkyRadiance()`，最后用 `ACES(result * Exp=20)` 预览。因此验证截图和 Mecraft SkyCapture debug view不是同一显示路径：一个是“原始 radiance × 20 后 tonemap”，另一个是“capture 内已 ×20，再由 debug/post 预览”。
- `gameplay_sky.fs` metadata pass 会用 LUT 计算 `directIlluminance/skyIlluminance` 写入 SkyCapture metadata；但 `Renderer::buildFrameData()` 仍调用 `GameplaySkyRenderer::computeSkyIlluminance()` 的 CPU 艺术近似，并把它作为 `uDirectIlluminance/uSkyIlluminance/uSunIlluminance/uMoonIlluminance` 传给云、雾、水等 pass。Deferred lighting 从 SkyCapture metadata 取值，云 pass 从 uniform 取值，两套光照量不同源，导致天空、云、地表光照相互不一致。
- `deferred_debug.fs` mode 16 直接 `texture(uSkyCaptureTex, vTexCoord)`，显示的是整张 256×514 atlas 的直接纹理预览，不等价于 `sampleSkyRadiance()` 的方向采样，也不等价于验证程序的 equirectangular 单图预览。
- `D:\project\yanzheng` 验证程序中窗口标题 `5:Sky Radiance` 实际对应 `uDebugMode == 4`，`debugSkyRadiance()` 返回原始 `GetSkyRadiance()`，最后统一 `ACESFilm(result * uExposure)`；它不是 Mecraft 的 `uSkyCaptureTex` atlas 直接预览，也不是 cloudy sky/云合成结果。应把验证程序当作 LUT 函数验证，而不是 SkyCapture atlas 显示等价验证。

### 2.4 云 ⚠️ 主体完成，合成/光照输入偏差

- 32 步体积 ray march（积云），球面交叉 ray setup
- 4 octave 3D noise + 2D coverage lookup + height attenuation
- Sun optical depth 4 步 exponential-growth，sky light 2 步
- 4-lobe multi-phase（forward HG g=0.6, backward HG g=-0.35, Cornette-Shanks g=0.85/0.5）
- Beer-Powder scattering
- 卷云 + 卷积云独立层（5-octave FBM、curl noise、3-step sun OD）

**2026-05-14 复核新增问题：**
- `scene_composite.fs` 当前已经修到“只在天空像素合成云”，不再把远处地形与云混合；旧报告中“云出现在物体前面”的结论已过时。
- 当前合成公式仍不是 DerivativeMain 的 premultiplied alpha。DerivativeMain 是 `sceneData = sceneData * cloudData.a + cloudData.rgb`；Mecraft 当前是 `color = sky * cloud.a + cloud.rgb * uCloudCompositeStrength`。这会在 `uCloudCompositeStrength < 1` 时只压低云的散射项，不同步恢复 sky 权重，云会显得淡、灰、贴不上天空。
- `cloud_target.fs` 的体积云照明使用 `uSunIlluminance/uMoonIlluminance/uSkyIlluminance` uniform，而不是 SkyCapture metadata。若 CPU 近似与 LUT metadata 不一致，云亮度/颜色会偏离 sky capture。

### 2.6 后处理 ⚠️ 可用但非完整等价，Tonemap Mode 命名/语义偏离 DerivativeMain

### 2.8 体积雾 ⚠️ 部分

- 8 步 ray march，固定 `kFogSteps = 8`
- CSM shadow 4-tap PCF
- Height density、weather haze、phase、powder scattering
- Atmosphere transmittance integration
- 半分辨率 target + 5 tap depth-aware composite

**2026-05-14 复核：DerivativeMain 体积雾档位不是简单“更多步数”，而是四套密度场预设：**

| FOG_TYPE | DerivativeMain UI | 密度模型 | 视觉结果 |
|----------|-------------------|----------|----------|
| 0 | No Noise (Low) | 纯高度雾：`exp2(min((SEA_LEVEL + 32 - y) / 12, 0.2)) * 0.5` | 原版距离雾增强版 |
| 1 | Cloudy Fog Lite (Medium) | 高度雾 + 2 层 3D noise，晴天中午回退到轻雾 | 小团雾/薄雾 |
| 2 | Cloudy Fog (High) | 以 `SEA_LEVEL` 为中心的 4 层 FBM，`noise * 12 * falloff - 4.5`，输出 `* 9` | 大片团雾 |
| 3 | Cloudy Sea (Ultra) | 5 层 FBM，频率每层 `*4`，`falloff * noise * 400 - 170`，输出 `* 48` | 云海/低空云层 |

**Mecraft 当前与 DerivativeMain 的关键差异：**
- **无 FOG_TYPE 档位。** Mecraft 只有单一 `structuredFogDensity()`，更接近 Medium 的轻量噪声雾，没有 High/Ultra 的 `SEA_LEVEL` 云海密度场。
- **密度量级被压低。** 当前 `volumetricFogStrength=0.35`、`baseDensity=(0.00012+0.00030*horizon)*strength`，最终 `stepOpacity` clamp 到 `0.18`、总 `opacity` clamp 到 `0.34`。DerivativeMain High/Ultra 的 density 先被 `VOLUMETRIC_FOG_DENSITY * volFogDensity` 缩放，再通过 `*9`/`*48` 产生非常厚的雾团。
- **步数和步长策略不同。** DerivativeMain 默认 `VOLUMETRIC_FOG_SAMPLES=20`，实际 `steps = min(samples, samples*0.4 + rayLength*0.1)`；远距离快速接近 20，用户可调到 50/70/100/300/500。Mecraft 固定 8 步，无法支撑云海的体积边界。
- **缺少沿太阳方向二次光学深度。** DerivativeMain 在 FOG_TYPE > 1 时，每个有密度的样本再沿 `worldLightVector` 走 4 步，计算 `sunlightOD`，再用四瓣相函数和 powder 形成亮边/暗芯。Mecraft 只做 CSM 可见性，没有雾体自遮挡和多重散射近似。
- **云影集成不完整。** DerivativeMain 可同时把体积云阴影 `VC_SHADOW` 和平面云阴影 `PC_SHADOW` 乘进每个雾样本；Mecraft 只采 CSM，没有真正用云密度遮挡体积光。
- **独立体积光路径偏弱/不同源。** DerivativeMain 在 `VOLUMETRIC_LIGHT` 开启时，即使没有厚雾密度，也会加入 `airDensity = VOLUMETRIC_LIGHT_STRENGTH * RayleighPhase(LdotV) * (3.0 / far)`，再用 `directIlluminance * sunlightSample * 20.0` 输出丁达尔光束。Mecraft 当前把体积光并入雾的 `stepColor += shadowedDirect * ... * uVolumetricLightStrength`，颜色来自 `uSunLightColor`，且仍乘很低的雾 opacity；没有 DerivativeMain 那条“清空气溶胶体积光”路径，所以视觉上会像没有体积光。
- **时间/天气调制缺失。** DerivativeMain 有 `volFogWind`、`volFogDensity`、`meWeight`、`timeNoon/timeMidnight`，让日出日落和夜晚显著加强体积雾。Mecraft 主要靠 `weatherHaze` 和固定风，缺少日夜权重。
- **Bloomy Fog 缺失。** DerivativeMain 合成后把 `fogTransmittance` 送到 `BLOOMY_FOG`，后处理会用 bloom 模拟雾散射；Ultra 还把 `fogTransmittance = fogTransmittance * 0.3 + 0.7`，避免云海把画面压死但保留亮雾扩散。Mecraft 只是 `scene * volumetric.a + volumetric.rgb`，没有雾驱动的 bloom 亮扩散。

**结论：** 当前 Mecraft 体积雾视觉接近“前向距离雾 + 少量屏幕空间散射”，不是 DerivativeMain High/Ultra 的云状体积介质。要获得“云海感”，优先级不是单纯把 8 步加到 16-24，而是移植 FOG_TYPE 2/3 的密度场、太阳方向光学深度、多瓣散射和 Bloomy Fog 链路。

### 2.13 曝光/亮度/对比度链路 ⚠️ 系统性偏差

当前画面存在：背光面死黑、受光面过曝、天空颜色不可见、云不可见等问题。根因不是单一 bug，而是 SkyCapture 坐标、skylight/exposure/shadow shaping/cloud compositing 链路与 DerivativeMain 有系统性偏差。

#### 2.13.0 SkyCapture 坐标/单位链路偏差（2026-05-14 新增）

**Mecraft 纹理布局：**
- `DeferredRenderTargets::kSkyCaptureWidth = 256`
- `DeferredRenderTargets::kSkyCaptureHeight = 514`
- `render_contract.glsl` 声明 `skyCaptureRes = ivec2(255, 256)`
- raw sky 写入 rows 0..257，cloudy sky 写入 rows 258..513，metadata 写入 column 255 rows 0..5

**当前问题：**
```glsl
vec2 projectSkyCloudy(vec3 direction) {
    vec2 uv = projectSky(direction);
    return vec2(uv.x, uv.y + 1.0);
}

vec3 sampleSkyRadiance(sampler2D skyCapture, vec3 worldDir) {
    return texture(skyCapture, projectSky(worldDir)).rgb;
}
```

这套函数沿用了 DerivativeMain 的“`v` 可以处在 0..2 的虚拟 sky atlas”语义，但 Mecraft 采样的是普通 256×514 `sampler2D`，归一化 `v` 有效范围是 0..1。结果：

| 采样 | 期望 | 实际 |
|------|------|------|
| `sampleSkyRadiance()` | rows 0..255/257 的 raw sky | `v 0..1` 横跨整张 514 高纹理，混入 cloudy sky/metadata 区域 |
| `sampleSkyRadianceCloudy()` | rows 258..513 的 cloudy sky | `uv.y + 1.0` 超出 1，被 `GL_CLAMP_TO_EDGE` 钉到最后一行 |
| debug mode 16 | 方向采样预览 | 直接 atlas 预览，不能代表主画面实际采样 |

**影响：** 主画面天空、反射、水体、雾和 composite fallback 都可能采到错误的 sky row。截图中 debug view 出现清楚蓝带，而最终天空仍灰白，优先怀疑此坐标映射，而不是 LUT 本身。

**验证程序差异：**

`D:\project\yanzheng\shaders\atmos.frag` 的 mode 5：
```glsl
vec3 sky = GetSkyRadiance(atmosphereModel, dir, uSunDir, transmittance);
result = ACESFilm(sky * uExposure); // 截图 Exp=20.0
```

Mecraft/DerivativeMain sky capture：
```glsl
vec3 skyRadiance = GetSkyRadiance(...) * 20.0;
```

因此最后一张验证截图是“原始 LUT sky radiance × 20 后 ACES 预览”；Mecraft SkyCapture debug view 是“已写入 ×20 的 atlas 再预览”。两者不能逐像素比较，只能比较方向、色相和大致动态范围。若要对齐验证，应该新增一个 debug mode：按 direction 调 `sampleSkyRadiance()`，只显示 raw sky 区域，并明确是否额外乘曝光。

#### 2.13.1 Skylight 公式偏差

**DerivativeMain** (`deferred5.fsh:304-323`):
```glsl
vec3 skylight = FromSH(skySHR, skySHG, skySHB, worldNormal);  // SH 重建天空辐射率
skylight *= worldNormal.y * 2.0 + 3.0;                         // 方向加权 1.0-5.0x
vec3 skySunLight = (worldNormal.y * 0.24 + 0.4) * directIlluminance;
skylight = mix(skylight, skySunLight, wetness * 0.7);
sceneData += skylight * mcLightmap.g * SKYLIGHT_INTENSITY;      // SKYLIGHT_INTENSITY = 1.0
```

**Mecraft** (`deferred_lighting.fs:566-573`):
```glsl
vec3 skylight = coolSkyColor * skyIlluminance * directionalBoost * outdoorSkyMask * shadowTint;
sceneData += skylight * voxelLight.r;
```

**关键差异：**

| 方面 | DerivativeMain | Mecraft | 偏差 |
|------|---------------|---------|------|
| 数据来源 | `FromSH()` — 25 方向采样的 SH 重建辐射率 | `coolSkyColor * skyIlluminance` — 艺术色 × 辐照度 | 物理单位不同 |
| 乘积结构 | 辐射率 × 方向 × 遮罩 | 色彩 × 辐照度 × 方向 × 遮罩 | Mecraft 是两个独立量相乘 |
| 典型值（水平朝上，正午） | ~0.125 | ~0.365 | Mecraft ~2.9x 偏亮 |
| SH 方向性 | L0+L1 SH 自然编码方向变化 | `normal.y * 2.0 + 3.0` 近似 | SH 有方位角变化，近似没有 |
| 湿度混合 | `mix(skylight, skySunLight, wetness * 0.7)` | 无 | 缺失 |
| 闪电贡献 | `+ lightningColor * 1.2` | 无 | 缺失 |

**根因：** `coolSkyColor`（~0.73，艺术色，0-1 范围）× `skyIlluminance`（~0.1，物理辐照度）= 0.073。而 DerivativeMain 的 SH 评估直接返回 ~0.025。Mecraft 的 `coolSkyColor` 不是物理辐射率，是艺术调色的环境色，比物理值大 ~3x。

#### 2.13.2 Sunlight 强度偏差

**DerivativeMain** (`deferred5.fsh:241`):
```glsl
vec3 sunlightMult = 64.0 * waterTint * SUNLIGHT_INTENSITY * directIlluminance * cloudShadow;
// SUNLIGHT_INTENSITY = 1.0
```

**Mecraft** (`deferred_lighting.fs:512`):
```glsl
vec3 sunlightMult = waterTint * directIlluminance * 64.0 * uDirectSunStrength * cloudShadow;
// uDirectSunStrength 默认 1.36（已改为 1.0）
```

**差异：** Mecraft 原默认 `directSunStrength = 1.36`，比 DerivativeMain 的 `SUNLIGHT_INTENSITY = 1.0` 高 36%。这直接导致受光面更亮，与背光面的亮度差更大。

#### 2.13.2b Sunlight 颜色来源偏差（2026-05-14 新增）

**DerivativeMain：**
```glsl
sun_irradiance = atmosphere.solar_irradiance * GetTransmittanceToSun(r, mu_s);
directIlluminance = sunIlluminance + moonIlluminance;
sunlightMult = 64.0 * waterTint * SUNLIGHT_INTENSITY * directIlluminance * cloudShadow;
```

地表直射光、体积雾光照、水雾散射等主路径都以 LUT 大气透过率得到的 `directIlluminance/sunIlluminance` 为颜色来源。`sunIlluminance` 的 RGB 来自 `solar_irradiance = vec3(1.474, 1.8504, 1.912)` 乘大气 transmittance，不额外套 CPU 艺术色。

**Mecraft 当前：**
```glsl
vec3 directIlluminance = getDirectIlluminance(uSkyCaptureTex);
vec3 sunlightMult = waterTint * directIlluminance * 64.0 * uDirectSunStrength * cloudShadow;

vec3 warmSunColor = artisticSunIlluminance(uSunLightColor, sunDir);
color = applyAerialPerspective(color, worldPos, fogDistance, outdoorSkyMask, warmSunColor);
```

地表直射主项已经读 SkyCapture metadata，但画面整体阳光色仍会被以下路径改写：
- `artisticSunIlluminance()` 额外把 `uSunLightColor` 乘 `noonWarmth/lowSunWarmth` 和 `energy`，再用于 aerial perspective 的太阳前向散射。
- `GameplaySkyRenderer::computeSkyColors()` 生成 `uSunLightColor`：正午近 `vec3(1.0, 0.98, 0.92)`，低太阳近 `vec3(1.0, 0.58, 0.28)`，这是 CPU 艺术色，不是 LUT transmittance。
- `water_composite.fs` 的 `WaterFog()` 用 `uSunLightColor` 代替 DerivativeMain 注释里写的 `directIlluminance`，水雾/反射太阳盘会偏向 CPU 艺术色。
- `volumetric_fog.fs` 的 `sunScatterColor` 使用 `uSunLightColor`，不是 `directIlluminance`，所以体积雾/体积光颜色与地表直射颜色不同源。

**影响：** 即使地表 Lambert/BRDF 的直射主项量级正确，空气透视、水雾、体积雾、太阳反射仍会把画面染成 Mecraft 自己的暖色/灰色调，造成“阳光颜色不像 DerivativeMain”。修复优先级应和 §2.13.6b 一起处理：所有受太阳照亮的 pass 统一从 SkyCapture metadata 读取 `directIlluminance/sunIlluminance`，`uSunLightColor` 只保留给非物理 UI/旧 forward fallback。

#### 2.13.3 Shadow Shaping（DerivativeMain 无此步骤）

**Mecraft** (`deferred_lighting.fs:258-261`):
```glsl
float shapeShadowVisibility(float lit) {
    lit = clamp(lit, 0.0, 1.0);
    float contrasted = pow(lit, max(uShadowContrast, 0.001));
    return mix(clamp(uShadowMinLight, 0.0, 0.8), 1.0, contrasted);
}
```

**DerivativeMain：** 无此函数。PCF 输出的 shadow 值直接进入光照方程。

**影响：**
- `shadowContrast = 1.28` → `pow(0.5, 1.28) = 0.406`，半阴影区域亮度从 50% 降到 40.6%
- `shadowMinLight = 0.08` → 完全阴影区只有 8% 最低亮度
- DerivativeMain 没有这些参数，阴影值直接使用

**这是背光面死黑的直接原因之一：** 对比度增强 + 最低亮度限制，使阴影区域比 DerivativeMain 暗得多。

#### 2.13.4 自动曝光链路

**DerivativeMain** (`Temporal.vert:13-61`):
1. 从 mip chain（LOD 6，64×64）计算加权平均 log-luminance（中心加权）
2. Sigmoid 响应曲线：`targetExposure = 0.19 / (3.42 - 3.4124 * exp(-avgLum / 3.4124))`
3. 时序平滑：暗适应 1.5x，亮适应 1.0x

**Mecraft** (`PostProcessRenderer.cpp:318-339`):
1. 从 exposure_downsample.fs 计算加权平均 log-luminance（中心加权，`* 0.75` 压缩）
2. 同一 Sigmoid 曲线
3. 时序平滑：暗适应 1.5x，亮适应 1.0x（后改为 3.0x/1.5x）

**问题：** 曝光算法本身与 DerivativeMain 一致，但因为 skylight 不足导致阴影区域极暗，auto-exposure 为补偿暗区而大幅提升曝光值（~5x），导致切到亮区时严重过曝。这不是曝光算法的问题，是上游 skylight/shadow shaping 的问题。

#### 2.13.5 AcademyFit Tonemapper 隐藏增益

**DerivativeMain** (`lib/Post/ACES.glsl:367-384`) 与 **Mecraft** (`postprocess.fs:256-262`) 都有：
```glsl
vec3 AcademyFit(vec3 rgb) {
    rgb *= 1.4;   // 40% 隐藏增益
    rgb = RRTSweeteners(rgb * acesAp1ToAp0);
    rgb = RRTAndODTFit(rgb);
    ...
}
```

DerivativeMain 的 AcademyFit 也有 `* 1.4`，这不是 Mecraft 的问题。但它与 skylight/SkyCapture/exposure 偏差叠加，会放大过曝。

**新增校正：当前 Tonemap Mode UI 不是 DerivativeMain 原版。**

| UI/代码 | DerivativeMain 对应关系 | 结论 |
|---|---|---|
| `Reinhard` | 仅 TAA history blend domain 使用，不是最终 tonemap | 应标为 Mecraft debug/extra |
| `AcademyFit` | DerivativeMain 默认正式路径 | 应作为默认对齐目标 |
| `Filmic` | DerivativeMain 无正式选项 | 应标为 Mecraft extra |
| `AgX` | DerivativeMain 分 `AgX_Minimal` 与 `AgX_Full` | 当前单一 AgX 不够精确 |

**影响：** 如果用户在 UI 中切到 `Reinhard` 或 `Filmic` 调画面，会把 DerivativeMain-like 的曝光/色调问题混入非 DerivativeMain 曲线，导致对“自动曝光是否正确”的判断失真。对齐 DerivativeMain 时应先固定 `AcademyFit`，或明确实现 `AcademyFull / AgX_Minimal / AgX_Full` 三个真实选项。

#### 2.13.6 云合成偏差

**DerivativeMain** (`deferred5.fsh:168-176`):
```glsl
if (depth >= 1.0 && materialID != 36) {
    sceneData = textureBicubic(colortex5, skyCaptureCoord).rgb;
    vec4 cloudData = texelFetch(colortex1, texel, 0);
    sceneData = sceneData * cloudData.a + cloudData.rgb;  // premultiplied alpha
}
```
只在天空像素上合成云。地形像素永远不混合云。

**Mecraft 旧实现** (`scene_composite.fs:67-79`，已过时):
```glsl
if (depth >= 0.9999) {
    color = mix(sky, cloud.rgb, cloud.a * uCloudCompositeStrength);
} else if (cloud.a > 0.001) {
    float farCloudBlend = smoothstep(48, 192, viewDistance) * uCloudCompositeStrength * 0.28;
    color = mix(color, mix(color, cloud.rgb, cloud.a), farCloudBlend);
}
```
旧实现会在地形像素上也混合云（48m 起始，192m 完全），且 `uCloudCompositeStrength = 0.42` 限制了天空像素的云可见度。

**旧影响（当前地形混云已修正）：**
- 云出现在物体前面（48m 外的地形被云覆盖）
- 云在天空中只有 42% 可见度
- `* 0.28` 额外衰减使地形上云只有 11.8% 可见

**Mecraft 当前实现（2026-05-14）:**
```glsl
if (depth >= 0.9999) {
    vec3 sky = sampleSkyRadianceCloudy(uSkyCaptureTex, skyDir);
    color = sky * cloud.a + cloud.rgb * clamp(uCloudCompositeStrength, 0.0, 1.0);
}
```

已修正“地形像素混云”，但仍有两个问题：
- `sampleSkyRadianceCloudy()` 坐标错误，可能只采到底部边缘行，而不是 cloudy sky 区域。
- DerivativeMain 的 `cloudData.rgb` 是 premultiplied scattering，不应单独乘 `uCloudCompositeStrength`。若要保留调试强度，应在 premultiplied 语义下混合完整结果：`mix(sky, sky * cloud.a + cloud.rgb, strength)`。

#### 2.13.6b Sky illuminance 双来源偏差（2026-05-14 新增）

**DerivativeMain：**
- `world0/deferred.vsh` 用 `GetSunAndSkyIrradiance()` 计算 direct/sky/sun/moon illuminance。
- `Deferred0.glsl` 将 metadata 写入 `colortex5`。
- 后续 pass 通过 `texelFetch(colortex5, ivec2(skyCaptureRes.x, row), 0)` 读取同一份 metadata。

**Mecraft 当前：**
- `gameplay_sky.fs` mode 5 会用 LUT 写 SkyCapture metadata。
- `Renderer::buildFrameData()` 同时调用 `GameplaySkyRenderer::computeSkyIlluminance()`，该函数使用 CPU 近似：`colors.skyAmbientColor * (0.10 + 0.42 * skyVisibility)`。
- `deferred_lighting.fs` 从 SkyCapture metadata 读取 direct/sky illuminance；`cloud_target.fs`、`volumetric_fog.fs`、`water_composite.fs` 等 pass 使用 C++ uniform。

**影响：** 同一帧里“天空本身”和“被天空照亮的云/雾/水/地形”可能使用不同亮度和色彩来源，画面会表现为 LUT 验证有蓝天，但主画面天空、云和地表光照不跟随 LUT。

#### 2.13.7 完整亮度链路对比

| 环节 | DerivativeMain | Mecraft | 偏差 |
|------|---------------|---------|------|
| Skylight 数据源 | `FromSH()` SH 重建辐射率 ~0.025 | `coolSkyColor * skyIlluminance` ~0.073 | +2.9x |
| Skylight 方向加权 | `normal.y * 2.0 + 3.0` | 同 | 一致 |
| Sunlight 强度 | `SUNLIGHT_INTENSITY = 1.0` | `uDirectSunStrength` 原 1.36 | +36%（已修正） |
| Shadow shaping | 无 | `pow(lit, 1.28)` + `minLight=0.08` | 阴影更暗 |
| Auto-exposure | Sigmoid + 1.5x/1.0x 适应 | 同（+0.75 压缩） | 基本一致 |
| Tonemap modes | `AcademyFit/AcademyFull/AgX_Minimal/AgX_Full` | `Reinhard/AcademyFit/Filmic/AgX` | UI/实现集合不同构 |
| AcademyFit | `* 1.4` + RRT+ODT | 同 | 单个函数基本一致 |
| SkyCapture 坐标 | 方向采样 raw/cloudy sky 区域 | `v 0..1` 跨整张 514 高纹理，cloudy `v+1` clamp 到底边 | 天空采样错误/灰白 |
| Illuminance 来源 | SkyCapture metadata 单来源 | deferred 读 metadata，云/雾/水读 CPU 近似 uniform | 光照不一致 |
| Sunlight 颜色 | `directIlluminance/sunIlluminance` 来自 LUT transmittance | aerial/water/volumetric 使用 `uSunLightColor` + `artisticSunIlluminance` | 阳光色偏暖/偏灰，不随 LUT |
| 云合成 | 仅天空像素，premultiplied | 仅天空像素，但 `cloud.rgb` 被强度单独缩放 | 云偏淡/不融入 |

**链路叠加效果：**
- 背光面：skylight 不是 SH 重建，缺少正确方位/半球分布 → shadow shaping pow(1.28) 进一步压暗 → minLight=0.08 兜底不足 → 死黑
- 受光面：直接光动态范围大（历史上还叠过 `uDirectSunStrength=1.36`）→ auto-exposure 为补偿暗区而提升 → 亮区被推到严重过曝
- 天空：SkyCapture 坐标错误 + auto-exposure 高值 + sky radiance 已 `*20` → tonemap 后灰白/接近 1.0，蓝色层次被压扁
- 阳光颜色：地表直射、空气透视、水雾、体积雾不是同一 `directIlluminance/sunIlluminance` 来源 → 受光面和空气染色不像 DerivativeMain
- 云：输入 illuminance 与 sky metadata 不同源 + premultiplied scattering 被单独缩放 → 云偏淡，且与天空不一致

### 2.14 2026-05-14 全量复扫新增差异

本节来自对 `DerivativeMain/shaders.properties`、`Settings.glsl`、`world0/*`、`program/*`、`lib/*`、`block.properties`、`entity.properties` 的重新扫描，用来补足前面按症状分析时容易漏掉的内容。

#### 2.14.1 Pass/Buffer 语义差异

| DerivativeMain pass | 关键语义 | Mecraft 当前差异 |
|---|---|---|
| `deferred0` | raw sky + cloudy sky + metadata 共用 `colortex5` atlas | Mecraft SkyCapture 布局相似，但 normalized UV 未按 256x514 atlas 映射 |
| `deferred1` | 云渲染支持 `TEMPORAL_UPSCALING` checkerboard/history；只在 depth max 为 sky 的低分辨率格子渲染当前云样本 | Mecraft 云无 DerivativeMain 式 checkerboard temporal upscale，也缺 `depthMax4x4` 级别的天空格子筛选 |
| `deferred2` | 用 history frame count、CatmullRom、motion confidence 重建 full-res skybox/cloud history | Mecraft 有 cloud/history 纹理绑定，但没有 DerivativeMain 的 cloud history confidence/upscale 逻辑 |
| `deferred5.vsh` | 从 SkyCapture 做 5x5 SH，传 `skySHR/G/B` | Mecraft 未移植 `FromSH` 数据链 |
| `composite` | 半分辨率体积雾/体积光输出 `fogData` | Mecraft 是固定 8 步轻雾，不含独立清空气溶胶体积光 |
| `composite1` | 透明/水/折射/land scattering/volumetric fog/CommonFog，且体积雾关闭时启用 `LAND_ATMOSPHERIC_SCATTERING` | Mecraft 拆分成多个 pass，但 DerivativeMain 的 land scattering/CommonFog 分支没有作为同一套 fallback 链路复现 |
| `composite10/12/13/15/final` | tiled bloom + grade + final CAS/dither | Mecraft 后处理功能可用，但 buffer layout 与 fog bloom 耦合不同 |

#### 2.14.2 block/entity properties 缺口

DerivativeMain 的材质 ID 来源不是 shader 里硬编码 33 个常量，而是 `block.properties` 与 `entity.properties`：

- `block.properties` 覆盖植物、作物、花、树叶、banner/snow/ice SSS、lava/water/stained glass、torch/fire/glowstone/sea lantern/redstone/soul fire/amethyst/glowberry/sculk/glow lichen/ore 等。
- `entity.properties` 覆盖 lightning、slime、boat、projectile、experience orb、end crystal、warden 等。
- `program/Gbuffers/Entities/Hand/HandWater/Spidereyes/ArmorGlint/Weather` 让这些分类进入 deferred/material/lighting contract。

Mecraft 当前 terrain material id 基本覆盖了主原版方块，但没有完整 properties 映射层，也没有实体/手/掉落物/天气/glint 的 GBuffer 等价 pass。因此 “GBuffer 材质完成”应限定为 terrain fallback，不代表完整 DerivativeMain GBuffer 生态。

#### 2.14.3 大气追加差异

- `atmGetSkyRadiance()` 内部写死约 `Alt=100m`，而 metadata pass 使用 `uCameraAltitude + 100`；DerivativeMain 全局使用 `eyeAltitude`。这会让 sky radiance 与 metadata/验证程序在高度上不同源。
- `SKY_GROUND`、`FULL_AERIAL_PERSPECTIVE`、aurora、stars、night vision/lightning 对 sky/skylight/cloud 的贡献没有完整对齐。
- `MoonFlux` 与 `DoNightEye` 需要确认 C++ `uMoonPhaseFlux` 是否完全等价 DerivativeMain 的 `moonPhase/nightVision/NIGHT_BRIGHTNESS` 链。
- DerivativeMain 在 `VOLUMETRIC_FOG || VOLUMETRIC_LIGHT` 开启时会 `#undef LAND_ATMOSPHERIC_SCATTERING`，否则 land scattering 作为非体积路径的远景空气透视 fallback。Mecraft 当前 deferred lighting 的 `applyAerialPerspective()` 与半分辨率 `volumetric_fog.fs` 会叠加/分担职责，需要明确互斥关系，否则容易出现远景灰雾和体积雾都偏弱或都叠加的状态。
- `CommonFog()` 处理 blindness/darkness、lava、powder snow，并在粉雪里用 `skyIlluminance + directIlluminance` 生成亮雾；Mecraft 仍以普通 forward fog/水雾为主，没有完整纳入 deferred composite 链路。

#### 2.14.4 水/透明/雨湿追加差异

- `water_composite.fs` 的 WaterFog 使用 `uSkyAmbientColor/uSunLightColor`，DerivativeMain 使用 `skyIlluminance/directIlluminance`。
- 水焦散在 DerivativeMain shadow pass 写 `shadowcolor0/1`；Mecraft 当前 water 在 CSM 中 discard，避免硬阴影但丢掉 caustics 数据。
- DerivativeMain terrain/entity/hand 雨湿会改 `specularData.rg`、normal、albedo，并由 `wetnessCustom`、`eyeSkylightFix`、biome precipitation 平滑驱动；Mecraft 目前有 terrain wetness mask/roughness 调整和水面雨涟漪，但没有完全复现实体/手/方块 pass 的雨湿 GBuffer 语义。
- 透明折射、stained glass absorption、ice tint 在 Mecraft 有近似，但没有完整 `depthtex1`/dual-depth 语义。

#### 2.14.5 后处理追加差异

- Mecraft 自动曝光公式接近 DerivativeMain，但执行在 CPU readback/downsample 链，且带 clamp；DerivativeMain exposure 存在 `colortex5(0).a` 并由 Temporal pass 写回 history。
- Mecraft bloom extract 对 HDR 有额外 clamp，说明上游 HDR 范围与 DerivativeMain 不同；DerivativeMain bloom 依赖 tiled mip 和 exposure compensation。
- `BLOOMY_FOG` 缺失是体积雾“不惊艳”的关键之一，不只是后处理小差异。
- DerivativeMain `CalculateBloomFog()` 会从 bloom tile 叠加多级模糊，再用 `colortex6.x` 的 `fogTransmittance` 混合：`color = mix(fogBloom * 0.5, color, fogTransmittance)`。Mecraft `volumetric_composite.fs` 只做 `scene * volumetric.a + volumetric.rgb`，后续 bloom 不知道哪些像素被雾衰减过。
- Final CAS/dither/CatmullRom upsample 与 DerivativeMain `Final.glsl` 不是同一 buffer 输入。

#### 2.14.6 Shadow/Colored Shadow 追加差异

- 当前正式阴影采样走 `uCsmShadowMap/uCsmShadowMapRaw` depth array；`uShadowColorTex/uShadowNormalTex` 绑定的是旧单层 shadow FBO 的 color/normal。由于正式 CSM layer pass 没有 color attachment，`sampleShadowColorTint()` 无法按 cascade texel 读取透明 caster 颜色。
- DerivativeMain 的 colored shadow 依赖 `shadowtex0`（含透明）与 `shadowtex1`（opaque-only）比较差异，再从 `shadowcolor0` 取 stained glass tint。Mecraft 目前只做 water/stained glass discard，避免硬阴影，但没有“透明 caster 仍投彩色光”的第二语义。
- 因为 CSM 是多 cascade array，不能简单复用旧 `shadowColorTex` 二维纹理；需要 `shadowColorArray/shadowNormalArray` 或单独 colored-shadow atlas，并明确 cutout/透明/水焦散各自写入规则。

#### 2.14.7 配置/Profile 差异

- DerivativeMain 默认 `FOG_TYPE=1`，但 UI 暴露 0/1/2/3；Medium/High/Ultra profile 分别把 `VOLUMETRIC_FOG_SAMPLES` 设为 9/12/16，而 shader 内默认常量是 20、滑块可到 500。Mecraft 当前只有单一 strength/density，不存在 profile 与质量档位的双层控制。
- DerivativeMain 的 `PC_SHADOW/VC_SHADOW` 会随 `CLOUDS_SHADOW` 和具体云开关自动启停；Mecraft 的 `cloudShadowsEnabled` 是简化的屏幕/世界噪声投影，未复用 planar/cumulus density。
- `eyeSkylightFix`、`wetnessCustom`、`volFogDensity`、`volFogWind`、`cloudDynamicWeather` 都由 `shaders.properties` 的表达式平滑计算；Mecraft 有部分 C++ 近似，但没有建立“shaderpack uniform 表达式 -> Mecraft frame uniform”的等价表。

## 三、已发现的 Bug

### 3.1 Debug shader 旧编译错误已过时，但 SkyCapture debug 语义仍不足

- `deferred_debug.fs` modes 21/32/33/34 当前已改为 `localShadowUvFromWorld()`、`selectedShadowNormalOffsetWorld()`、CSM cascade debug，不再引用 `warpDensity` 或 `localShadowDepthWorldScale()`。
- 现存调试缺口是 SkyCapture：mode 16 直接 atlas 预览，不能验证主画面 `sampleSkyRadiance()` / `sampleSkyRadianceCloudy()` 的方向采样，也不能对齐 `D:\project\yanzheng` 的 equirectangular LUT 验证。

### 3.2 SSS 永不生效

- `shadowFactor()` 始终设置 `outSssDepth = 0.0`
- `deferred_lighting.fs` 中 `shadowSssDepth < -1e-5` 条件永远不满足
- `CalculateSubsurfaceScattering` 是死代码

**根因：** CSM 路径（`mecraft_shadow.glsl`）无 blocker search 输出 SSS depth。PCSS blocker search 计算了 avgBlocker 但未暴露 SSS depth。

### 3.3 Shadow color attachment 未进入正式 CSM 语义

- `shadow_depth.fs` 写入 `ShadowColor` 和 `ShadowNormal`
- 旧单层 `m_shadowFbo` 已有 color/normal attachment，不再是完全“静默丢弃”
- 正式 CSM `m_csmShadowFbo` 仍是 `GL_NONE` depth-only array，lighting 的 `sampleShadowColorTint()` 仍返回白色
- 因此 colored shadow/water caustics 的问题不是“是否创建了颜色附件”，而是“正式 CSM cascade 采样路径没有对应的 color/normal array 语义”
