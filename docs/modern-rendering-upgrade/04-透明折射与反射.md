# 透明、折射与反射

## 1. 当前结果为何与网页预览不同

当前模型透明着色器已经实现：

- IOR 驱动的 `refract` 方向。
- Roughness × IOR 映射到 Scene Color Mip 的模糊透射。
- `KHR_materials_volume` 的 Attenuation Color/Distance。
- Clearcoat、屏幕空间反射和透明 Reactive Mask。

它能够正确显示单个透明 Primitive，因此模型可以导入并看见折射/模糊。不过当前透明
Primitive 只按中心距离排序，每次着色只读取不透明 Scene Color。它不知道同一像素后方
还有哪些透明层，也没有可靠的出射面深度，所以会出现：

- 凹模型、相交玻璃和多个透明物体排序错误。
- 透射只看到不透明背景，看不到经过后方玻璃处理后的颜色。
- 厚度主要来自材质常量与模型缩放，不能表达真实入射/出射距离。
- 粗糙透射模糊了不透明 Scene Color，却没有模糊层间合成结果。
- 透明物体运动时缺少独立运动矢量，时域重建可能留下残影。

网页预览器常见的“玻璃折射/模糊感”来自完整的 Transmission、Volume、环境预过滤和
有序层合成，不是再调高透明度或 Bloom 就能得到。

## 2. 材质分类

统一 Alpha/Transmission 分类：

| 类别 | 示例 | 深度/排序 | 光照 |
| --- | --- | --- | --- |
| Opaque | 石头、金属、不透明模型 | GBuffer 深度 | Deferred PBR |
| Alpha Mask | 树叶、草、铁栏 | GBuffer 深度 + Alpha Test | Deferred PBR |
| Thin Blend | 烟、粒子、薄贴花 | 透明层 | Forward+ / 专用粒子模型 |
| Thin Transmission | 窗片、薄塑料 | 透明层，无几何体积 | Forward+ Transmission |
| Closed Volume | 玻璃器皿、冰块、水体 | 成对界面与光学厚度 | Forward+ Volume |
| Additive | 火花、能量粒子 | 透明层 | Emissive |

模型资产从 glTF Alpha Mode 与 Material Extensions 得到分类。方块定义必须显式提供相同
分类，不能仅靠纹理 Alpha 猜测玻璃或水。

## 3. Vulkan 多层透明架构

### 3.1 选择 PPLL 的原因

Weighted Blended OIT 适合大量薄粒子，但不能准确处理前后玻璃的折射顺序和体积吸收。
Vulkan 现代透明链采用 Per-Pixel Linked List（PPLL）收集，再按像素深度排序。粒子可
使用独立 Weighted Pass；玻璃、水、冰和模型 Transmission 必须进入 PPLL。

### 3.2 资源

- `TransparentHead`：`R32Uint`，每像素链表头。
- `TransparentNodeBuffer`：Storage Buffer，全局节点池。
- `TransparentAtomicCounter`：节点分配计数。
- `TransparentLayerCount`：每像素层数与诊断。
- `TransparentSortedLayers[K]`：排序后的紧凑层属性。
- `TransparentResolvedPing/Pong`：逐层解析 HDR Color。
- `TransparentVelocity/Reactive/CompositionMask`：时域输入。

单个节点紧凑保存：线性深度、Premultiplied Color、Transmission、Normal Oct、Roughness、
IOR、Material ID、Stable Object ID、Front Face、UV/Primitive 引用和 Velocity。高成本材质
字段在排序解析时通过 Material ID 读取 Bindless Material Table。

节点池容量依据 Render Extent 与设置中的 `maxAverageLayers` 创建。任何全局节点池耗尽或
单像素超过 `maxSortedLayers` 都设置 `TransparentStorageExhausted`，记录像素与需求量，
并让画质验收失败；实现不能静默丢弃末端层。

### 3.3 Pass 顺序

```text
Opaque HDR + Opaque Depth
        │
        ├── SceneColorPyramid
        ├── TransparentClear
        └── TransparentGather (PPLL append, opaque depth test)
                    │
                    ▼
          TransparentSortAndClassify
                    │
                    ├── pair closed-volume entry/exit interfaces
                    ├── write sorted layer attributes
                    └── validate layer capacity/topology
                    │
                    ▼
          Back-to-front Layer Resolve K-1 ... 0
                    │
                    ├── reflection + direct/indirect lighting
                    ├── refracted lookup from previous resolved color
                    ├── rough transmission convolution
                    └── Beer-Lambert absorption
                    │
                    ▼
          Transparent HDR + Velocity + Temporal Masks
```

每层 Resolve 从远到近读取上一代 HDR 颜色并写下一代，因此当前界面能够看到已经处理的
后方透明层。粗糙透射在上一代颜色上执行受 Roughness/IOR 控制的多样本卷积；不直接
读取最初的 Opaque Scene Color。Ping/Pong 依赖由 Render Graph 明确表达。

质量模式以 `K = 8` 作为初始配置，实际值由测试资产峰值确定。超过配置是明确容量错误，
场景作者可在 Debug View 定位层数异常区域。

## 4. 厚度与体积吸收

### 4.1 Closed Volume

同一 Stable Object ID 的 Front/Back Interface 按深度配对，得到相机空间或世界空间的
真实穿行距离。配对要求闭合、流形网格和一致 Winding；导入检查器报告 Open Edge、
Non-manifold 和负缩放导致的方向错误。

厚度来源必须显式声明，不能把两个带长度单位的值相乘：

| Thickness Source | 光学距离 | 用途 |
| --- | --- | --- |
| glTF Material | `thicknessFactor * thicknessTexture.g * modelScaleAlongRay` | 严格保持 `KHR_materials_volume` 语义 |
| Closed Geometry | Front/Back Interface 的世界空间路径长度 | 闭合玻璃器皿、实心冰体 |
| Voxel Shape | 射线穿过方块形状的世界空间路径长度 | 玻璃块、玻璃板、水体 |

Closed Geometry 可额外使用无量纲 Density Mask 调整局部吸收，但不能把 glTF 的米制
Thickness Factor 当作无量纲倍数。

颜色吸收使用 Beer-Lambert 形式，与 glTF Volume 的 Attenuation Color/Distance 对齐：

```text
transmittance = attenuationColor ^ (opticalDistance / attenuationDistance)
```

Attenuation Distance 为正无穷时表示无吸收，由规范化材质中的显式标志表达，着色器不
使用特殊负值猜测。

### 4.2 Thin Transmission

薄片材质没有成对表面，光学距离来自明确的 Thin Thickness 参数，法线在双面时按观察
方向校正。薄片不参与 Closed Volume 配对统计。

### 4.3 体素方块

- 完整玻璃/冰立方体：选择 Voxel Shape Source，使用可见前后面的世界距离。
- 玻璃板：使用方块形状定义的实际厚度。
- 水：入口为水面，出口来自水体几何/水底深度；吸收系数由 Biome 与水材质定义。
- 多个相邻同材质玻璃方块：内部不可见面不产生界面，整体厚度连续。
- 染色玻璃：Attenuation Color 参与层间透射和彩色阴影。

## 5. 折射

### 5.1 屏幕空间折射

每个界面使用 View Direction、Shading Normal 和 IOR 计算 Snell Refraction Direction，
再通过当前层的深度区间约束屏幕空间步进。命中返回 UV 与深度，解析器从上一代已合成
HDR 颜色采样。Total Internal Reflection 进入 Reflection Lobe，不能继续读取透射颜色。

几何法线决定介质进出方向，法线贴图只扰动局部高频折射方向，避免强法线贴图翻转整个
体积。Ray Thickness、步数、二分细化次数是固定画质参数并纳入性能统计。

### 5.2 粗糙透射

粗糙透射根据 Microfacet BTDF 近似确定采样半径和 Lobe 权重：

- Roughness = 0 时保持清晰折射。
- Roughness 增加时采样覆盖扩大，能量保持稳定。
- IOR 影响折射角和有效粗糙度。
- 多层解析对已经合成的后方颜色做卷积。
- Blue Noise 旋转减少固定采样图案，并由透明运动矢量支持时域重建。

这条链路对应网页预览中的磨砂玻璃效果；Scene Color Mip 可服务首层快速预览，但正式
多层质量模式使用逐层解析输入。

### 5.3 Vulkan Ray Query Refraction

屏幕外透射作为独立 `RayTracedTransmission` 设置。Ray Query 沿折射方向查询 TLAS，
读取命中材质与天空，支持离屏几何。多界面遍历拥有固定最大 Interface 数，达到上限时
返回 `RayTransmissionInterfaceLimitReached` 诊断，而不是伪造环境颜色。

该功能在 PPLL 屏幕空间多层链完成后建设，复用同一 IOR、Volume 和材质函数。

## 6. 反射

### 6.1 来源与统一合成

每个透明界面的反射来自统一 PBR IBL 链：

- GGX Prefiltered Sky/Reflection Probe 提供粗糙环境 Lobe。
- Hi-Z SSR 解析屏幕内可见反射。
- 选中的 RT Reflection 解析屏幕外和被遮挡区域。
- Fresnel、Roughness、Source Confidence 与 Visibility 决定合成权重。

Clearcoat 拥有独立 Normal/Roughness Lobe，并按 Fresnel 衰减基底反射和透射能量。透明
和不透明路径调用同一反射合成函数，避免模型玻璃与方块玻璃亮度标准不同。

### 6.2 RT Reflection 降噪

RT Reflection 输出 Specular Radiance + Hit Distance，使用 `RELAX_SPECULAR` 或
`REBLUR_SPECULAR` 的独立 NRD Instance/Method 配置。Diffuse RTGI 与 Specular Signal
可以共享 NRD Common Settings，但不共享 Permanent History 纹理。

## 7. 透明光照与阴影

透明 Resolve 通过屏幕位置和线性深度定位 Cluster，读取与不透明路径相同的局部灯列表。
太阳、局部灯、Denoised RTGI、IBL 与 Reflection Probe 均参与着色。

透明投影分为：

- Alpha Shadow：树叶等 Mask 材质执行二值 Alpha Test。
- Colored Transmission Shadow：玻璃按 Transmission 与 Attenuation 写彩色透射。
- Volume Shadow：使用光线在介质中的距离计算 Beer-Lambert 吸收。

CSM 与局部灯 Shadow Map 使用同一材质透射函数。Ray Query Shadow 的 Candidate Loop
累积有限界面透射，并在达到公开 Interface Limit 时报告诊断。

## 8. 水、粒子和天气

### 8.1 水

水使用 Closed Volume 主体契约，并增加波法线、泡沫、深浅水吸收与水下介质状态。水面
Velocity 来自当前/上一帧几何位置、波相位和相机运动。水下相机切换介质时清空透明与
曝光相关历史。

### 8.2 粒子

烟雾、降水和大量软粒子进入 Weighted Transparency Pass，输出 Premultiplied Color、
Reactive Mask 和 Composition Mask。需要折射的粒子进入 PPLL，并在材质定义中明确。
Additive 粒子在 HDR 域合成且参与 Bloom。

### 8.3 体积效果顺序

大气与远距离体积雾构成透明层后方的 Opaque HDR 背景；局部雾对透明层按其深度积分。
完整顺序由 Render Graph 固定，不能因模型预览与 Gameplay 使用不同入口而变化。

## 9. 时域输入

每个透明层写 Current/Previous Clip Position，解析器按实际 Contribution 选择前景速度，
同时生成：

- `TransparentVelocity`
- `ReactiveMask`
- `TransparencyAndCompositionMask`
- `TransparentDisocclusionMask`

Transmission UV 偏移显著的像素提高 Reactive/Composition 权重。相机切换、介质切换、
PPLL 层拓扑改变和 Transparent Extent 变化进入统一历史失效原因。

## 10. 调试与验收

调试视图：

- Layer Count、Sorted Depth、Front/Back Pair。
- Geometric Thickness、Optical Distance、Transmittance。
- Refraction UV/Hit Depth/Total Internal Reflection。
- Reflection Source 与 Weight。
- Transparent Velocity、Reactive 与 Composition Mask。
- PPLL Node 使用率和容量错误像素。

体素验收场景：连续玻璃墙、染色玻璃叠层、冰下水体、水下观察、活塞移动玻璃、玻璃后
火把。模型验收场景：Khronos Transmission/Volume 测试资产、厚玻璃器皿、相交透明
Primitive、粗糙度扫描和移动实例。

完成标准：排序不依赖 CPU Primitive 顺序；后层透明可通过前层被观察；厚度随真实几何
与材质变化；粗糙度连续改变透射 Lobe；运动时无持续重影；容量不足产生明确诊断。
