# 渲染架构与能力契约

## 1. 目标

本章定义现代渲染升级的公共边界。核心要求不是堆叠互不相识的 Pass，而是让体素世界
和模型场景都能生成同一种 GPU Scene、材质、灯光、光追几何和时域帧数据，再由
Render Graph 编排光栅、计算、Ray Query、第三方 SDK 与展示链。

## 3. 公共场景契约

### 3.1 GPU Scene 记录

```cpp
struct GpuSceneInstance {
    glm::mat3x4 worldFromObject;
    glm::mat3x4 previousWorldFromObject;
    glm::mat3x4 objectFromWorld;
    uint32_t geometryBase;
    uint32_t geometryCount;
    uint32_t materialBase;
    uint32_t flags;
    uint32_t stableObjectId;
    uint32_t rayTracingInstanceId;
};

struct GpuSceneGeometry {
    uint64_t vertexAddress;
    uint64_t indexAddress;
    uint64_t primitiveMetadataAddress;
    uint32_t vertexStride;
    uint32_t indexType;
    uint32_t materialId;
    uint32_t flags;
};
```

正式代码中的矩阵存储格式需满足 `std430`/Scalar Block Layout 对齐，并以静态断言验证
CPU/GPU 大小。`stableObjectId` 在对象可见生命周期内不变化，供时域表面身份判定使用。

体素与模型写入规则：

- 体素区块：一个可渲染区块或 SubChunk 对应一个或多个 Geometry，当前区块世界偏移写入
  Instance Transform；Greedy Quad 的纹理重复与方块材质写入 Primitive Metadata。
- 静态模型：每个 glTF Node Instance 对应 Instance，每个 Primitive 对应 Geometry。
- 蒙皮模型：Instance 指向当前变形顶点缓冲；上一帧变形缓冲供速度计算。
- 生物、掉落物、方块实体和移动方块：均使用稳定对象 ID 与双 Transform。
- 水、玻璃、Cutout 和不透明几何由 `flags` 明确分类，分类同时约束光栅与光追行为。

### 3.2 统一材质句柄

所有 Geometry 只保存 `materialId`。`materialId` 索引 `GpuMaterial`，材质结构不暴露
glTF 或 LabPBR 的文件格式细节。体素资源加载器和模型资源加载器负责规范化，运行时
着色器只消费统一字段。详细字段见《02-灯光与PBR材质链》。

### 3.3 统一光源

`GpuLight` 同时表示游戏灯光和模型展示灯光，至少包含 Directional、Point、Spot、Rect
四类。太阳/月亮使用 Directional；火把、灯笼、发光方块可生成 Point/Spot 代理；模型
场景灯光来自编辑器或 glTF `KHR_lights_punctual`。光源强度统一使用物理单位，曝光负责
最终显示映射。

### 3.4 场景修订号

场景系统输出以下单调递增修订号：

- `geometryRevision`：顶点、索引或 Primitive Metadata 变化。
- `instanceRevision`：实例加入、移除或 Transform 变化。
- `materialRevision`：材质参数或纹理绑定变化。
- `lightRevision`：光源集合或参数变化。
- `worldOriginRevision`：浮动原点变化。

Render Graph 依据修订号建立上传与 AS 构建任务。历史系统依据稳定 ID、速度与修订原因
作出复用判定，不能仅以相机矩阵是否相等推断。

## 4. RHI 光追接口

### 4.1 能力结构

`RhiCapabilities` 增加：

- `accelerationStructure`、`rayQuery`。
- `accelerationStructureHostCommands`。
- `maxAccelerationStructureGeometryCount`。
- `maxAccelerationStructureInstanceCount`。
- `minAccelerationStructureScratchOffsetAlignment`。
- `descriptorBindingPartiallyBound`。
- `descriptorBindingVariableDescriptorCount`。
- `runtimeDescriptorArray`。
- `shaderSampledImageArrayNonUniformIndexing`。
- `shaderStorageBufferArrayNonUniformIndexing`。

Vulkan 初始化为现代管线请求并验证：

- `VK_KHR_acceleration_structure`
- `VK_KHR_ray_query`
- `VK_KHR_deferred_host_operations`
- `VK_KHR_buffer_device_address`
- Vulkan 1.2 Descriptor Indexing 特性组

缺少任一硬要求时返回结构化能力错误，现代 RT 预设保持不可选。

### 4.2 资源与命令

公共 RHI 增加以下概念，Vulkan 类型只存在于后端实现：

```cpp
struct RhiAccelerationStructureHandle;
struct RhiAccelerationStructureGeometryDesc;
struct RhiAccelerationStructureBuildDesc;
struct RhiAccelerationStructureBuildSizes;
struct RhiAccelerationStructureInstance;

virtual RhiAccelerationStructureHandle createAccelerationStructure(...);
virtual RhiAccelerationStructureBuildSizes queryAccelerationStructureBuildSizes(...);
virtual uint64_t bufferDeviceAddress(...);
virtual uint64_t accelerationStructureDeviceAddress(...);
virtual void buildAccelerationStructures(...);
virtual void writeAccelerationStructureProperties(...);
virtual void copyAccelerationStructure(...);
virtual void accelerationStructureBarrier(...);
```

资源状态至少包含：

- `AccelerationStructureBuildInput`
- `AccelerationStructureBuildScratch`
- `AccelerationStructureBuildWrite`
- `AccelerationStructureRead`

Buffer 创建描述增加 Device Address、AS Storage、AS Build Input、Storage Buffer 用途。
AS 对象及其底层 Buffer 均进入延迟销毁队列，释放时机由 Submission Token 决定。

`RhiDescriptorType` 增加 Acceleration Structure；Query Pool 增加 Compacted Size 查询；
AS Copy Mode 明确 Clone/Compact；Build Desc 明确 Build/Update、Top/Bottom Level、几何 Flags
和 Build Flags。缺少这些接口时无法实现本文要求的静态 BLAS 压缩与动态变形更新。

### 4.3 Ray Query Shader

首版使用 Compute Stage，所以现有 `RhiShaderStage` 不需要增加 RayGen/Miss/ClosestHit。
编译器目标升级为 Vulkan 1.3 / SPIR-V 1.6，并允许：

```glsl
#extension GL_EXT_ray_query : require
#extension GL_EXT_nonuniform_qualifier : require
#extension GL_EXT_buffer_reference2 : require
#extension GL_EXT_scalar_block_layout : require
```

Shader Reflection 需要识别 Acceleration Structure Descriptor 与运行时 Descriptor Array。
绑定布局哈希必须包含 Descriptor Binding Flags，避免缓存复用错误布局。

## 5. Bindless Descriptor 契约

Vulkan 现代管线定义一个帧间稳定的 Global Bindless Set：

| Binding | 内容 | 更新频率 |
| --- | --- | --- |
| 0 | Sampled 2D Texture Array | 资产创建/销毁 |
| 1 | Sampled Cube Texture Array | 天空与反射探针变化 |
| 2 | Sampler Array | 采样器创建/销毁 |
| 3 | Storage Buffer Array | 几何与动画资源变化 |
| 4 | TLAS | AS 更新 |

描述符槽由 Generation Handle 管理；槽复用必须晚于引用该槽的 GPU Submission 完成。
纹理销毁先撤销材质引用，再等待 GPU 完成，最后释放槽。Vulkan 每个 Descriptor Set 只允许
一个 Variable Descriptor Count Binding，且该 Binding 必须位于最高编号；Binding 4 已冻结给
TLAS，因此 Binding 0–3 使用初始化时确定的固定描述符数量。Shader 侧仍以运行时索引访问
数组，Layout 使用 Partially Bound、Update-after-bind、Update-unused-while-pending 和
Non-uniform Indexing，容量同时受 Descriptor Set 与 Per-stage Update-after-bind 上限约束。
OpenGL Bind Group 不承担模拟这一机制的职责。

当前底层实现已经提供 Vulkan `GlobalBindlessSet`，覆盖 2D Texture、Cube Texture、Sampler
和 Storage Buffer 的强类型发布、整批原子更新、Submission Sequence 退役与代际复用；
`GpuSceneBufferSet` 已提供固定容量的 Material、Geometry、Instance GPU-only Buffer、连续
Dirty Span 上传、录制批次确认和修订保护。体素与模型场景生产者尚未写入这些表，运行时
剔除、间接绘制和 TLAS 消费链仍属于后续接入范围。

## 6. Render Graph 集成

### 6.1 图资源类型

Render Graph 增加外部与瞬态 AS 资源描述，并把 Buffer Device Address 读取表达为显式
Buffer Read。AS 构建读取顶点、索引、Instance 和 Scratch，写入 BLAS/TLAS；RTGI Trace
读取 TLAS 与 Scene Buffers。编译器据此生成正确的
`VK_PIPELINE_STAGE_2_ACCELERATION_STRUCTURE_BUILD_BIT_KHR` 到 Compute Shader 同步。

NRD 由一个 `NrdRenderGraphBridge` 接入。Bridge 根据 NRD Dispatch 描述创建或导入资源，
把每个 Dispatch 注册成 Compute Pass，并由图统一处理 Barrier 与生命周期。Bridge 不在
Render Graph 外自行提交命令。

### 6.2 帧依赖

```text
SceneUpload ───────┬──► BlasBuild/Compact ─► TlasBuild ──────────────┐
                   │                                                 │
Depth/GBuffer ─► HiZ ─► ClusterBuild ─► DirectLighting ──────────┐  │
       │                                                         │  │
       └─────────────────────────────────────────────────────────┴──┴► RtgiTrace
                                                                     │
GBuffer + Velocity + NRD History ────────────────────────────────────┴► NrdDispatches
                                                                        │
DirectLighting + DenoisedGI + Reflection + Atmosphere ─────────────────┴► OpaqueComposite
```

可并发计算必须由时间戳证据证明收益。AS Build、NRD 与光栅共享资源的 Queue Ownership
转移由 Render Graph 生成，不在 Pass 内散布手写 Semaphore。

## 7. 帧错误与可观测性

高性能路径使用错误码或 `std::optional`，不使用异常。新增稳定错误类别：

- `RayTracingCapabilityMissing`
- `AccelerationStructureBuildFailed`
- `BindlessDescriptorCapacityExceeded`
- `NrdInitializationFailed`
- `NrdDispatchContractInvalid`
- `TransparentStorageExhausted`
- `HdrDisplayModeUnavailable`

Dashboard 至少展示：

- BLAS 总数、构建数、压缩数、字节数和 Scratch 峰值。
- TLAS Instance 数及更新时间。
- GPU Scene Instance/Geometry/Material/Light 数。
- Cluster 平均与最大光源数、溢出计数。
- RTGI 射线数、有效命中率、平均命中距离和 Trace GPU 时间。
- NRD Method、历史帧长、Disocclusion 比例和 GPU 时间。
- 透明节点使用量与存储耗尽计数。
- 每个主要 Render Graph Pass 的 p50/p95 GPU 时间。

所有容量耗尽都返回可观测状态并进入自动测试，不能静默截断数据。

## 8. 所有权边界

| 模块 | 职责 |
| --- | --- |
| Scene/ECS | 产生稳定对象、Transform、材质与光源语义 |
| Asset Runtime | 导入并规范化网格、纹理、材质、动画与 LOD |
| GPU Scene | 分配 GPU 记录、上传修订、生成剔除与间接绘制输入 |
| Ray Tracing Scene | 管理 BLAS/TLAS、Scratch、Compaction 与实例 Mask |
| Render Graph | 排序、同步、资源生命周期、Queue 提交 |
| Lighting | Cluster、阴影、BRDF、IBL 与反射探针 |
| RTGI | 方向采样、Ray Query、次级命中辐射与原始信号输出 |
| NRD Bridge | NRD 资源、常量、Dispatch 和历史生命周期 |
| Temporal Output | Upscale、动态分辨率、曝光、Tone Map 与显示映射 |
| Presentation | Frame Generation、UI 合成、Swapchain 与 Present |

这一边界禁止 Model Preview、Gameplay 和单个 Pass 各自维护相互冲突的材质或历史定义。
